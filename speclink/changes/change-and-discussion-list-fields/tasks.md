## 3. core 與儲存：輸出

- [ ] 3.1 清單的新鍵（design D2）：依需求「清單的詳細輸出與 show 帶說明、階段與時間」與「建立者識別的輸出」，先在 crates/engine/speclink-core/src/lifecycle/listing.rs 的測試寫失敗的斷言，再實作——`ListChangeJson` 加 `whyExcerpt`、`stage`、`startedAt`、`createdById`、`readyAt`，只在 `--detail` 填值；`ListArchivedJson` 加 `createdById`。斷言 payload 結構：五個鍵是 camelCase 的字串、`stage` 是三個值之一、沒有值的鍵不出現；不帶 `--detail` 的輸出與既有的期望字串逐位元相同；metadata 損壞的項目不帶五個鍵；`readyAt` 在取消勾選後不出現；`whyExcerpt` 與 `summary` 來自同一次提案讀取（用計數的測試儲存斷言提案只讀一次）。驗證：`cargo test -p speclink-core --lib listing` 通過，既有的期望字串沒有被改。 <!-- speclink-task:tsk_01M8AMSTQGCXGN6FG0TK8M5WTF -->
