## 5. 稽核

- [x] 5.1 對新增的環境變數處理（`HC_TERMINAL_ID`、`HC_TERMINAL_SOCKET`、`SPECLINK_TERMINAL_REPORT`）與 socket 連線套用 sharp-edges 稽核清單，至少檢查：終端機代號裡的任意字元只經 serde 序列化、不手拼；socket 路徑只用來連線，不建立、不寫入、不刪除檔案；安靜失敗只限回報本身，不會吞掉動詞的錯誤或改變 exit code；開關的非預期值不會意外關掉或打開回報以外的東西。驗證：發現的問題各補一個測試並修正，`cargo test -p speclink-cli terminal_report` 通過；沒有發現時在任務完成註記寫明檢查過哪些項目。 <!-- speclink-task:tsk_01M88SPW0Z9K1RCM8JER613BH2 -->
  - 稽核結果（壞蛋、懶惰的開發者、搞混的開發者三種角度）：沒有發現要修的問題。檢查過的項目：(1) 終端機代號與標籤值只經 serde 序列化成一行，換行與引號都會跳脫，不能在同一個連線多塞一則請求，補了測試 `a_newline_in_the_terminal_id_cannot_add_a_second_request` 並做過突變檢查；(2) socket 路徑只拿來連線，不建立、不寫入、不刪除檔案；指到別的程式的 socket，對方只會收到一行它不認得的 JSON，而能改環境變數的人本來就能執行任意程式；(3) 安靜失敗只在回報內部（`exchange` 的錯誤在 `send` 裡丟掉），回報只在 `dispatch` 回傳 `Ok` 之後執行，不經手動詞的錯誤；(4) 沒有會 panic 而改變 exit code 的路徑：執行緒用 `Builder::spawn`，開不了就不等，序列化失敗就返回；寫入已關閉的連線時 Rust 程式預設忽略 SIGPIPE，只得到錯誤；回覆最多讀 64 KiB；(5) 開關只認 `false`，`flase`、`0` 這類值會讓回報照常開著；這和 Speclink 其他布林環境變數一致，而開著時只會改自己終端機的標籤，沒有安全風險。
