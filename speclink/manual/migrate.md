# 本地工作區遷移到 remote

已經有本地工作區的專案，可以整個搬到 server 上的一個空 scope。遷移是一次性的整批動作：全部成功才轉換本地，任一步失敗本地分毫不動。

## 從哪裡進入

遷移在桌面 app 操作，有兩個入口：

- 新增工作區時選本機路徑，開到含 `speclink/` 的專案，選擇次要動作「遷移」。
- 本地 `speclink/` 與 remote 連接並存時跳出的衝突對話。

兩個入口進的是同一條流程：選 connection 與空 scope、確認、上傳、轉換。沒有「上傳合併到非空 scope」這種路徑。

## 哪些專案可以遷移

本機規格資料夾是預設的 `speclink/`，或是舊佈局的 `openspec/`，都可以遷移。下面兩種會被拒絕，畫面說明原因，本地不變、遠端也沒有任何寫入：

- `.speclink.yaml` 明寫了自訂的規格資料夾路徑（例如 `docs/specs`）：訊息說明只支援預設資料夾。
- `speclink/` 與 `openspec/` 同時存在：只備份其中一個會留下另一個。

## 上傳什麼

桌面 app 用引擎讀取本地工作區的全部內容打包上傳：

- 進行中變更的中介資料與全部產物；
- 正式規格；
- 進行中與已封存的討論；
- 進行中變更的證據記錄；
- 已封存變更的全部文件，連同它的證據記錄。已封存變更的資料檔不論在本機叫 `.meta.yaml` 還是舊檔名 `.openspec.yaml`，上傳時一律用 `.meta.yaml` 這個名字；同一個已封存變更兩個檔都有時，只上傳 `.meta.yaml` 的內容；
- 工作流設定與共用詞彙文件；
- 看板順序：各變更與各討論在看板上排過的順序。遷移後，遠端的看板與 plan 照同樣的順序呈現。沒有任何一張卡排過順序時，不帶這一項。

任一來源檔解析失敗，打包中止並點名該檔。不會只搬一部分。

### 規格資料夾裡有符號連結時

打包不會經符號連結（symlink）讀檔。下面任何一個是符號連結時，遷移在讀取任何文件之前就中止：

- 通往規格資料夾路上的資料夾；
- 規格資料夾本身；
- 規格資料夾底下的任何一個檔案或資料夾；
- 舊位置的證據資料夾 `.speclink/touched/`，規則相同。

中止時你會看到：

- 錯誤訊息點名第一個找到的項目，寫的是相對專案根目錄、使用正斜線的路徑。同一層依名稱排序。
- 訊息不含連結指向的位置，也不含任何檔案內容。
- app 沒有送出任何請求。本機不做備份，也不轉換。

| 符號連結的位置 | 訊息點名的路徑 |
| --- | --- |
| 規格資料夾底下的檔案 `specs/leak/spec.md` | `speclink/specs/leak/spec.md` |
| 規格資料夾底下的資料夾 `changes/linked` | `speclink/changes/linked` |
| 規格資料夾本身 | `speclink` |

這些位置有列不出內容的資料夾時，遷移同樣中止並點名那個資料夾：app 無法確認裡面沒有連結。規格資料夾不存在不算這種失敗。

> [!NOTE]
> 這是刻意的改變。以前遷移會跟著連結讀檔，把連結指向的內容一起上傳。除了這一點，遷移的流程、確認畫面、送出的內容與成功後對本機的處理都沒有變。

## server 端怎麼收

server 只接受「建立新的」這一種匯入語意：

- 目標 scope 已持有任何文件時，server 拒絕，並且不寫入任何內容。錯誤訊息帶 create-new 語意。
- 你的角色是 reader 時，server 拒絕（403）。
- 格式版本未知或缺欄位時，server 拒收。
- 送出的內容超過 server 設定的大小上限時，server 以 413 拒絕。

成功時整包以單一原子提交落庫。不存在「寫了一半」的狀態。已經連著這個 scope 的其他用戶端會收到通知，知道內容變了。

官方的示範用 server 與內嵌引擎的宿主，收的方式相同。

## 成功後本地會怎樣

1. 本機規格資料夾改名為帶日期的備份目錄，名稱是「原資料夾名.migrated-日期」：例如 `speclink.migrated-2026-11-02`，舊佈局是 `openspec.migrated-2026-11-02`。同名已存在時加序號，例如已有 `speclink.migrated-2026-11-02` 時改名為 `speclink.migrated-2026-11-02-2`。沒有任何路徑會刪除本地內容。
2. 桌面 app 寫入 remote 連接標記。
3. 原分頁原地轉為 remote 分頁，這個資料夾成為它的 checkout。
4. 之後 CLI 在這個資料夾以 remote 模式運作。

遷移前的確認對話會指出目標 Project／Repo，以及本地備份的行為。

> [!NOTE]
> 匯入失敗時（scope 非空、網路、驗證），本機規格資料夾原樣存在、沒有連接標記、分頁維持本地，錯誤原樣呈現在畫面上。

## 用 SDK 匯出同一個專案

整合者可以用 Node SDK 的 `engine.exportScope()` 把本機專案匯出成一包文件。它與桌面 app 的遷移是同一套打包：

- 對同一個本機專案，兩者得到的文件集合逐項相同。之後打包涵蓋的文件種類有增減，兩邊同時跟著變。
- 會讓遷移中止的來源，同樣讓匯出失敗，並指出同一個檔案：壞掉的變更中介資料、引擎不支援的文件形式、規格資料夾裡的符號連結、不在專案根目錄裡面的規格資料夾。匯出失敗時不回傳任何一包。
- 差別只有一個：桌面 app 的遷移只接受預設的規格資料夾（`speclink/` 或 `openspec/`），這是打包之前的檢查。匯出還接受專案根目錄裡面的自訂規格資料夾，例如 `docs/specs`。

遷移完成後的工作方式見 [remote 模式總覽](remote-overview.md)。
