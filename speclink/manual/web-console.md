# 瀏覽器後台

server 自帶一個瀏覽器後台。管理員在這裡管帳號、專案與憑證；一般成員在這裡管自己的帳號。後台不顯示規格內容：變更、規格、討論都在桌面 app 與 CLI。後台的版面、元件、字級與按鈕高度都和桌面 app 一致。

## 有哪些頁

- 未登入的流程頁：`/setup`（開箱）、`/invite/<token>`（接受邀請）、`/login`（登入）、`/activate`（裝置核准）。
- 登入後：`/account`（帳號頁）與 `/admin` 底下的管理面。
- 每一頁都可以直接開啟或重新整理。例如直接開 `/admin/audit`，後台檢查登入狀態後顯示稽核紀錄頁。
- 使用者與專案的詳情頁也一樣：`/admin/users/<使用者 id>` 與 `/admin/registry/<專案代號>` 可以在詳情頁按重新整理，也可以直接開別人分享的詳情頁連結。後台依網址顯示那一筆的詳情頁；對不到資料時顯示找不到的狀態，不會回 JSON 的 404。
- 只有上面這些網址會回後台頁面。打錯的 `/api/...` 網址回 JSON 的 404，不存在的 `/assets/...` 檔案也回 404，都不會回後台首頁。列表路徑後面接了兩段以上（例如 `/admin/users/a/b`）、最後一段是空的（例如 `/admin/users/`），或不存在的管理路徑（例如 `/admin/changes`），一樣回 404。
- 後台的網頁檔案內嵌在 server 執行檔裡，不需要 Node、外部 CDN 或外部字型服務。

未登入的流程頁長這樣：

- 畫面正中是橫式字標，下面一張卡片，卡片有標題與灰字說明，主要動作在卡片頁尾的右側。
- 多步驟的流程在卡片頂端標「步驟 n / 總數」與步驟條。例如 `/setup` 建立管理員之前是「步驟 1 / 2」，建好之後是「步驟 2 / 2」。
- 提交出錯時，錯誤放在對應欄位附近，已輸入的非祕密內容保留。例如登入時密碼打錯，錯誤緊貼在欄位下方，電子郵件還在。
- 連結無效或沒有權限時，卡片只有警示圖示、標題與說明，不出現任何表單欄位。

## 版面：側欄加主欄

登入後，管理員與一般成員用同一個版面：左邊是側欄，右邊是主欄。畫面頂端沒有橫貫的 header。

- 側欄由上而下是字標、導覽、帳號選單。
- 管理員的導覽有六個目的地：總覽、使用者、專案與儲存庫、憑證、系統、稽核紀錄。沒有獨立的資料操作項目，匯出與資料結構遷移都在系統頁。
- 一般成員的導覽只有「帳號」一項，看不到任何管理目的地。
- 主欄的頂列是麵包屑，下面是主內容。只有主內容區會捲動，側欄與頂列固定不動。

麵包屑告訴你在哪裡：

| 位置 | 麵包屑 | 可以點的 |
| --- | --- | --- |
| 管理面的目的地 | `後台 / <目的地>` | 「後台」回總覽 |
| 使用者或專案的詳情頁 | `後台 / <目的地> / <該筆名稱>` | 「後台」回總覽、目的地回列表；名稱不能點 |
| 帳號頁 | 帳號 | — |

管理員在詳情頁時，側欄高亮該詳情頁所屬的目的地。

### 帳號選單

帳號不在管理員的導覽目的地裡，要從側欄底部的帳號選單進入。

- 選單的觸發鈕顯示你的顯示名稱與電子郵件。
- 展開後，頂端顯示顯示名稱，以及「電子郵件 · 管理員」或「電子郵件 · 成員」。下面依序是帳號、介面語言、登出。
- 選登出後，登入工作階段被撤銷，畫面回到登入頁。登出請求失敗或網路中斷時，後台照樣回登入頁，不會停在還顯示帳號資訊的畫面。
- 管理員開 `/account` 時，側欄六個目的地照常顯示，沒有項目高亮，可以直接點去任一管理目的地。

### 視窗寬度與頁面排版

- 視窗寬度至少 1024px：側欄固定顯示圖示與文字。
- 更窄時：側欄隱藏。按主區頂列的開啟導覽鈕，側欄內容從左側滑出。管理員與一般成員都一樣。關閉後，焦點回到開啟導覽鈕。
- 每頁頂端是該頁唯一的大標題，下面灰字說明，右側放頁級動作。寬度不夠並排時，動作換到標題下一列。每一頁只有一個主要動作。
- 列表頁（使用者、專案與儲存庫、憑證、稽核紀錄）全寬排版。搜尋與篩選放在頁標題區，下面一張列表卡填滿剩餘高度。清單在卡內捲動，卡底是換頁列。頁面本身不會因為清單長而捲動。
- 設定型頁（總覽、系統、帳號）以 768px 寬的一欄置中，每個區塊一張卡，卡內一列一筆。例如系統頁是執行環境、儲存狀態、匯出與危險區四張卡。
- 視窗窄到 375px、放大到 200% 時，登入、開箱與邀請流程仍然可以用鍵盤完成，不會出現整頁水平捲動。

## 登入後去哪

後台照 server 的裁決導向，不自己猜。順序是：

1. 網址帶有效的裝置碼：先顯示裝置核准流程。
2. 網址帶安全的返回路徑：只接受以 `/account`、`/activate` 或 `/admin` 開頭的站內路徑。
3. 都沒有：回角色首頁。

會擋下的情況：

- 返回路徑指向外部網站：後台不導向外部，改回角色首頁。
- 一般成員以 `/admin` 為返回路徑：顯示無權限狀態，不會退回 `/account`。
- 未登入時開受保護的頁：前往登入頁，只保留安全的站內路徑當返回路徑。
- 已開的頁面收到 401（登入過期）：回到 `/login`，只保留安全的當前路徑。

換到另一頁後，焦點移到主內容的標題。

## 列表與詳情頁

- 列表是主體。清單列裡沒有輸入框、下拉或提交按鈕。
- 使用者列與專案列整列可點。用滑鼠點，或用 Tab 移到該列後按 Enter 或空白鍵。
- 點下去後，主內容區換成這一筆的詳情頁，網址變成 `/admin/users/<使用者 id>` 或 `/admin/registry/<專案代號>`。詳情頁不從側邊滑出。
- 詳情頁網址可以直接開啟或重新整理。網址對不到任何資料時，主內容區說明找不到，並提供回到列表的按鈕。
- 詳情頁以 768px 寬的一欄置中：頁標題是這一筆的名稱，下面灰字說明，右側頁級動作；再下面是分頁。

### 在詳情頁之間前後切換

詳情頁頂列右端有 ‹ n／m ›。m 是列表目前呈現的筆數（含搜尋與篩選的結果），n 是這一筆在其中的位置。

- 到第一筆或最後一筆時，對應的鈕停用，不會繞回另一端。
- 直接開詳情頁網址時，前後順序是該列表沒經過搜尋與篩選的全部項目。
- 這一筆不在順序中時，整組不出現。對不到資料的詳情頁也不出現。
- 用 ‹ › 切換不新增瀏覽紀錄。
- 從詳情頁回列表（點麵包屑的目的地、點側欄，或按瀏覽器上一頁），列表的搜尋字串、篩選與頁碼都維持進入詳情頁前的樣子。

例：使用者頁有 12 位使用者。輸入只符合 3 位的關鍵字，點清單第 2 列，頂列顯示「2 / 3」。按 › 換成第 3 位，顯示「3 / 3」，› 停用。這時按瀏覽器上一頁回到列表，搜尋框裡仍是那個關鍵字。

## 建立、邀請與確認

- 建立與邀請類動作用按鈕開啟畫面中央的對話框：邀請使用者、建立專案、新增儲存庫、建立存取金鑰。表單平常不在頁面上。
- 按取消或 Esc 關閉對話框。點對話框以外的地方不會關閉，已輸入的內容不會因為誤點而消失。
- 邀請時選要加入的專案：用下拉逐一挑選。已選的專案列在下方，可以逐一移除，也不再出現在下拉裡。
- 對話框送出失敗：對話框保持開啟，保留你輸入的非祕密內容，錯誤放在對應欄位附近。
- 建立專案、新增儲存庫、更名成功：對話框關閉，列表或詳情頁立即更新。

只顯示一次的祕密（邀請連結、存取金鑰明文）這樣呈現：

1. 送出成功後，同一個對話框換成已建立狀態。
2. 畫面有成功標題，說明這個值只顯示這一次，綠色成功框裡是值與複製鈕。
3. 邀請以受邀者可直接開啟的完整 `/invite/<token>` 連結呈現，不只給一串 token。
4. 按「完成」關閉對話框。之後頁面上不會再出現這個值。

> [!WARNING]
> 關掉對話框前先複製。關閉之後，頁面上不會再出現這把明文金鑰或這條邀請連結。

破壞性操作送出前會跳確認框，寫出確切對象：停權、撤銷憑證、移除成員資格、刪除專案、資料結構遷移、撤回邀請。

- 請求進行中，確認按鈕停用並顯示進度。第二次按不會重複送出。
- 完成後，畫面以一則訊息回報結果。

存取金鑰與裝置登入列上的撤銷鈕（帳號頁、憑證頁、使用者詳情頁的憑證分頁），以及成員資格列上的移除鈕，平常是隱藏的：

- 滑鼠移入該列，或用 Tab 移到該鈕時才出現。隱藏時它仍在 Tab 順序裡。
- 觸控裝置等沒有滑鼠移入的環境，這些鈕一直顯示。
- 已撤銷的列沒有撤銷鈕。

每一頁都分得出載入中、有資料、空的、沒有權限與意外錯誤這幾種狀態。頁面載入或畫面出錯時，顯示重試入口，不會整頁空白。

## 搜尋、篩選與換頁

| 頁面 | 工具列 |
| --- | --- |
| 使用者 | 關鍵字搜尋、狀態篩選 |
| 專案與儲存庫 | 關鍵字搜尋 |
| 憑證 | 列表卡頂端分存取金鑰與裝置兩個分頁，各自標總筆數；關鍵字搜尋、狀態篩選 |
| 稽核紀錄 | 關鍵字搜尋、動作篩選、來源篩選、時間區間 |

工具列裡的搜尋框、下拉與日期輸入一樣高，各自有說明用途的無障礙名稱。

清單非空時，列表卡底部一直有換頁列：

- 左側是「第 a–b 筆，共 N 筆」與每頁筆數下拉（20、50、100，預設 20）。
- 過濾後的筆數超過每頁筆數時，右側有第一頁、上一頁、頁碼、下一頁、最後一頁與跳頁輸入。沒超過時，右側不出現。
- 改搜尋字串、改篩選或切換分頁，清單回到第 1 頁。
- 清單變短、目前頁碼超出範圍時，停在最後一頁。
- 換頁後，列表卡捲回頂部。
- 每頁筆數與頁碼不會跨重新整理保留。
- 視窗寬度小於 1024px 時，清單改成可換行的清單列，稽核紀錄的表格也一樣。換頁列收成筆數範圍與「‹ 目前頁 / 總頁數 ›」，不會出現水平捲動。

誰來算：

- 使用者、專案與儲存庫、憑證三個列表：搜尋、篩選與換頁都在瀏覽器裡算，不另向 server 要資料。例：45 位使用者按第 3 頁，左側由「第 1–20 筆，共 45 筆」變成「第 41–45 筆，共 45 筆」，清單只列第 41 到 45 位。
- 稽核紀錄：篩選、頁碼與每頁筆數交給 server 算，畫面只顯示 server 回的當頁事件。「共 N 筆」取自 server 回的符合篩選總筆數。改任何篩選或每頁筆數，頁碼回到 1。server 端的規則見 [管理面與稽核](server-admin.md)。

清單是空的時候：

- 本來就沒有資料：頁面說明這種資料的用途，不只寫一行「尚無資料」。例如沒有任何存取金鑰的憑證頁，會說明存取金鑰拿來做什麼。
- 建立入口一直在頁首，不會因為清單有資料而消失；空狀態裡不另放第二個建立鈕。
- 搜尋或篩選後沒有符合的項目：顯示與「本來就空」分得開的無符合結果提示，不含建立鈕。工具列保留，換頁列不出現。

## 使用者頁

頁首的主要動作是「邀請使用者」。列表卡頂端有「使用者」與「邀請中」兩個分頁，各自標總筆數。

使用者分頁的每一列：頭像字、顯示名稱與電子郵件、管理員籤（只有管理員有）、狀態籤、所屬專案數。狀態篩選只在這個分頁出現。

### 使用者詳情頁

點一列進入該使用者的詳情頁：

- 頁標題是名稱，後面接狀態籤。頁級動作是停權；已停權的人換成重新啟用。
- 分頁有四個：概要、成員資格、憑證、稽核。成員資格與憑證分頁標出筆數。
- 概要：電子郵件（附複製）、狀態、建立日期，以及管理員開關。
- 成員資格：每列是專案名稱與專案代號、角色下拉、移除鈕。角色下拉一改就送出，沒有另外的儲存鈕。按移除鈕先跳出指名該使用者與專案代號的確認框，確認後該列消失、分頁計數減一，取消則什麼都不送出。
- 成員資格的末列是「加入專案」：專案下拉只列還沒加入的專案，旁邊是角色下拉與加入鈕。
- 憑證：該使用者的存取金鑰與裝置登入，有效的可以撤銷。

> [!NOTE]
> 全站只剩一位有效管理員時，他的詳情頁裡管理員開關維持開啟且停用，停權鈕也停用。

### 邀請中分頁

受邀者接受邀請之前沒有使用者資料，所以邀請另放一個分頁，不和正式使用者混在一起。

- 只列仍有效的邀請（還沒用過、也還沒過期）。已接受或已過期的不出現。
- 每筆顯示受邀者的電子郵件、顯示名稱、角色、要加入的專案、到期時間。
- 邀請列不能點開。待啟用的人不能停權，也沒有憑證或細節可看。
- 關鍵字搜尋套用在目前分頁；在這裡比對電子郵件與顯示名稱。
- 每筆都有一直顯示的撤回動作。確認框指名受邀者。撤回後，邀請連結立即失效，該筆離開分頁，並留下一筆指名受邀者的稽核事件。
- 已接受的邀請不能撤回。它背後已有真實帳號，要走停權。
- 剛送出的邀請立即出現在這裡，分頁計數加一。受邀者接受後，該筆離開，人出現在使用者分頁。
- 沒有任何邀請時，分頁仍在、計數為 0，切過去顯示說明邀請用途的空狀態。
- 直接開 `/admin/users?tab=pending` 就停在邀請中分頁。切回使用者分頁後網址不再帶這個參數。切換分頁不新增瀏覽紀錄，按瀏覽器上一頁不會回到邀請中分頁。

邀請與帳號的完整行為見 [帳號、邀請、存取金鑰與 membership](accounts.md)。

## 專案與儲存庫頁

頁首的主要動作是「建立專案」。點一列進入專案詳情頁，網址是 `/admin/registry/<專案代號>`。

- 頁標題是專案名稱，說明裡標出專案代號。頁級動作是「更名」。
- 分頁有兩個：儲存庫、成員，各自標筆數。
- 儲存庫分頁：每列可以更名，末列是新增儲存庫。
- 成員分頁：唯讀列出這個專案成員的顯示名稱、電子郵件與角色。要改成員資格，到該使用者的詳情頁。

代號與名稱的規則：

- 專案代號與儲存庫代號建立後不能改。畫面以唯讀文字呈現並標示建立後不可變更，沒有可以編輯代號的輸入框。
- 專案名稱與儲存庫名稱平常也是唯讀文字。專案名稱就是專案詳情頁的頁標題，儲存庫名稱是儲存庫分頁的列標題。
- 按「更名」後，畫面中央出現對話框：輸入框預填目前名稱，有確認與取消，並標示代號不會跟著改。
- 更名成功：對話框關閉，頁標題、麵包屑或列標題立即顯示新名稱。例如把專案 demo 的名稱改成「Demo 2」，頁標題與麵包屑最後一段變成「Demo 2」，說明裡的專案代號仍是 demo。
- 更名失敗：對話框保持開啟，保留你輸入的名稱，並顯示錯誤。

## 總覽

總覽以 768px 寬的一欄置中。

- 頂端四格數字磚：有效使用者、專案、有效憑證、待啟用邀請的計數。每格的說明帶出次要計數（停權人數、儲存庫數）或這個數字的定義。
- 點數字磚前往對應的管理目的地。待啟用邀請那格前往使用者頁的邀請中分頁。
- 有待處理事項時，數字磚下方出現「需要處理」卡。每則待辦一列，附處理入口；待接受的邀請前往邀請中分頁。例如系統沒有任何有效憑證時，這張卡提供建立存取金鑰的入口。
- 沒有待處理事項時，「需要處理」卡整張不出現，不留空白的小標或空卡。
- 另有兩張卡：系統健康摘要（含資料結構版本），標頭有前往系統頁的入口；最近稽核事件，標頭有前往稽核紀錄的入口。資料結構版本不另做一格數字磚。

## 帳號頁

帳號頁以 768px 寬的一欄置中，由上而下四張卡：我的專案、存取金鑰、裝置登入、登入工作階段。

- 我的專案：你隸屬的每個專案。每列左邊是顯示名（沒有顯示名時用專案代號）與專案代號，右邊是角色籤。
- admin 與一般成員看到的是同一張卡、同一種內容。admin 不會因為管理身分而多列沒有隸屬的專案；全部專案要到管理面看。
- 沒有任何隸屬時，卡內說明隸屬由管理員授予。卡本身與小標仍在。
- 這張卡唯讀，沒有任何改隸屬的操作。
- 建立存取金鑰：按「建立存取金鑰」開對話框，流程同上面的「只顯示一次的祕密」。按「完成」後，存取金鑰卡多出這一列。

存取金鑰、裝置登入與登入工作階段各自的規則見 [帳號、邀請、存取金鑰與 membership](accounts.md)。

## 首次進入的導覽

- 第一次開管理面時，後台自動啟動分步導覽。
- 每一步指向畫面上實際存在的元素，附一句說明。說明卡片依元素的位置擺放，不遮住它。
- 說明寫的互動方式與畫面一致。例如「使用者」那一步說明點使用者那一列進入詳情頁編輯，「建立」那一步說明這一頁的主要動作會開啟置中的對話框。兩種介面語言都一樣。
- 每一步都有下一步、上一步、略過整個導覽。導覽不會擋住你用鍵盤離開。
- 走完或略過後，之後不再自動啟動。介面保留重新啟動導覽的入口。
- 某一步的目標元素不存在時，導覽跳過那一步，不中斷，也不顯示空的高亮框。
- 導覽不讀寫任何管理資料。

## 介面語言

- 後台提供中文（zh-TW）與英文（en），兩種語言的欄位、動作與說明完全對應。
- 沒選過語言時，依瀏覽器語言決定：以 `zh` 開頭的用中文，其餘用英文。
- 已登入：在側欄底部帳號選單的「介面語言」切換，可選中文、英文或跟隨系統，並標示目前選擇。
- 未登入的流程頁：卡片下方有中文與英文兩個切換鈕（英文那顆寫「English」），標示目前語言。在登入頁切成英文後登入，管理面也是英文。
- 兩處切換寫的是同一個偏好。切換立即生效，重新載入後維持。選「跟隨系統」會清掉偏好，回到依瀏覽器語言決定。
- 語言選擇不影響 artifacts 的產出語言、CLI 輸出、稽核紀錄的動作名稱，也不影響 server 回傳的錯誤訊息。
- 英文介面的計數依數量用單數或複數。例如總覽有 1 位尚未啟用的受邀者時，需要處理區顯示「1 user has not activated yet.」；專案只有 1 個儲存庫時，專案列顯示「Key demo · 1 repository」，2 個時顯示「Key demo · 2 repositories」。中文介面不變。

## 狀態顏色

- 正常、啟用、有效：綠色。
- 異常：紅色。
- 停權：琥珀色。
- 已撤銷：中性色，與有效一眼可分。
- 對話框裡裝明文金鑰或邀請連結的成功框：綠色成功樣式，不用主題主色。
- 角色、稽核來源這類純資訊籤：中性色。
- 同一件事在同一頁的橫幅與徽章，顏色意思一致。例如總覽與系統頁的儲存後端狀態，連線正常是綠色、斷線是紅色，與同頁的離線警示橫幅一致。

## 鍵盤、游標與動態效果

- 所有操作都可以用鍵盤完成。頁面有跳到主內容的連結，取得焦點的控件有至少 2px 的焦點框。
- 可點的東西滑鼠移入時顯示手指游標：按鈕與圖示鈕、可選取的清單列與卡片、分頁、選單項與下拉選項、側欄導覽。
- 停用或唯讀的元素是箭頭游標，不顯示禁止符號，也沒有滑過時的底色。文字輸入框的文字游標不在這條規則內。
- 桌面 app 與後台共用同一份游標設定，但桌面 app 一律改成箭頭；手指游標只出現在瀏覽器後台。
- 作業系統設定減少動態效果時，後台不播放頁面切換、側欄滑出、提示訊息與狀態切換的動畫，狀態仍然看得出來。
