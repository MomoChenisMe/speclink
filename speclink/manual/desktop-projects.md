# 專案、新增專案與設定頁

桌面 app 可以同時開著好幾個專案。一個專案是一個本機資料夾，或 server 上的一個 Project／Repo。這一頁說明怎麼新增專案、在專案之間切換、專案動作選單，以及兩種設定（專案設定、應用程式設定）能改什麼。視窗外殼（標題列、圖示列、專案欄、原生選單）見[認識桌面 app](desktop-overview.md)。

## 新增專案

所有開啟入口——圖示列的「＋」、沒有任何專案時空狀態頁的「新增專案」與「連線 Server」、macOS 原生選單的「開啟專案…」——都進到同一個「新增專案」對話框。

第一步選來源，有兩張可選取的來源卡：

- 「本機資料夾」：選取後頁尾的主要鈕變成「選擇資料夾…」，按下開系統的資料夾選擇器。
- 「Server」：選取後主要鈕變成「下一步」，按下進到 Server 步驟。

還沒選卡之前，主要鈕停用。從空狀態按「連線 Server」會直接進 Server 步驟。Server 這條路（Server、Project／Repo、checkout 三步）見[桌面連線 server 與 remote 專案](desktop-remote.md)。

### 選了本機資料夾之後

app 從你選的資料夾往上找 speclink 專案根。找到就直接切換過去：看板、已封存、規格、手冊與專案設定全部換成新專案的內容，不用重啟。你選到子目錄也可以，app 會切到往上找到的專案根。

開啟失敗（路徑不存在或不可讀）時，app 顯示一行錯誤訊息，目前的專案不變。

### 三種資料夾，三種結果

| 資料夾狀態 | app 的反應 |
| --- | --- |
| 專案根有 `.speclink.yaml` | 直接開啟，不問任何問題 |
| 有規格資料夾（`speclink/`，或舊佈局的 `openspec/`）但沒有 `.speclink.yaml` | 顯示啟用確認對話框 |
| 往上找不到任何 speclink 專案 | 顯示初始化確認對話框 |

兩種確認對話框都有 AI 工具多選（claude、codex、copilot），預設只勾 claude。初始化對話框的說明文字寫明會建立 `speclink/`。你按確認之前，app 不會在資料夾寫入任何東西。你取消，資料夾內容維持原樣。

每個工具的技能檔放在各自的目錄：

| 工具 | 技能檔位置 |
| --- | --- |
| claude | `.claude/skills/` |
| codex | `.agents/skills/` |
| copilot | `.github/skills/` |

**初始化**（全新資料夾）：確認後 app 做的事等同於 `speclink init`。它建立 speclink/ 骨架（specs/、changes/archive/、config.yaml）、在專案根寫 `.speclink.yaml` 記錄你選的工具、為每個工具生成技能檔。它不會產生 CLAUDE.md、AGENTS.md 或 `.github/copilot-instructions.md`。接著切到該專案，看板是空的。

**啟用**（已有規格資料夾的資料夾，例如從別處搬來的專案）：確認後 app 只補缺的東西：`speclink/` 缺的骨架、專案根的 `.speclink.yaml`、你選的工具的技能檔，同樣不生成指令檔。既有規格文件的內容不會被改寫，包含你自訂過的 config.yaml。判定與寫入都以往上找到的專案根為準，不是你點的子目錄。例如只勾 copilot 啟用，專案根只會多出 `.speclink.yaml`（工具只有 copilot）與 `.github/skills/`，不會產生 `.claude/`、`.agents/`、CLAUDE.md、AGENTS.md。

規格資料夾是舊佈局的 `openspec/`（例如 OpenSpec 專案）時，啟用對話框另外寫明：確認後資料夾會改名為 `speclink/`，之後 OpenSpec CLI 讀不到這個專案。確認後 app 先匯入：`openspec/` 改名為 `speclink/`、內容逐位元組不變，每個 `.openspec.yaml` 改名為 `.meta.yaml`；接著才補缺件，然後在看板呈現既有內容。這條路與 CLI 的工作區補齊相同，見[建立工作區與指令檔](init-workspace.md)。

初始化或啟用失敗時，app 顯示一行錯誤訊息說明原因，不切換專案。舊佈局的資料夾有其他 worktree、或 `openspec/` 有未提交修改時，匯入會被拒絕：例如錯誤訊息說明 `openspec/` 有未提交修改，目前專案不變，所選資料夾的內容也不變。

資料夾帶 remote 標記（`.speclink.yaml` 的 remote 區段）時另有分流，見[桌面連線 server 與 remote 專案](desktop-remote.md)。

### 最近開啟

「新增專案」第一步的兩張來源卡下方是「最近開啟」區段。沒有任何專案時，空狀態頁也以同一份清單列出同樣的記錄，點擊與移除的效果一樣。它記住你成功開過的專案，讓你下次一點就開。

**怎麼記**：

- 每次成功開啟一個專案，app 就把它記到清單最前面。經對話框開、點圖示列的方塊切換、直接開帶 remote 標記的資料夾、本機轉 remote，四種方式都算。
- 同一個專案只留一筆，再開一次就移到最前。清單最多 20 筆，滿了就丟最舊的一筆。
- 本機轉 remote 成功時，那個資料夾的本機條目被移除，改記成 remote 條目。
- 記錄存在 app 本機，不寫進任何專案目錄。關閉專案、圖示列滿 10 個被淘汰，都不會動到這份記錄。

| 開啟順序 | 記錄（最新在前） |
| --- | --- |
| A、B、A | A、B |
| A、B、C（之後關閉 B） | C、B、A |
| W1 到 W21（21 個不同專案） | W21 到 W2，W1 被丟掉 |

**怎麼顯示**：

- 已經開著的專案不會列出來。濾完沒有東西時，整個「最近開啟」區段連標題都不顯示。
- 本機條目顯示資料夾名稱與完整路徑。remote 條目帶「遠端」籤，顯示連線名稱與 Project／Repo，連線名稱從伺服器頁的清單即時查得。
- 滑鼠停在條目上會出現 ×（「自最近開啟移除」）。移除後從畫面與記錄一起消失，重啟 app 也不會回來，其餘條目順序不變。
- 介面語言是英文時，這幾個字面分別是「Recently opened」、「Remove from recently opened」、「Connection removed」、「Connection signed out」。

**點本機條目**：app 先探測那個路徑。探測成功就關掉對話框，走與「本機資料夾」選同一路徑完全相同的流程：既有專案直接開、沒有 speclink 骨架的走初始化確認（確認前不寫入）、帶 remote 標記的走 remote 分流。探測失敗（例如資料夾已被刪除）時，該條目變成錯誤態並顯示一行原因，對話框留在原地，目前專案不變。條目會留在清單裡，直到你自己移除；你也可以再點一次重試，重試開始時錯誤態清掉。

**點 remote 條目**：app 先確認原本綁定的 checkout 仍然對得上那個 Project／Repo，再用同一個連線開啟。連線已移除或已登出的條目會停用開啟，規則見[桌面連線 server 與 remote 專案](desktop-remote.md)。

錯誤態在你下一次打開「新增專案」、或空狀態頁重新出現時清掉。

**升級與壞資料**：升級 app 後第一次啟動、還沒有最近開啟記錄時，app 用既有的開著的專案補種這份清單，最後開的排最前。記錄已存在（就算是空的）就不補種，重啟也不會重複補種。記錄壞到無法解析時，app 照常啟動、不報錯，清單視為空。個別條目壞掉時只丟那一筆。下一次成功開啟專案後，記錄重新寫入，只含那一筆。

## 圖示列上的專案

每個開著的專案在左側圖示列是一個方塊，裡面是顯示名的首字母。作用中的方塊是主色底白字。

- 最多開 10 個專案。開著哪些、順序、最後作用中的是哪個，都跨重啟保留。這些記錄存在 app 本機，不寫進任何專案目錄。
- 點方塊就切換專案：看板、已封存、規格、手冊與專案設定全部換成那個專案，左側標題列與麵包屑的專案名也跟著換。Ctrl+Tab 循環切換，Ctrl+1 到 Ctrl+9 直達第 N 個專案。
- 同一個專案再開一次不會多一個方塊，而是跳到既有那個。
- 滑鼠停在方塊上，提示顯示完整的顯示名與路徑。remote 專案顯示 checkout 路徑；沒有 checkout 時顯示連線與 Project／Repo。
- 方塊上沒有計數徽章。待收尾的數量看看板欄位計數與系統匣面板的分區計數。
- 方塊角落可能有狀態點：紅點代表資料夾已不存在；琥珀點代表 remote 專案離線或需要重新登入。本地專案方塊的琥珀點見[自動更新、CLI、技能檔過期與關於頁](desktop-update.md)的技能檔過期提示。
- 關閉專案：左側標題列的「⋯」或方塊右鍵選單裡的「關閉專案」。關閉只把它從圖示列移除，不影響最近開啟；關掉的專案會出現在最近開啟，一點就能開回來。

方塊指到的資料夾已經不存在時，方塊變成錯誤態（角落紅點，提示附錯誤原因）。點它會彈出選單，第一列是一行錯誤訊息，其後只有「自專案列移除」，不會切換專案。app 啟動時會對每個背景本地專案探測一次路徑，失效的也轉成錯誤態。

沒有任何專案時（例如第一次使用），左側只有圖示列（品牌標記、「＋」、設定），沒有專案欄。主區置中顯示空狀態：字標、「開啟一個專案開始」標題、說明（含「資料夾還沒有 speclink/ 時會先問你要不要初始化」）、「新增專案」與「連線 Server」兩顆按鈕，以及最近開啟卡。

## 專案動作選單

左側標題列的「⋯」與圖示列方塊的右鍵，打開的是同一份選單：

| 項目 | 做什麼 |
| --- | --- |
| 在 Finder 顯示（Windows 為「在檔案總管顯示」，Linux 為「在檔案管理員顯示」） | 在系統檔案管理器顯示專案目錄 |
| 在終端機開啟 | 以專案目錄為工作目錄開終端機 |
| 以編輯器開啟 | 依序嘗試 PATH 上的 code、cursor、zed、subl |
| 複製路徑 | 把目錄的完整路徑寫進剪貼簿 |
| （分隔線） | |
| 重新整理（⌘R／Ctrl+R） | 重新載入專案 |
| 關閉專案（紅字，⌘W／Ctrl+W） | 把專案從圖示列移除 |

本機專案作用在專案根目錄。remote 專案連接了 checkout 時作用在 checkout 目錄；沒有 checkout 時，選單只有「重新整理」與「關閉專案」。

終端機依平台嘗試：

| 平台 | 依序嘗試 |
| --- | --- |
| macOS | 系統的 Terminal |
| Windows | Windows Terminal，沒有時退回 cmd |
| Linux | x-terminal-emulator、gnome-terminal、konsole、xfce4-terminal |

啟動後立刻以失敗結束的候選（例如不認得工作目錄參數）視同無法啟動，改試下一個。

- 動作成功時不顯示任何文字訊息。
- 候選全部無法啟動：toast「找不到可用的終端機」，或「找不到可用的編輯器（支援 VS Code、Cursor、Zed、Sublime）」。
- 在終端機開啟或以編輯器開啟時，專案目錄已不存在：toast「專案目錄已不存在」，不嘗試任何候選。
- 其他失敗（包含在檔案管理器顯示失敗）：toast 顯示錯誤原文。

在非作用中專案的選單選「重新整理」，會切換到那個專案（切換就是重新載入），原本的作用中專案不重新載入。快捷鍵 ⌘R（macOS）或 Ctrl+R（Windows、Linux）重新整理作用中專案；Ctrl+W（Windows、Linux）關閉作用中專案。macOS 的 ⌘W 由系統選單處理。

## 兩種設定

設定分成兩種模式：

- **專案設定**：跟著作用中專案走，從專案欄底部的「專案設定」進入。
- **應用程式設定**：與任何專案無關，從圖示列的設定齒輪進入。沒有任何專案時也進得去。

兩種模式都用左側分類欄切換：點一個分類，主區就換成那個分類的一頁；分類欄記得你上次在哪一頁。每頁上方是頁標題、灰字說明，右側是頁級動作（例如編輯）；內容是一張張卡，卡內一列一筆，左邊是標籤與說明，右邊是開關或下拉。

### 專案設定（本地專案）

分類欄分兩組，預設落在專案說明：

| 組 | 分類 | 內容 |
| --- | --- | --- |
| speclink/config.yaml | 專案說明 | 專案說明卡 |
| | 產出規則 | 產出規則卡 |
| | 審查規則 | 預設清單卡、專案規則卡 |
| | 產出流程 | 產出政策卡、產出流程卡 |
| 專案 | .speclink.yaml | 檔案列、AI 工具卡 |

每頁頁標題下用等寬字註記對應的檔案與鍵，例如 `speclink/config.yaml · context`。註記與分類欄的組名都照專案實際的規格資料夾顯示：還沒遷移的舊佈局專案是 `openspec/config.yaml · rules` 這種寫法，`.speclink.yaml` 明寫了規格資料夾路徑時就用那個路徑。

整個 app 提到規格資料夾或變更資料檔的地方都照這條規則，不寫死舊名稱：

- 討論詳情顯示的記錄路徑，例如 `speclink/discussions/board-search-bar.md`。
- 遷移到遠端與來源選擇對話框，把本機的規格資料夾稱為「本機規格資料夾」。
- 某個變更的資料檔解析失敗時，看板卡片的提示稱它為「變更資料檔」並附解析原因，不出現 `.openspec.yaml` 字樣。
- 新專案的說明文字（初始化對話框、空狀態、來源選擇）寫 `speclink/`。

這些文案都跟隨介面語言。

#### 專案說明

唯讀時以 markdown 渲染全文，不收合（這一頁只有它）。沒設定時顯示空狀態提示。

按頁標題右側的編輯，卡片換成程式碼編輯器：有行號、自動換行，底部狀態列顯示模式、自動換行與「第 N 行第 M 欄」。這裡是 markdown 模式，標題、行內 code、連結、強調會上色。按鈕列變成「編輯／預覽」切換、取消與儲存。儲存鈕標示 ⌘S／Ctrl+S，在編輯器裡或頁面上按都會儲存。

- 預覽：以 markdown 渲染目前的草稿。切回編輯，草稿與游標位置都還在。
- 儲存：把編輯器內容原樣寫入，不去頭尾空白、不增刪檔尾換行、不改縮排。全部清空再儲存，這個欄位會整個移除。
- 取消：還原唯讀呈現，不寫檔。

#### 產出規則

唯讀時只列出有內容的產物分節，分節名為小標、規則為清單。

編輯時依目前的產出流程固定分節（spec-driven 是 proposal、design、specs、tasks 四節），每節一張小卡：等寬的分節名、即時的「N 條」計數，裡面是與專案說明同款的編輯器（純文字模式）。不能自己新增分節。

- 一行就是一條規則，行的順序就是寫入與注入的順序。把第二行搬到第一行再儲存，順序就對調。
- 儲存時每行去頭尾空白，空行不寫入、也不計入「N 條」。
- 某節清空就移除那一節，全部清空就移除整個產出規則。
- 以特殊字元開頭的規則（例如 @ 或反引號）會自動加引號，存回去仍逐字還原。

專案說明與產出規則兩頁各自獨立：一頁進入編輯不影響另一頁，各頁儲存只寫自己的鍵。

#### 審查規則

頁標題下註記 `speclink/config.yaml · review`。介面文案跟隨介面語言，但嚴重度籤 CRITICAL、WARNING、SUGGESTION 與 smell 名稱維持英文。這些規則在審查時怎麼生效、CLI 怎麼寫，見[工作流政策與設定](policy-config.md)與[審查](review.md)。

唯讀時兩張卡：

- 預設清單卡：目前的模式（「沿用並追加」或「整份換掉」）與一句說明。按「查看 12 條」展開 12 條 smell 名稱：Mysterious Name、Duplicated Code、Feature Envy、Data Clumps、Primitive Obsession、Repeated Switches、Shotgun Surgery、Divergent Change、Speculative Generality、Message Chains、Middle Man、Refused Bequest。名稱取自引擎，app 不另存一份。
- 專案規則卡：依三個嚴重度分節列出規則，每節帶嚴重度籤、一行效果說明與條數。三節都空時顯示空狀態。

| 嚴重度 | 效果說明 |
| --- | --- |
| CRITICAL | 擋蓋章；要接受放行須逐條再確認 |
| WARNING | 擋蓋章；偶有正當例外可接受放行 |
| SUGGESTION | 只記在工單，不擋蓋章 |

按編輯後：

- 預設清單是列右側的下拉，選項「沿用並追加」與「整份換掉」，列說明跟著所選模式換。
- 專案規則是 CRITICAL、WARNING、SUGGESTION 三張固定小卡（嚴重度籤與即時「N 條」計數），裡面是與產出規則同款的編輯器，不能新增節。一行一條、行序就是寫入順序；儲存時每行去頭尾空白，空行不寫入。
- 選「整份換掉」又把三節都清空時，頁內提示「Standards 軸只依 repo 文件審查」，但不擋儲存。
- 儲存只寫審查規則這個區塊，專案說明、產出規則與政策欄位逐字不變。取消不寫檔。

| 操作前 | 編輯 | 寫入後 |
| --- | --- | --- |
| CRITICAL 一條、WARNING 一條 | 清空 WARNING 並儲存 | 只剩 CRITICAL 一條 |
| 整份換掉、CRITICAL 一條 | 改選「沿用並追加」並儲存 | 只剩 CRITICAL 一條，模式不寫進檔案（沿用並追加是預設） |
| 只有 SUGGESTION 一條 | 清空 SUGGESTION 並儲存 | 整個審查規則區塊移除 |

#### 產出流程

這一頁有兩張卡。

**產出政策卡**：locale 與 spec_locale 是列右側的下拉，tdd、audit、worktree 是開關，底部是儲存與訊息列。這些欄位的意義見[工作流政策與設定](policy-config.md)。

- 儲存只代換你動到的鍵，其他鍵原樣保留。把政策欄位設回預設值時會移除那個鍵，而不是寫明值。

  | 操作前 | 操作 | 寫入後 |
  | --- | --- | --- |
  | 沒有 tdd | tdd 切開啟 | 新增 tdd: true |
  | tdd: true | tdd 切關閉 | tdd 被移除（預設就是關） |
  | locale: tw，還有產出規則 | spec_locale 選 auto | 新增 spec_locale: auto，locale 與產出規則不動 |

- worktree 開關的文案直接寫「worktree」，中英文介面都一樣。開關顯示 config.yaml 的現值，儲存時以畫面上的值寫入，成功後同步技能檔（與 CLI 改 worktree 相同）。這個同步只動技能檔：還是舊佈局 `openspec/` 的專案，資料夾原封不動，兩顆 worktree 技能照常以 `openspec/` 生成，看板持續自動更新；搬資料夾只由技能檔提示的「更新」做，見[自動更新、CLI、技能檔過期與關於頁](desktop-update.md)。由開改關時，如果還有活躍的 linked worktree，app 拒絕寫入並浮出擋下訊息：列出每個 worktree 的變更名、分支與路徑，提示先執行 worktree-merge 收尾。設定不變、開關回到開啟。見[平行實作與合回：worktree](worktree.md)。
- locale 或 spec_locale 的儲存值不在合法選項內時（例如有人手改成「繁體中文」），下拉直接顯示那個原始值，帶無效標註與警示樣式，欄位下方出現提示文字，引導你改選合法代碼。app 不會自動清空或改寫它。你改選合法代碼並儲存後，值被覆蓋、提示消失。合法代碼：locale 為 tw、ja、en；spec_locale 為 tw、ja、en、auto。

**產出流程卡**：列出每個可解析的產出流程，每列有名稱、來源層級、產物順序圖（例如 proposal → design → specs → tasks）。點進去是唯讀詳情，列出每個產物的說明、指令與範本全文；內建流程的內容不能在桌面編輯。卡上提供的動作：

- 切換：用下拉選專案要用的產出流程，寫進 config.yaml 的 schema 鍵，其他內容逐位元組不變。config.yaml 壞掉時拒寫，錯誤浮出、檔案不變。產出規則頁的分節隨新流程更新；如果產出規則正在編輯中，分節等你儲存或取消後才跟上，草稿不會丟。
- fork：把選中的流程複製到專案的 speclink/schemas/ 下，複本名固定為「原名-custom」，例如 spec-driven 的複本是 spec-driven-custom。同名流程出現在不同層時，只有引擎實際會用到的那一層提供 fork。
- 建立：輸入 kebab-case 名稱，在專案 speclink/schemas/ 下產出預設骨架。

  | 輸入 | 結果 |
  | --- | --- |
  | my-flow | 建立 speclink/schemas/my-flow/，清單新增這一項 |
  | My Flow | 拒絕，引擎的名稱錯誤浮出，磁碟不變 |
  | my-flow（已存在） | 拒絕，引擎的已存在錯誤浮出，磁碟不變 |

- 開啟所在資料夾：對專案層與使用者層的流程，在系統檔案管理器顯示它的目錄。內建流程沒有這個動作。內容編輯交給外部編輯器。
- 刪除：只對專案層的流程。按下先出確認對話框，取消零變動。確認後整個目錄移除。config.yaml 正在使用的流程拒刪，錯誤浮出、磁碟不變。

產出流程本身是什麼、CLI 怎麼管，見[產出流程 schema 管理](schemas.md)。

#### .speclink.yaml

這一頁有「檔案」列（等寬路徑，唯讀）與「AI 工具」卡。內建工具 claude、codex、copilot 每個一列附開關；自訂工具描述子原樣列出、不可編輯，寫入後也原樣保留。

改了工具並儲存後，app 同步技能檔：新開的工具生成技能檔，關掉的工具清掉它目錄下 speclink- 開頭的技能資料夾。不生成 AGENTS.md 之類的指令檔。例如先開 copilot 儲存，專案根多出 `.github/skills/`；再關掉 copilot 儲存，`.github/skills/` 下 speclink- 開頭的資料夾全數移除，`.github/` 下其他檔案一個位元都不變。

### 專案設定（remote 專案）

作用中的是 remote 專案時，分類欄只有 speclink/config.yaml 組的四項：專案說明、產出規則、審查規則、產出流程。沒有 .speclink.yaml，因為工具屬於本機 checkout。四頁的內容來自 server 上的政策文件，頁標題下以等寬字顯示政策版次。鍵的保留規則與本地相同：沒動到的鍵原樣保留，設回預設就移除。

- 儲存時 app 帶著你讀到的版次送出。別人先一步改過時，你會收到版次衝突：你的輸入原樣保留，頁頂浮出逐欄位對照（server 現值｜我的輸入）。只有兩個出口：「以 server 版重載」與「檢視後以最新 revision 重新提交」。沒有強制覆寫。
- 你在這個 Project 的角色是 reader 時，四頁唯讀、儲存停用，並附繁中角色說明。
- 產出流程頁只列兩個內建流程（spec-driven 與 no-spec-change，後者的產物圖是 proposal、design、tasks），切換下拉也只有這兩個可選。config 指到非內建名稱時，以停用項顯示現值、不可選取，並顯示「遠端自訂尚不支援」，產出規則的分節留空。fork、建立、開啟所在資料夾、刪除都不出現，也沒有 worktree 開關。
- 審查規則頁一樣能展開 12 條名稱，儲存同樣帶版次。

## 設定寫入的保護

- 讀取時區分「檔案不存在或欄位未設定」與「檔案存在但解析失敗」。前者顯示為預設值狀態。後者：分類欄裡掛那個檔的分類項帶警示點（config.yaml 壞掉時是專案說明、產出規則、審查規則、產出流程四項；.speclink.yaml 壞掉時是 .speclink.yaml 項），頁內浮出解析失敗說明，表單與編輯鈕停用，app 不會對那個檔案寫入。審查規則區塊裡出現不認得的子鍵（例如把 critical 打成 critcal）也算解析失敗，說明會帶出那個字。
- 應用程式設定不受任何專案設定檔壞掉的影響，例如顯示語言照常可改。
- 每次寫入前 app 先確認新內容解析得回來、目標欄位值正確。寫檔後再回讀驗證一次。任一步失敗就顯示一行指明檔案與階段的錯誤訊息，磁碟上的檔案維持原內容，不會留下解析不了的設定檔。
