# 路線圖

路線圖是看板頁的另一種檢視：一張表，一波一欄，每個還沒封存、排得出波次的變更一列。你可以一眼看出先做哪個、誰在等誰，以及討論結論裡還有哪幾刀沒轉成變更。

路線圖只能看，上面沒有任何會寫入的操作。資料都來自引擎的 plan，順序怎麼算見[執行順序：plan 與依賴](plan.md)。

> [!NOTE]
> 畫面文字「沒有進行中的變更」在路線圖上泛指還沒封存的變更，包含提案中與已就緒，跟看板的「進行中」欄不是同一個意思。

## 切換看板與路線圖

看板頁的頁首有「看板｜路線圖」切換，兩種檢視都看得到它。

- 切換只換看板頁顯示哪一種檢視。專案欄不變，兩種檢視下「變更」項都是現行項。
- app 啟動時一律是看板。同一次執行期間，切換分頁、或切到別頁再回來，都維持上次選的檢視。例外是 `speclink://project` 網址：它一律切回看板，見[用 speclink 網址開啟畫面](desktop-deep-link.md)。
- 這個選擇不寫入任何檔案，所以重開 app 又回到看板。
- 切到路線圖時，看板仍保留在背後，看不到也不能操作。切回來時，捲動位置、搜尋字串與篩選都和切走前一樣。
- 路線圖和看板用同一次載入的資料，不另外查詢。本地與 remote 專案的行為相同。

| 你做的事 | 結果 |
| --- | --- |
| 在看板輸入搜尋字串 search，把「進行中」欄捲到底，點「路線圖」，再點「看板」 | 點「路線圖」後主區是路線圖，專案欄「變更」項仍高亮；點「看板」後搜尋字串仍是 search，「進行中」欄仍捲在底部 |
| 在路線圖點專案欄「規格」，再點「變更」 | 先看到規格頁，回到看板頁時仍是路線圖 |

## 表的長相

最左是變更欄，右邊每一波一欄，波次由左到右遞增。每個波次欄的欄頭寫波次與該波的變更數，另外再寫一句：

| 波次 | 欄頭例子 |
| --- | --- |
| 第 1 波 | 「第 1 波」「2 · 可以並行」 |
| 第 N 波（N ≥ 2） | 「第 2 波」「1 · 等第 1 波」 |

每個有波次的變更是表中的一列，稱為一站。列由上而下依波次遞增，同一波內依 plan 的配置順序。站的圓點落在所屬的波次欄，其他波次欄留白。

討論卡與已封存的變更不會出現在路線圖上。

### 站的圓點與文字

變更欄寫變更名，次行寫「完成數/總數 · 狀態」。圓點依階段不同：

| 情況 | 圓點 | 次行 |
| --- | --- | --- |
| 提案中 | 外框 | `0/4 · 提案中` |
| 進行中 | 圓圈，表示任務進度 | `2/5 · 進行中` |
| 已就緒（任務全勾） | 實心 | `6/6 · 已就緒` |
| 被前置擋住 | 虛線圈，整列變淡 | `0/3 · 等待：add-a` |

名稱等於 plan「下一個」的站，狀態是「下一個」籤，圓點帶主色光暈。plan 沒有下一個時，沒有任何站帶這個籤。

### 開啟詳情頁

每站可以用 Tab 移過去。點一下或按 Enter，開啟該變更的詳情頁。

開詳情頁不改變看板頁的檢視：從路線圖開的詳情頁，按 Esc 關閉後回到路線圖。詳情頁麵包屑右端的 ‹ n／m › 依看板卡片的順序，路線圖沒有自己的一套順序。詳情頁的共通規則見[認識桌面 app](desktop-overview.md)。

### 無法排程的變更

狀態檔（`.meta.yaml`）無法解析的變更沒有波次，不會成為站。有這種變更時，路線圖頁首下方多一行「N 個變更無法排程，只在看板顯示」。看板照舊列出它。

例如專案有一個狀態檔壞掉的 broken-meta 與兩個正常的變更：路線圖只有兩站，頁首下方寫「1 個變更無法排程，只在看板顯示」。

## 依賴線與亮起路線

路線圖替每一條兩端都在表上的依賴畫一條線，從前置站連到依賴它的站。

- 一端不在表上（已封存、無法排程）的依賴不畫線。例如 add-b 依賴 add-a、add-a 已封存：沒有連到 add-b 的線，add-b 也不會變淡。
- 尚未轉出的刀不和任何站或刀連線。

滑鼠停在一站、或鍵盤焦點落在一站時，亮起它的整條路線：

- 該站、它全部的前置（前置的前置也算）、全部依賴它的站（依賴者的依賴者也算），以及兩端都在這組站內的線，維持原樣，線用主色強調。
- 路線外的站與線變淡。
- 滑鼠移開而且焦點離開後恢復。

亮起只改呈現，不改任何資料或選定狀態。

假設 add-b 依賴 add-a、add-c 依賴 add-b，add-x 與三者無關：

| 停留的站 | 亮起的站 | 亮起的線 |
| --- | --- | --- |
| add-a | add-a、add-b、add-c | add-a→add-b、add-b→add-c |
| add-b | add-a、add-b、add-c（add-x 變淡） | add-a→add-b、add-b→add-c |
| add-c | add-a、add-b、add-c | add-a→add-b、add-b→add-c |
| add-x | add-x | 無 |

## 尚未轉出的刀

討論結論裡規劃了、還沒轉成變更的刀，會列在路線圖上。哪些算尚未轉出，規則見[執行順序：plan 與依賴](plan.md)。

有這種刀時，表的最右邊多一欄「尚未轉出」，欄頭寫刀數，例如「1 刀」。每把刀一列，排在所有站的列之下，順序與 plan 的清單相同。全部都轉出時，沒有這一欄，也沒有刀的列。

刀的一列長這樣：

- **變更欄第一行**：該刀尚未轉出的變更名。滑鼠停在變更名上，提示範圍句；範圍句是空的就沒有提示。
- **次行**：討論 slug 與刀編號，例如 `herdr-speclink-panel · cut 4`。slug 在目前專案的討論清單內時可點，點了開啟該討論的詳情頁，關閉後回到路線圖；不在清單內時是不可點的文字。
- **再下一行**：與討論詳情頁相同的指令籤 `/speclink-propose --from-discussion <slug>`。按籤上的「複製指令」，剪貼簿就是這條指令。
- **其他欄**：波次欄留白。「尚未轉出」欄有橄欖色虛線方塊，和討論詳情頁的「尚未轉出」相同。討論詳情頁怎麼呈現這些刀，見[規格、討論、已封存與搜尋](desktop-browse.md)。

## 成環與空狀態

| 情況 | 路線圖 |
| --- | --- |
| 依賴成環 | 沒有波次欄、站與線；顯示與看板相同文字的成環提示，含引擎的訊息，例如 `dependency cycle: add-a -> add-b -> add-a` |
| 沒有任何變更，也沒有尚未轉出的刀 | 顯示「沒有進行中的變更」 |
| 全部變更都無法排程，也沒有尚未轉出的刀（例如 remote 專案的 server 沒有 plan） | 只有一行「N 個變更無法排程，只在看板顯示」，沒有表，也沒有「沒有進行中的變更」 |
| 資料載入中 | 與看板相同的載入狀態 |

## 用網址直接開路線圖

外部程式送出 `speclink://roadmap?project=<專案資料夾絕對路徑>`，app 會切到該專案的路線圖。細節見[用 speclink 網址開啟畫面](desktop-deep-link.md)。
