# 自由欄位

自由欄位是你自己訂的「鍵＝值」，掛在變更或討論上。常見的用法是記下工單編號、來源系統或負責的小組，例如 `ticket=PROJ-1`。

> [!NOTE]
> Speclink 只替你存放自由欄位，不解讀任何鍵或值。它們不會改變任何指令的行為、順序或守門：即使你把鍵取名為 `schema` 或 `depends_on`，`plan`、`validate` 與 `archive` 的結果都不變。要依欄位做判斷，由你自己的程式或系統來做。

## 設定與移除

變更與討論各有一組指令：

```
speclink change field set <變更> <鍵>=<值> ...
speclink change field unset <變更> <鍵> ...
speclink discuss field set <slug> <鍵>=<值> ...
speclink discuss field unset <slug> <鍵> ...
```

- 一次可以給好幾組。全部寫入，或全部不寫：有一組不合規則，整次都不寫。
- `<鍵>=<值>` 在第一個 `=` 分開，所以值可以含 `=`。`query=a=b` 的值是 `a=b`。
- 移除一個不存在的鍵會成功，不產生任何改動。

成功時印出一行：

| 情況 | 輸出 |
| --- | --- |
| 有設定 | `✓ <名稱>: set <鍵…>` |
| 有移除 | `✓ <名稱>: unset <鍵…>` |
| 沒有任何改動 | `✓ <名稱>: no change` |

列出的鍵依位元組順序排，不是你輸入的順序。例如 `speclink change field set demo ticket=PROJ-1 source=portal` 印出 `✓ demo: set source, ticket`。加 `--json` 時改印寫入後的全部欄位。

本機專案與遠端專案的用法與輸出相同。

## 建立時一起帶上

建立變更或討論時，可以用 `--field` 直接附上欄位，要幾個就寫幾次：

```
speclink new change <變更> --field ticket=PROJ-1 --field source=portal
```

`speclink discuss new` 也接受同樣的 `--field`。

欄位和建立是同一次寫入。有一個欄位不合規則時，建立整個失敗，變更或討論不會被建立。

## 鍵與值的規則

| 項目 | 規則 |
| --- | --- |
| 鍵 | 小寫英文字母開頭，後面只能是小寫英文字母、數字、`_`、`.`、`-`，總長最多 64 個字元 |
| 值 | 字串，最多 1024 個位元組，不能有換行或其他控制字元。可以是空字串 |
| 數量 | 一個變更或一份討論最多 32 個鍵 |

值一律當成字串存，讀回來和寫入時逐字相同。看起來像數字、布林或 null 的值（`123`、`true`、`null`），以及含冒號、井號、引號、反斜線或中文的值都一樣。

不合規則的例子：鍵 `Ticket`（大寫）、`1st`（數字開頭）、含空白的鍵、65 個字元的鍵、含換行的值、第 33 個鍵。

## 會被拒絕的情況

| 情況 | 結果 |
| --- | --- |
| 鍵、值或數量不合規則 | 拒絕，文件完全不變 |
| 參數沒有 `=`（`set` 時），或同一次指令重複同一個鍵 | 非零結束，不寫入 |
| 變更或討論不存在 | 非零結束，訊息說明找不到 |
| 討論已經封存 | 非零結束，訊息說明找不到 |
| 欄位區塊被人手改成指令讀不懂的內容（巢狀的項目、重複的鍵） | 拒絕，文件完全不變；指令不會弄丟那些內容 |

## 存在哪裡、會不會被洗掉

- 變更的自由欄位存在變更的資料裡，討論的存在討論記錄開頭的區塊裡，名稱都是 `fields`。Speclink 不為它另開檔案。
- 最後一個鍵被移除時，`fields` 區塊也一起移除。
- 其他寫入動作都原樣保留自由欄位：勾選任務、宣告依賴、排序、更換產出流程、審查與驗證蓋章都一樣。
- 封存時，自由欄位跟著文件進入封存。

手改過的 `fields` 區塊仍然讀得出來：沒加引號的數字讀成字串，巢狀的項目被略過，變更照常列得出來。但這時指令會拒絕寫入，要先把區塊改回單純的「鍵：字串」。

變更與討論的資料放在哪裡，見[認識資料：變更、討論與規格](data-layout.md)。

## 怎麼讀回來

自由欄位只出現在 `--json` 輸出裡：`speclink list --json`、`speclink show <變更> --json`、`speclink discuss list --json`、`speclink discuss show --json` 與 `speclink discuss search --json`。沒有任何自由欄位的變更或討論，輸出裡沒有這一項。

一般輸出（不加 `--json`）不顯示自由欄位，有沒有欄位看起來都一樣。
