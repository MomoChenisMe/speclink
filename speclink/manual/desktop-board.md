# 看板與任務

看板是每個專案的主畫面。這一頁講看板的欄位、卡片、搜尋、拖曳、卡片與詳情頁上的動作，以及變更詳情頁的排程與任務分頁。側欄、詳情頁的共通版面（三欄骨架、麵包屑與返回）與回饋規則見[認識桌面 app](desktop-overview.md)；提案、設計、規格三份文件怎麼呈現，見[規格、討論、已封存與搜尋](desktop-browse.md)。

## 看板的欄位

看板由左到右是「討論」「提案中」「進行中」「已就緒」四欄。四欄等寬、間距 12px，填滿主區；每欄最窄 220px，視窗再窄時整列欄位改成水平捲動。

每一欄是一個白底、細框、圓角的容器：

- 頂端一條細色條，標出這一欄的色相：討論桃紫、提案中主色、進行中藍、已就緒綠。
- 色條下是白底的欄頭：色相圖示、欄名，以及淡底的計數徽章。計數是該欄目前顯示的卡片數。
- 欄頭下的卡片區是淡灰底，卡片多時在欄內上下捲動。
- 某一欄沒有卡片（也不是正在載入）時，卡片區中央顯示灰字：提案中「沒有提案中的變更」、進行中「沒有進行中的變更」、已就緒「沒有已就緒的變更」、討論「尚無討論」。

變更卡在哪一欄，由變更的狀態推導，優先序如下：

1. 任務全部完成（總數大於 0，完成數等於總數）→「已就緒」。
2. 已蓋開工章，或已有任何任務完成 →「進行中」。
3. 其餘 →「提案中」。

| 開工章 | 任務進度 | 所在欄 |
| --- | --- | --- |
| 無 | 0 任務 | 提案中 |
| 無 | 0/28 | 提案中 |
| 無 | 3/28 | 進行中（詳情頁不顯示開工資訊） |
| 有 | 0/28 | 進行中 |
| 有 | 13/28 | 進行中 |
| 無 | 28/28 | 已就緒 |
| 有 | 28/28 | 已就緒 |

剛提案完的變更（有任務、全未勾、未開工）在「提案中」欄。詳情頁只在變更有開工章時顯示開工者與開工日；沒有開工章、只因任務進度而列在「進行中」的變更，詳情頁不顯示開工資訊。本地與 remote 專案用同一套規則：remote 的變更帶開工章時，就算進度是 0 也列在「進行中」，系統匣也一樣。

卡片上的名稱與進度，跟 `speclink list`、`speclink status` 的輸出是同一份資料。

## 討論欄

討論欄分上下兩區，同時顯示：

- **上區**是全尺寸卡，放「引擎不會自動收走」的討論：狀態為 open 或 concluded 的討論、已轉出但尚無結論的討論，以及已轉出、已有結論但保留在途的討論。open 卡是唯讀的。concluded 卡帶「封存」按鈕。已轉出但尚無結論的卡帶「已轉出・尚無結論」標示；已轉出且保留在途的卡帶「已轉出・保留中」標示（英文介面為「Promoted · on hold」）。兩種標示都是警示色，兩種卡都沒有任何按鈕：前者等結論寫入，後者的收尾由你在 CLI 用 `speclink discuss archive` 明示解除（分期轉出的整套做法見[討論：需求還模糊時](discuss.md)）。已轉出但尚無結論的卡，不論有沒有保留旗標，都標「已轉出・尚無結論」。上區的卡不列衍生變更清單，衍生進度到討論詳情頁看。
- **下區**是欄底的「已轉出 N ›」收合列，N 是已轉出、已有結論且未保留在途的討論數。收合列是白底、上緣一條細線。預設收合；點一下，已轉出的細列就在收合列上方展開，箭頭改成朝上、指向展開出來的細列；再點一下收合，箭頭回到 ›。展開或收合的狀態記在 app 本機，重開 app 後照舊，不會寫進專案目錄。沒有這類討論時收合列不出現。

「保留在途」是 `speclink discuss conclude --hold` 寫進討論記錄的旗標。連到還沒有這個欄位的舊 server 時，一律視同未保留。討論清單資料沒有「是否已有結論」的欄位時（舊資料），已轉出的討論一律收進收合列，上區不會出現「已轉出・尚無結論」。

討論卡以 slug（檔名）為標題，用等寬字型；topic 是卡身描述。複製 slug 鈕緊跟在標題最後一個字後面，點它把 slug 寫進剪貼簿並短暫顯示已複製，不會開詳情頁。建立者以頭像圓點呈現，指標停留顯示全名，卡面不直接寫出全名。卡底並排「N 輪」與建立時間。討論卡有狀態 chip。改進討論（由改進掃描產生的討論）的卡片帶一枚小章，提示文字是「改進討論」；這枚章跟著討論走，轉出後、封存後都還在。一般討論沒有這枚章。

已轉出細列是白底細框的列，以 slug 為首行（等寬字型、帶複製鈕）、topic 為次行，下面用樹狀前綴（├、└）逐列列出轉出的變更與階段 chip：提案中、進行中、已就緒的 chip 對應各自階段欄的配色；已封存為中性色；兩邊清單都找不到的變更標示「已刪除」（紅色加刪除線），討論維持已轉出。

欄頭的計數是上區的卡片數，保留中的討論也算。可拖排的討論卡就是上區的全部卡片。上區沒有卡片、但有收進收合列的討論時，不會顯示「尚無討論」。已封存的討論不在這一欄。在外部用 CLI 對討論加一輪，幾秒內卡片的輪數就會更新，不用在 app 裡做任何事。

> [!NOTE]
> 桌面 app 不提供新增討論、加輪、寫結論、轉為變更。這些由 CLI 或 agent 執行，見[討論：需求還模糊時](discuss.md)。討論詳情頁的內容見[規格、討論、已封存與搜尋](desktop-browse.md)。

## 變更卡長什麼樣

變更卡與討論卡都是白底、細框、圓角的卡片，平常沒有陰影；指標移上去時框線變深、底色微灰。每張變更卡有三列：

1. **識別列**：變更名稱（等寬字型）、緊跟其後的複製鈕（指標停留才顯現；點它複製名稱，不開詳情頁）、右端的建立者頭像與關係圖示。
2. **描述列**：提案「為什麼」段落的首句，一行截斷。提案缺席或該段為空時，這一列不出現，看板也不會因此報錯。
3. **meta 列**：進度條與「完成數/總數」。清單有波次資訊時，這一列最左多一枚圓圈數字的波次章（見下表）。

標題永遠單行。太長時在可用寬度處截斷，以省略號收尾，不折行、不斷字；沒被截斷時完整顯示、不出現省略號。複製鈕留在同一列，緊跟標題文字，不會被推到右緣。變更卡沒有狀態 chip，因為所在欄就是階段。建立者頭像是首字母圓標，指標停留顯示全名；沒有建立者時頭像不出現。

卡片上可能出現的標示：

| 標示 | 什麼時候出現 | 指標停留顯示 |
| --- | --- | --- |
| 來自討論 | 變更有來源討論。多份來源時也只有一枚，代表第一份（出身）討論 | 全部來源討論 |
| 「待重新反映」徽章（琥珀色） | 這個變更反映的討論被重新結論，等待再次 ingest | 待重新反映的來源 |
| 「待手動」小章（暖黃色） | 寫碼任務全部完成，但還有未勾的手動任務 | 「待手動·剩 N 項」 |
| 波次章（meta 列最左的圓圈數字，顏色跟所在欄的色相） | plan 算出這個變更的波次。同一個數字的變更可以並行 | 沒被擋住：「第 N 波」；被擋住：「第 N 波 · 等待：add-a、add-b」 |
| 整卡變淡 | 這個變更被前置變更擋住，現在不能做 | 同波次章 |
| worktree 標示（藍色） | 這個變更有活躍的 worktree | 見下方「worktree 卡片」 |
| 審查章、驗證章 | 品質關卡有進度或已蓋章 | 見[桌面上的品質關卡](desktop-quality.md) |
| 「invalid」標記 | 變更的 metadata 檔壞掉 | — |

「待重新反映」與「待手動」都不影響卡片所在的欄。還沒有任何寫碼任務的變更不顯示「待手動」。remote 專案的卡片不顯示「待手動」。metadata 壞掉的卡照其階段顯示，但對它發起的變更操作會被引擎拒絕。

| 寫碼任務 | 剩下未勾的任務 | 「待手動」 |
| --- | --- | --- |
| 9 個，全部完成 | 1 個 | 顯示（剩 1 項） |
| 8 個，還有 2 個沒完成 | 3 個 | 不顯示 |
| 10 個，全部完成 | 0 個 | 不顯示 |
| 0 個 | 2 個 | 不顯示（還沒有寫碼任務） |

波次章只出現在 meta 列，標題列不會多任何章，名稱的空間不被佔用。被擋住的卡只變淡，不另外顯示「等 N 項」的文字章。清單沒有波次資訊時（remote 連到沒有 plan 的舊 server、請求失敗、或依賴成環），波次章缺席、卡片不變淡，其餘呈現與以前一樣。波次與阻擋怎麼算，見[執行順序：plan 與依賴](plan.md)。

## 搜尋與篩選

搜尋輸入在看板頁標題區的右端：全圓的輸入框帶搜尋圖示，右邊同一列是篩選圖示鈕。兩者都在欄位上方，不另外佔一列。

- 按 Cmd+F（macOS）或 Ctrl+F（其他平台）聚焦搜尋輸入。
- 輸入非空白內容後，看板只顯示命中的卡片，輸入框出現清除鈕與即時命中數。點清除鈕清空字串，輸入保持聚焦。
- 各欄欄頭的計數等於過濾後的卡片數。沒有任何命中時各欄為空、計數為 0，不顯示錯誤。

比對有三層，任一層命中就顯示：

1. **欄位子字串**：變更卡比對名稱與摘要，討論卡比對主題與 slug。去頭尾空白、不分大小寫。命中的字會高亮。
2. **名稱模糊比對**：變更名稱與討論 slug 另以字元順序比對（查詢的字元依序出現就命中）。摘要與主題不做模糊比對。只模糊命中時卡片顯示但不高亮。
3. **全文比對**：查詢也會掃描進行中變更的提案、設計、任務、delta 規格，以及進行中討論的記錄全文。全文命中的卡片會顯示一行摘錄：命中的文件名、前後文與高亮（每張卡取第一個命中）。全文查詢失敗時靜默退回前兩層，不顯示錯誤，也不擋你繼續輸入。

| 輸入 | 效果 |
| --- | --- |
| desktop | 名稱含 desktop 的變更卡顯示並高亮 |
| 桌面 | 摘要含「桌面」的變更卡顯示並高亮 |
| dta | 名稱依序含 d、t、a 的變更卡顯示，不高亮 |
| （清空） | 還原全部卡片 |

篩選收在篩選圖示鈕後面：

- 點開關鈕彈出篩選面板，有三個維度：建立者、建立時間（近 7 天／近 30 天／更早三選一）、來源討論（選定後只顯示該討論卡與來源含它的變更卡）。
- 再點開關鈕、點面板外或按 Esc 關閉面板。關閉不清除已啟用的篩選；開關鈕顯示啟用數。
- 面板內可單獨清除某個維度，也可全部清除。
- 多個維度與搜尋字串以交集過濾。

搜尋字串與篩選不跨啟動保留，也與已封存頁的搜尋各自獨立。過濾中點卡片、拖曳與封存都照常。

## 拖曳卡片

拖曳中的卡片浮起來、帶陰影；放開後浮起的卡消失，卡片回到沒有陰影的樣子。

**欄內順序**：本地專案的變更卡順序，是引擎 plan 算出的配置順序投影到該欄的結果（見[執行順序：plan 與依賴](plan.md)）。plan 的輸入之一是每張卡自己記錄檔裡的順序鍵（變更在變更目錄的 `.meta.yaml`，討論在討論記錄的 frontmatter）。同一欄的基底順序是：

1. 有順序鍵的卡排前面，依鍵值升冪。
2. 沒有順序鍵的卡排後面，依序比：被依賴的次數多的在前 → 任務總數少的在前 → 建立時間早的在前，沒有建立時間的殿後。
3. 同值以變更名的字典序決斷。

基底順序再經宣告依賴修正：宣告的前置一律排在依賴它的變更之前，就算前置的順序鍵比較大也一樣。整欄都沒有順序鍵時，欄內就是上面第 2 點的順序。依賴成環時退回基底順序。討論卡不參與 plan：依順序鍵升冪，沒有鍵的排欄頂、依 slug 序。

順序鍵有兩個寫入來源：桌面拖排，以及 CLI 的 `speclink change rank`（見[執行順序：plan 與依賴](plan.md)）。兩者寫同一個欄位、用同一套中間值算法。

**欄內拖排**：把卡片拖到同欄的新位置放開，順序就存進那張卡自己的記錄檔。

- 一次拖排只改被拖那張卡的檔案，而且只改順序那一行，其他內容逐位元不變。前提是欄內其他卡都有格式正確的順序鍵、而且鍵的順序與顯示順序一致。被拖的卡自己沒有順序鍵，不影響這一點：它的新鍵由這次移動寫入。
- 欄內（被拖的卡除外）有卡沒有順序鍵、或鍵的格式不對時，app 先依目前顯示順序替那一欄的其他卡補上順序鍵，再以落點前後鄰居的中間值寫被拖的卡。格式正確的鍵不是空的、只有小寫英文字母、不以 a 結尾；被手改成別的樣子（例如大寫）的鍵算不出中間值，視同沒有鍵。只補這一欄。欄內鍵的順序與顯示順序不一致時（例如加了前置但鍵沒動過），app 也先依顯示順序整欄重派，再套用移動。
- 變更卡寫回前，引擎先做依賴檢查：新位置會排在任何一個宣告前置之前、或排在任何一個依賴它的變更之後，就拒絕寫回。畫面顯示單行錯誤，看板刷新回磁碟上的順序。只因 delta 重疊而要依序的變更不會構成拒絕。所有檢查（依賴檢查、要寫入的卡都有 `.meta.yaml`）都在第一筆寫入前做完：被拒時，補鍵與被拖的卡都不寫任何檔案。
- 拖動變更卡的期間，不合法的落點會先灰掉：拖動 c 而 c 依賴 a 時，a 與 a 上方的位置變淡；拖動 a 時，依賴 a 的 c 與 c 下方的位置變淡。放在灰掉的位置上不寫任何檔案，卡片回原位。灰化只看宣告依賴，不看 delta 重疊。搜尋過濾中，被隱藏的前置仍決定哪些位置不合法。依賴成環時沒有灰化。
- 新建的變更卡（還沒有順序鍵、沒人依賴、任務已建立）落在欄內沒有鍵的那一群裡，位置由任務總數與建立時間決定；同欄其他沒有鍵的卡都沒人依賴、任務數也不比它多時，就是欄底。新建的討論卡落欄頂。同欄順序在不同機器上一致。
- 順序不會出現在 CLI 輸出，`speclink list` 的輸出不受影響。
- 寫回失敗（例如檔案不可寫）時，畫面以失敗浮層顯示單行錯誤，看板刷新回磁碟上的實際順序。放開前鄰居被封存或刪除，app 會用現存鄰居重算，不會壞檔。
- metadata 壞掉的卡不參與順序寫入，也不會被整欄補章。
- remote 專案的順序存在 server 端的看板順序文件，不寫進卡片的記錄檔。server 提供 plan 時，卡片同樣帶波次章與依賴檢查；拖排違反宣告依賴時，app 顯示與本地相同的單行錯誤，不送出寫回。

| 情況 | 結果 |
| --- | --- |
| 同欄四張卡的順序鍵分別是 W、X、Y、Z | 顯示 W、X、Y、Z |
| c 依賴 a，但 c 的鍵比 a 小 | 顯示 a、c，依賴修正蓋過鍵的順序 |
| 承上，把 x 拖到 a 與 c 之間 | 整欄先依顯示順序重派鍵，x 的新鍵介於 a 與 c 之間，刷新後顯示 a、x、c |
| c 依賴 a，把 c 拖到 a 之前 | 拒絕：c 的記錄檔不變，畫面顯示單行錯誤，刷新回 a 在 c 前 |
| 承上，但 a 與 c 都沒有順序鍵 | 同樣拒絕，a 與 c 的記錄檔都不變（不會先補鍵） |
| 欄內其他卡都有鍵、而且與顯示順序一致，把沒有鍵的 x 拖到其中兩張之間 | 只寫 x 的記錄檔 |
| 同欄三張卡都沒有鍵：x 被兩張卡依賴、y 有 12 個任務、z 有 5 個任務，y 與 z 沒人依賴 | 顯示 x、z、y |
| a 與 b 只因 delta 重疊而依序，把 b 拖到 a 之前 | 放行 |

**依賴成環時**：看板欄位上方出現一行提示「依賴成環：」加引擎的訊息原文（例如 a -> b -> a）。這時所有卡片沒有波次章、不變淡，欄內順序是 plan 退回的基底順序，拖排照常可用。到某張卡的排程分頁移除一條前置就能解環。

**跨欄拖曳不改階段**：把變更卡拖到另一個階段欄放開，卡片彈回原位，不寫任何檔案。階段只由任務完成度與開工章決定。討論卡只能在討論欄內拖排。按下後位移沒超過拖曳門檻就放開，視為點擊，會開啟詳情頁。

**封存落點**：只有拖曳「已就緒」的變更卡時，看板右緣才浮現封存落點：主色淡底加主色虛線框的浮層，各欄寬度不變。拖近落點時會出現可以放開的提示。拖到落點放開，進入封存確認流程（見[封存](archive.md)）。拖曳提案中、進行中的變更卡或討論卡時，落點不出現，版面完全不動，放開時只照欄內拖排處理。

## 成功不出聲，失敗跳浮層

刪除變更、封存變更、封存討論、拖排卡片、開啟專案、初始化專案這六種操作，成功時不顯示任何文字訊息，結果由畫面自己表達；視窗頂欄也不顯示操作結果。失敗時跳出一則浮層（toast），內容是操作對象加上引擎回報的原始錯誤，不改寫。

| 操作 | 成功時你看到 | 失敗時的浮層 |
| --- | --- | --- |
| 刪除變更 | 卡片消失、詳情頁關閉 | `<變更名稱> · 刪除失敗 ✗ <core 錯誤>` |
| 封存變更 | 卡片消失、「已封存」計數加一、詳情頁關閉 | `<變更名稱> · 封存失敗 ✗ <core 錯誤>` |
| 封存討論 | 卡片消失、詳情頁關閉 | `<討論 slug> · 討論封存失敗 ✗ <core 錯誤>` |
| 拖排卡片 | 卡片在新位置 | `<卡片識別> · 排序寫回失敗 ✗ <core 錯誤>` |
| 開啟專案 | 切換到該專案 | `<選定路徑> · 開啟專案失敗 ✗ <core 錯誤>` |
| 初始化專案 | 進入該專案 | `<選定目錄> · 初始化失敗 ✗ <core 錯誤>` |

- 浮層疊在詳情頁與確認對話框之上，不會被遮住。在詳情頁裡封存失敗時，詳情頁維持開啟。
- 浮層過一段固定時間自動消失，也可以按關閉鈕提早關掉。同時只顯示一則，新的取代舊的並重新計時。
- 浮層用一般卡片的底色與字色，只有錯誤圖示與邊框是紅色；跟著系統的淺色、深色模式切換。
- 失敗後看板刷新回磁碟現況，不會留下沒寫進去的假順序或假狀態。
- 開啟專案失敗時，目前的專案不變。

## 退回提案中、刪除與封存

**退回提案中**：只有「進行中」的變更卡與其詳情頁有這個動作。

1. 點「退回提案中」，先出現確認對話框。
2. 確認後由引擎裁決，app 不預判。
3. 成功時開工章清空、已勾任務為 0，卡片依規則自然回到「提案中」欄，詳情頁的開工資訊跟著消失。
4. 變更已有工作痕跡時，引擎拒絕並開啟守門對話框：列出已勾任務數與 touched 記錄的檔案清單，並說明出路。已勾任務可在任務分頁取消勾選後重試；touched 記錄需要請 agent 判斷。對話框內沒有任何清理或強制退回的按鈕，卡片留在「進行中」。

本地與 remote 專案的行為一致。

**刪除變更**：在詳情頁標題列的「⋯」選單裡，位於選單底部、警示色。只有「提案中」的變更可以刪；其他階段這一項停用，下方灰字說明已有開工痕跡，並指向先退回提案中。刪除走引擎的 discard 全語意，不會直接刪目錄：

- 有開工痕跡（有開工章或任一任務已勾）時，引擎拒絕，`speclink/` 底下的檔案一個位元都不變，app 以失敗浮層呈現。
- 成功時變更目錄消失、touched 記錄清除，並解除來源討論的鏈結：來源討論的已轉出清單移除這個變更名；清單因此變空時，討論狀態回復。
- remote 專案由 server 拒絕已開工變更的刪除，同樣以失敗浮層呈現。

**封存變更**：「⋯」選單的「封存」只在「已就緒」可選；已就緒時標題列另有一顆「封存」主要鈕，兩者同一套守門。其他階段「封存」停用，下方灰字載明任務進度與「完成後才能封存」，標題列也沒有「封存」鈕。remote 專案缺少對應能力時，能力缺失的原因優先於階段原因顯示。可按期間階段在外部被改掉（例如另一個 session 取消勾選一個任務），引擎會拒絕封存，app 以失敗浮層呈現，變更留在看板、詳情頁維持開啟。桌面不提供任何略過守門的強制通道。封存成功時詳情頁關閉、回到看板。封存時若有未結的審查或驗證工單，會先出現三選項對話框，見[桌面上的品質關卡](desktop-quality.md)。

## 變更詳情頁

點變更卡，主區整個換成這個變更的詳情頁。變更與討論詳情頁的「底下那一頁」一律是看板：不論從看板卡片、系統匣、頁內跳轉，或封存確認對話框的「去蓋章」打開，也不論打開時你在規格頁、已封存頁或設定頁，關掉詳情頁後看到的都是看板。

詳情頁開著時，看板還在背後、只是看不到也點不到（Tab 鍵也到不了）。關掉詳情頁後，看板的捲動位置、搜尋字串與篩選都跟打開前一樣，不會重新載入。詳情頁裡的定位捲動（手動任務提示框的「前往」、「下一個未完成」、本頁目錄、D 籤）只捲中間的閱讀區，主區標題列、左欄與閱讀區的邊框都不會跟著位移。

詳情頁是三欄：左欄是文件樹，中間是閱讀卡，寬視窗時右欄是本頁目錄（共通規則見[認識桌面 app](desktop-overview.md)）。

**左欄上方：身分區**

- 變更名（等寬字型，太長會折行）緊跟複製名稱鈕，下面是階段籤（例如「已就緒」）。
- 一行灰字的出身：建立者頭像與名字、產生工具、建立的相對時間、「開工 YYYY-MM-DD」（有開工章時）。這一行永遠單行，放不下就裁切。建立者與開工者的完整識別（含 email）只在指標停留的提示裡出現。
- 出身下面最多三列關聯，各自一行：「來自」列放來源討論籤、「同源」列放同源變更籤、「規格」列放這個變更動到的能力籤。沒有的列整列不出現，不留白。
- 身分區不顯示任務計數，也不顯示審查與驗證章籤。

**來源討論與同源變更**：一個變更可以有多份來源討論，第一份是出身討論。「來自」列固定顯示出身討論，其餘收進「+N」籤；點「+N」彈出浮層，列出其餘來源討論的 slug 與 topic，點任一項開啟該討論的詳情頁。只有一份來源時沒有「+N」。兩個變更的來源討論有交集，就互為同源變更；「同源」列一樣顯示第一顆，其餘收進「+N」浮層，點了開啟該變更的詳情頁。

| 變更 A 的來源 | 變更 B 的來源 | 是否同源 |
| --- | --- | --- |
| d1, d2 | d2 | 是 |
| d1 | d1 | 是 |
| d1, d2 | d3 | 否 |
| （無） | d1 | 否 |

**左欄中段：文件**：每份文件一個節點，依序是提案、設計、任務（徽章 n/m）、規格、排程，有未結工單時再加審查、驗證。點一個節點，閱讀卡就換成那份文件；以下把這些文件叫做「分頁」，例如任務分頁。審查與驗證分頁見[桌面上的品質關卡](desktop-quality.md)。

**左欄下方：狀態**：三列，左邊標籤、右邊內容。

| 列 | 內容 |
| --- | --- |
| 任務進度 | 進度條與 n/m |
| 品質關卡 | 審查章籤、驗證章籤（已蓋章的附蓋章日期）；兩個關卡都沒有痕跡時灰字「尚未經過品質關卡」。細節見[桌面上的品質關卡](desktop-quality.md) |
| 排程 | 有波次時「第 N 波」與前置說明（沒被擋住是「可以開工」，被擋住是「等 N 項」）；沒有波次時顯示排程的說明文字 |

**標題列右端的動作**：在 ‹ n／m › 之後、隔一條細線，由左到右是：

1. 「分析」（外框樣式）。
2. 依階段的主要鈕（實心主色）：進行中是「退回提案中」，已就緒是「封存」，remote 專案可認領時是「認領」（認領見[認識資料：變更、討論與規格](data-layout.md)）。
3. 「⋯」選單：放「封存」與「刪除」，守門見上一節。

動作鈕不折行，也不會把標題列撐寬。左欄與閱讀卡裡沒有這些動作鈕。

**分析**：只有一個「分析」按鈕，同時執行結構驗證與分析；沒有獨立的「驗證」按鈕。結果以一張卡出現在閱讀卡上方，依序呈現：

- **結構驗證列**：通過時顯示單列通過標示；失敗時顯示錯誤數並逐條列出錯誤訊息（與 `speclink validate` 的輸出一致）。
- **維度摘要卡**：覆蓋度、一致性、模糊度、缺漏四張卡，各顯示發現數。零發現顯示「無問題」（成功配色），非零顯示「N 個問題」（警示配色）。
- **發現卡**：逐條列出嚴重度徽章、來源檔、摘要與建議行。

再點「分析」或結果卡的關閉鈕會收合；收合後再點「分析」會重新執行並展開。切換到別的變更時結果清空。

在詳情頁之間切換、麵包屑、返回與快捷鍵見[認識桌面 app](desktop-overview.md)。

## 排程分頁

排程分頁（英文介面為「Plan」）在「規格」之後。清單有波次資訊時，閱讀卡上方先有三樣摘要：

- **籤槽**：與前置卡同一枚狀態徽章，「可以開工」或「等 N 項」。
- **數字磚**：依序是「波次」、「宣告的前置」、「同名需求重疊」、「封存前要等」。
- **提示框**：標題由兩個子句組成，兩邊都是好消息時是提示（tip）樣式，否則是警示（warning）樣式。內文列出前置名、要先封存的變更名與同名衝突的對方，並說明排程會在看板刷新時重算。

| 被擋住 | 封存前要等 | 同名衝突 | 提示框標題 | 樣式 |
| --- | --- | --- | --- | --- |
| 無 | 無 | 無 | 可以開工，也可直接封存 | tip |
| add-a | 無 | 無 | 等 1 項前置，可直接封存 | warning |
| 無 | add-b | 無 | 可以開工，封存前要等 1 個變更 | warning |
| add-a | add-b | 無 | 等 1 項前置，封存前要等 1 個變更 | warning |
| 無 | 無 | add-x | 可以開工，有同名衝突要先改 | warning |

接著依序是四張卡片。卡片有邊框，卡頭是 16px 粗體標題、會列進本頁目錄，卡頭與內容之間有分隔線；重疊卡與封存順序卡的卡頭右端附筆數。分頁沒有獨立的「阻擋」段。

| 卡片 | 內容 |
| --- | --- |
| 波次 | 「第 N 波」，加同一波的其他變更名；沒有其他變更時顯示「本波只有這個變更」 |
| 前置 | 卡頭右側有一枚狀態徽章：沒被擋住時是「可以開工」，被擋住時是「等 N 項」，指標停留列出前置名。內容是宣告的前置變更，一項一列；本地專案每列附移除鈕，底部有下拉選單列出候選變更，選了就寫入。沒有前置時顯示「尚無前置」 |
| 重疊 | 與這個變更動到同名 requirement 的變更，一項一列：對方變更名、「capability › requirement」、雙方各自的操作各一枚小標籤（用詞與配色同規格分頁的 delta 區段，例如修改顯示「修改」；指標停留顯示這個操作屬於哪個變更）。衝突時再加「同名衝突」標籤。沒有時顯示「無重疊」。只動到同一個 capability、沒有同名 requirement 的變更不列 |
| 封存順序 | 這個變更封存要等的變更名，下方一句「先封存它們，再對照正式規格重寫同名 requirement 後封存本變更」。沒有要等、也沒有同名衝突時顯示「可直接封存」 |

封存順序卡在兩種情況下多一句警示：

- 兩個變更互相列在對方要等的清單裡：「與 add-b 互相等待：兩邊都要先等對方封存，須調整拆分」。單向的等待不出現這句。
- 有同名衝突：「與 add-x 同名衝突：先改掉其中一邊，較晚封存的一方才不會被拒」，這時不顯示「可直接封存」。

舊版 server 可能把「動到同一個 capability、配置在前」的變更也算進阻擋清單。這些不是宣告前置的名稱，會在前置卡裡另起一列唯讀顯示「另需等待（server 依重疊判定）：」加名稱，沒有移除鈕，讓徽章的數字對得上卡片內容。本地與新版 server 的阻擋清單只含宣告前置，不會出現這一列。

新增或移除前置都寫回變更狀態檔的前置那一行，成功後看板與分頁一起刷新。引擎拒絕（指向自己、名稱不存在、已封存、會成環）時，分頁以單行錯誤顯示引擎的訊息，畫面不變。新增下拉的候選是這個變更所在名冊裡的其他作用中變更，扣掉已宣告的前置：變更在 worktree 裡時名冊來自它的 worktree 副本，沒有 worktree 時來自主 checkout，與寫入作用的位置相同；名冊還沒查到之前不顯示下拉。remote 專案沒有名冊查詢，候選從作用中變更清單派生；看板刷新後重查名冊失敗時，沿用上一次的候選。

清單沒有波次也沒有前置資訊時（remote 連到沒有 plan 的舊 server、成環或請求失敗），分頁只顯示一句「此模式尚未提供排程資訊」，沒有籤槽、數字磚、提示框與四張卡片。本地依賴成環時，分頁顯示「依賴成環，先移除一條前置才有排程資訊」，只列前置卡：沒有狀態徽章、沒有新增下拉，有前置時每列附移除鈕，沒有前置時照樣顯示「尚無前置」，讓你解環；同樣沒有籤槽、數字磚與提示框。清單有波次、但沒有同名重疊與封存順序的資訊時（舊版 server），重疊卡與封存順序卡顯示各自的空白文字（「無重疊」「可直接封存」）。remote 專案不能改前置時，四張卡片照常顯示，只是沒有移除鈕與下拉選單。

| 情況 | 分頁顯示 |
| --- | --- |

## 任務分頁

### 版面

- **群組卡**：`tasks.md` 的每個二級標題是一張群組卡。卡頭是 16px 粗體的群組標題，文字照來源、不翻譯；標題開頭的「N.」變成等寬的序號籤；右端是這一組的小進度「已完成/總數」。群組標題會列進本頁目錄。第一個二級標題之前的任務，以沒有卡頭的清單呈現。
- **籤槽**：全部勾完時是「全部完成」，否則是「已完成/總數」。
- **數字磚**：依序是「任務」（總數）、「已完成」、「手動」（帶手動標記的任務數，不隨勾選變動）、「群組」（二級標題數）。沒有任何任務時，籤槽與數字磚都不出現。

**每條任務拆成三層**：描述以第一個「驗證：」切開，後面是驗證層；前段再以第一個全形「：」切成標題與內文。切不到「：」時整段是標題；切不到「驗證：」時沒有驗證層。標題後面緊接的「（design D1、D3）」或「(design D1, D3)」會從標題拿掉，裡面的 D 編號變成可點的 D 籤，括號內其餘文字歸到內文第一行。行內程式碼以等寬籤呈現。

| 任務描述 | 標題 | 內文 | 驗證 | D 籤 |
| --- | --- | --- | --- | --- |
| 新增 `a.ts`（design D1）：匯出 x；驗證：npm test | 新增 `a.ts` | 匯出 x； | npm test | D1 |
| 補 i18n 詞條；驗證：i18n 測試全綠 | 補 i18n 詞條； | （無） | i18n 測試全綠 | （無） |
| 對齊匯出 | 對齊匯出 | （無） | （無） | （無） |

點 D 籤會切到設計分頁，展開並捲到那一張決策卡；設計文件沒有那個編號的決策卡時，只切到設計分頁、從頂端開始。

**展開與收合**：標題層（勾選框、序號、標題、D 籤、手動徽章）永遠顯示。有內文或驗證的任務，列尾有一顆箭頭鈕展開或收合；兩者都沒有的任務沒有箭頭鈕。

- 預設依勾選狀態：未勾的展開、已勾的收合。
- 勾選狀態一改變就跟著翻：勾了就收合、取消勾就展開。不論是點列勾選、工具列的「全部已完成」「重置任務」、寫回失敗的回滾，還是外部檔案變更後重新載入，都一樣。
- 你用箭頭鈕手動展開或收合的狀態，會保留到那條任務的勾選狀態下次改變為止；拖曳排序與不影響它勾選狀態的重新載入都不會重設，排序後跟著原任務走。離開任務分頁再回來，則依勾選狀態重新決定。
- 點箭頭鈕不會切換勾選。

### 勾選任務

整條任務列都可以點：點勾選框、編號、文字或空白處，都會切換這條任務的完成狀態並寫回。例外如下：

- 點拖曳把手不切換。
- 在文字上拖選一段後放開不切換，選起來的文字可以複製。直接點勾選框不受這條限制。
- 雙擊選字時，兩下點擊互相抵銷，勾選狀態不變。
- 已封存的變更，以及「全部已完成」等批次操作或拖排還在寫回時，點任務列沒有反應。單一任務的勾選寫回不鎖列，勾了馬上取消也不會遺失。

勾選框本身仍是核取方塊，標籤是「任務 N」，可以用空白鍵切換。工具列下方有一行灰字提示「點整列即可勾選；拖曳把手改順序」；不能拖排（不顯示把手）時只寫「點整列即可勾選」。

勾選之後：

- 畫面立刻反映，不等寫回完成，其餘任務全程可互動。連續快速勾選不會互鎖；勾了馬上取消也不會遺失，兩次寫回依序落盤。
- 寫回失敗時該任務回復原狀，並顯示單行錯誤，檔案不變。
- 在畫面勾任務的效果與 `speclink task done` 相同：任務行打勾、記錄 touched 檔案（有未被先前任務認領的 git 髒檔時才追加）、變更首次有任務完成且尚未開工時蓋開工章。勾第一個任務後卡片會移到「進行中」欄。
- 重複勾選已完成的任務視為成功，不寫檔、不報錯。取消勾選與拖曳排序只改 `tasks.md`，不動開工章與 touched 記錄。
- 寫回在背景執行，視窗不會凍結，也不會閃出主控台視窗。凡是要讀寫檔案或叫用 git 的操作都在背景做；例如切換專案時引擎讀得很慢，主視窗與系統匣仍可操作，資料以載入中呈現。

### 工具列

任務清單頂部的工具列：

| 按鈕 | 效果 |
| --- | --- |
| 「全部已完成」 | 全部任務標為完成，單次寫回。未開工的變更會蓋開工章。全部已完成時按鈕停用。 |
| 「重置任務」 | 全部任務取消勾選，單次寫回。不蓋開工章、不記錄 touched。 |
| 「下一個未完成」 | 第一個未完成任務捲入可視範圍並短暫高亮。按 n 鍵等效。全部完成時停用。 |

目標狀態已達成時重按不改檔。

### 拖曳排序

每個任務列的列首有拖曳把手。

- 只能從把手啟動拖曳。點核取方塊或任務文字不會啟動拖曳。拖曳中按 Esc 只取消拖曳，不會關閉詳情頁。拖曳時浮起的列只畫標題層。
- 放開後一次到位排序並寫回 `tasks.md`。只搬 checkbox 行，群組標題與其他行不動。
- 編號前綴自動重寫：文字以「數字.數字」開頭、且位於帶「數字.」前綴標題的群組下的任務，前綴重寫為「群組編號.組內序」。不符這個樣式的任務文字逐字保留。
- 拖到群組標題上放開：來自標題上方的任務成為該群組的第一個任務；來自標題下方的任務移到標題之前，成為上一群組的末任務。兩個方向都重編號。
- 拖曳過程中被越過的任務讓位時不會穿過群組標題，群組歸屬看得清楚。
- 沒有逐格上下移動的按鈕。

| 拖放前（群組 1） | 把 1.1 甲拖到末位後 |
| --- | --- |
| - [ ] 1.1 甲 | - [x] 1.1 乙 |
| - [x] 1.2 乙 | - [ ] 1.2 丙 |
| - [ ] 1.3 丙 | - [ ] 1.3 甲 |

### 手動任務

以 `[M]` 標記的任務（需要你親手做、agent 無法代行，不限於測試）有兩個訊號：

- 未勾時整列是淡淡的暖黃底。
- 列尾（D 籤之後、展開鈕之前）有一枚「手動」小徽章，手形圖示加文字，字、框與底都是暖黃色。

徽章不插在勾選框、序號與標題之間，也不獨佔一行：手動任務的勾選框、序號、標題與一般任務對齊，長標題換行時各行左緣也不位移。勾完後任務文字劃線、整列淡底退掉，徽章保留且不劃線。暖黃色與看板的「待手動」章、下方的手動任務提示框同色，跟警示用的琥珀色是不同色相。

有未勾的手動任務時，閱讀卡上方有一個暖黃色提示框「N 個手動任務」：N 是未勾的手動任務數，內文只列這些任務的序號與標題，說明要由你親自做完再勾。每一列附「前往」鈕，點了捲到那條任務並短暫高亮；已封存的變更也能用。已勾的手動任務不列；全部勾完或沒有手動任務時，提示框整個消失，不會換成「都完成了」之類的別的提示。提示框隨勾選即時更新。

| 已勾的手動任務 | 提示框標題 | 提示框列出 | 「手動」數字磚 |
| --- | --- | --- | --- |
| 無 | 4 個手動任務 | 4.3、5.8、6.9、7.6 | 4 |
| 4.3 | 3 個手動任務 | 5.8、6.9、7.6 | 4 |
| 4.3、5.8、6.9、7.6 | （提示框消失） | （無） | 4 |

舊檔的 `[P]` 標記只會被剝掉，不產生徽章或淡底。手動任務的規則見[實作：完成任務](apply.md)。

### 任務文字與識別

清單顯示的任務文字不含行尾的穩定 ID 註解，也不含 `[M]`、`[P]` 前綴；寫回時這些原文都保留。勾選以任務的穩定 ID 定址，任務重排後仍命中同一個任務；沒有 ID 的舊檔走序號相容路徑。

### 已封存的變更

任務分頁唯讀：勾選框停用、沒有拖曳把手、沒有工具列，點任務列沒有反應。展開與收合照常，預設一樣依勾選狀態決定。

## worktree 卡片

本地專案在主 checkout 開啟 worktree 政策後（見[平行實作與合回：worktree](worktree.md)），看板會用與 `speclink list` 相同的規則探測 worktree。變更與 worktree 對應的條件是：worktree 的分支名為 `speclink/<變更名>`、主 checkout 有同名且未封存的變更、worktree 內該變更的目錄可讀。三個條件缺一就略過。

對應成立時：

- 卡片帶 worktree 標示（藍色，進行中語意）。變更詳情頁顯示分支名與 worktree 路徑（作業系統原生路徑形式，中性色）。中英介面都直接寫「worktree」。
- 詳情頁各分頁的文件原文、建立與開工資訊、狀態報告、分析報告、看板全文搜尋，全部讀 worktree 副本。同一變更在同一畫面的計數與內容同源，不會出現計數來自 worktree、內容來自主 checkout 的情況。
- 在 worktree 內勾任務，主看板的卡片計數自動更新。
- worktree 移除（合回收尾）後，標示與詳情頁的分支資訊退場。
- git 不可用時看板照常，只是沒有 worktree 標示，不顯示錯誤。

worktree 掛著時的動詞分兩級：

- **被擋下**：「封存」「退回提案中」「刪除」拒絕執行，訊息提示先執行 worktree-merge 收尾。變更目錄與看板狀態不變。
- **寫進 worktree 副本**：任務勾選、全部勾選、任務拖排、卡片拖排、放棄審查工單。檔案效果與側效（touched 記錄、首次完成的開工章）全部落在 worktree 副本，主 checkout 的對應檔案不被寫入。

唯讀呈現不受防護影響。這套防護只作用於桌面動詞；CLI 的對應動詞不在此限。remote 專案不適用 worktree 呈現。

**出處**：`desktop-app`、`board-card-order`、`worktree-overlay`、`manual-task-marker`、`task-identity`
