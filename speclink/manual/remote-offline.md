# 失聯與恢復

遠端專案連不上 server 時，桌面 app 不會退回本地模式，也不會把你離線時的操作存起來之後補送。這一頁說明你會看到什麼、哪些事做不了、以及連線回來後會自動發生什麼。你被移出專案、或帳號被停用時的「沒有存取權限」狀態，也在這一頁。

## 三種連線狀態

每個 server 連線只會處於三種狀態之一，由桌面 app 的執行期單一判定：

| 狀態 | 進入條件 | 你看到的 |
| --- | --- | --- |
| online | 任一請求成功、背景同步收斂成功，或 Server 以低於 500 的狀態碼回應（401 除外） | 一切正常 |
| offline | 請求連續失敗達到門檻，或背景同步在重試等待期間查詢狀態也失敗 | 分頁層級的離線橫幅、雲朵斷線圖示 |
| needs-reauth | server 明確拒絕已撤銷、失效或遭重放的憑證 | 分頁層級的需要重新登入橫幅 |

needs-reauth 優先於 offline 呈現。本地分頁不受任何 remote 連線狀態影響。同一台機器上第二個 server 也不受影響。

哪些失敗算進「連續失敗」：

- 只有兩種算：連不上 Server，以及 Server 以 500 以上的狀態碼回應。單次 500 以上的回應不會轉為離線：下一個請求成功，連線就維持 online。
- Server 以低於 500 的狀態碼回應（例如 403、404、409），表示 Server 還在服務：連續失敗的計數歸零，連線原本是 offline 時回到 online。這個錯誤照常回給發出請求的那個操作。
- 401 不適用上一條。它走換發憑證與需要重新登入的流程。

例如 Server 依序回 503、503、404、503、503：404 讓計數歸零，後面兩次 503 沒有達到門檻，連線維持 online。

進入 offline 時，最後一次失敗若帶有 Server 回報的原因（例如「系統維護中」），離線橫幅的說明含這段原文；沒有原因時，是固定的離線說明。Server 恢復回應後，連線自動回到 online。

> [!TIP]
> Server 用 HTTPS、明明在運作，桌面 app 卻一直顯示連線中斷時，可能是這台電腦不信任 Server 的 HTTPS 憑證。憑證被拒絕時，桌面 app 的呈現和 Server 沒有回應時相同：連線中斷，寫入動作停用。怎麼確認與處理，見 [CLI 連接 remote](cli-remote.md) 的「HTTPS 連線：信不信任 Server 的憑證」一節。

## 離線時：能看、不能寫

offline 或 needs-reauth 期間：

- 已載入的看板與文件內容保留可讀，並標示 stale。查詢失敗不會清空既有內容。
- 全部寫入操作在畫面上停用：任務勾選、動詞、產物寫回、政策儲存、封存。
- 就算繞過畫面直接呼叫寫入命令，也會立即被拒。
- 讀取仍會嘗試。讀取成功就促成回到 online。

> [!NOTE]
> 沒有離線佇列。離線期間的寫入不會排隊、不會暫存、不會延後重放。server 恢復後，server 上不存在離線期間的任何寫入。

### 還沒建立 session 時

app 重啟、或恢復連線後第一次交握還沒成功時，這個分頁還沒有 session。此時桌面 app 呈現「還原中」或錯誤的復原頁，不會顯示上一個工作區的變更與討論，也不會把空清單標成 stale。這條路徑在重試或登入恢復成功後才建立 session。

## 背景的遠端分頁也會亮燈

圖示列上只要有遠端分頁，桌面 app 就會定時檢查它們的 server 連不連得上。你不用先點開這些分頁。

- 檢查的時機：app 還原分頁列之後、主視窗取得焦點時，以及之後每 60 秒。同一個 server 連線有多個遠端分頁時，每個時機只檢查一次。圖示列只有本機專案時，app 不會向任何 server 送出檢查。
- 檢查只向 server 確認你的身分，不讀專案資料，不建立 session，也不交握。結果和其他請求一樣，算進上面「三種連線狀態」的判定。
- 一次檢查失敗、連線還是 online 時，app 在幾秒內重試，直到成功、轉為 offline，或送出的次數達到離線的門檻。所以偶發一次失敗、下一次重試成功時，連線維持 online，不會亮燈。檢查失敗不會彈出訊息。
- Server 有回應但拒絕（例如 403）不算離線：這次檢查只送一個請求，連線維持或回到 online。
- 連線已是 offline 時，每次檢查只送一個請求。連線是 needs-reauth 時，定期檢查不送請求，直到你重新登入。

你看到的：

| 分頁 | 連線狀態 | 圖示列方塊 | 提示 |
| --- | --- | --- | --- |
| 這次啟動後還沒點開過（沒有 session） | offline | 角落琥珀點 | 「離線」，不提最後資料（這種分頁還沒有資料） |
| 還沒點開過 | needs-reauth | 角落琥珀點 | 需要重新登入的狀態文字 |
| 點開過、現在在背景 | offline | 角落琥珀點 | 照舊是「離線，顯示最後資料」 |

- 點開過但在背景的分頁，最遲一個檢查週期（60 秒）加上重試的幾秒內亮燈，你不用切回去看。
- 系統匣面板的專案 tab 與原生選單的專案項顯示同一個狀態：還沒點開過的分頁在兩處的狀態文字都是「離線」，也不提最後資料。系統匣的其他呈現見 [系統匣面板與選單](tray.md)。
- 分頁已在復原狀態（正在連線、連線失敗）時，以復原狀態為準。例如你點開一個遠端專案、交握失敗而進入錯誤復原頁，之後連線轉為 offline，這個方塊維持紅點，不改成琥珀點。
- 連線回到 online 時琥珀點消失，app 不會自動交握，也不建立 session。你點選那個分頁時才開始連線。

例如圖示列有本機專案 A，以及同一台 server 上這次啟動後還沒點過的遠端專案 B、C。Server 停止中，你啟動 app，作用中的是 A。約 3 秒內 B、C 的方塊亮琥珀點，提示是「離線」；A 沒有標示。這段時間 server 只會收到一組（最多 3 個）身分查詢，不是 B、C 各一組。之後 server 恢復、你把主視窗切回前景，一次檢查成功，B、C 的琥珀點消失；你點選 C 時，C 才開始連線。

## server 恢復後：全自動收斂

server 重新可達後，你不用做任何事：

1. 背景同步自動重連。
2. 連線回到 online，桌面 app 發出全部失效的通知。
3. 資料全部重查後，stale 標示消失。
4. 離線期間別人建立的變更會出現在看板上。

同一個連線開了多個 remote 分頁時，恢復過程只會消耗一次已儲存的刷新憑證。其他分頁共用這次換發的結果，各自重試原本的讀取。這樣的本機併發不會被 server 當成憑證重放，不會撤銷憑證，也不會進入 needs-reauth。

## 需要重新登入時：原地復活

server 撤銷了這台裝置的憑證後，連線進入 needs-reauth。重新登入的入口有三處：

- 已有 session 的 remote 分頁上的橫幅；
- 還沒有 session 的 remote 復原頁；
- macOS 的面板與原生系統匣選單。

你明確選擇重新登入時，主視窗顯示並取得焦點，切到應用程式設定的伺服器頁，並聚焦這個連線。登入流程重用既有的裝置登入或存取金鑰路徑。只是顯示 needs-reauth 狀態、或執行不需要登入畫面的重試，不會自動喚起主視窗。

登入成功後，這個連線的全部 remote 分頁自動重新交握、全部重新查詢、重啟背景同步。既有分頁原地恢復，沒有 session 的分頁在原位建立 session。全程分頁不會消失，不會退回本地模式。系統匣同步回到就緒狀態。系統匣的細節見 [系統匣面板與選單](tray.md)。

## 沒有存取權限時

你被移出專案、或帳號被停用時，Server 還在服務，但不再讓你讀這個專案。桌面 app 把這種分頁標為「沒有存取權限」。

### 怎麼判定

- 只看背景輪詢（桌面 app 定時向 Server 查詢這個分頁的同步狀態）。輪詢收到 403 時，這個分頁標為沒有存取權限。讀文件、寫入等其他請求收到 403，不會觸發這個狀態。
- 狀態跟著分頁走，以分頁的 connection、Project 與 Repo 為單位。同一個 connection 上其他 Project 或 Repo 的分頁不受影響，寫入照常可用。
- 狀態由桌面 app 的執行期單一判定，畫面不會自己從查詢失敗推斷。
- 分頁用推送串流接收更新時，Server 會在你失去權限後關閉串流。重新訂閱與接著的輪詢都收到 403，結果與只用輪詢時相同。
- 從 Server 開始拒絕到畫面出現標示，最長一個輪詢間隔（最長 30 秒）。

### 你看到的

三個地方用錯誤的紅色與警示三角形圖示標示：

- **看板上方的橫幅**：與離線橫幅同一個位置。標題是「沒有存取權限」。說明是 Server 回報的原因原文（例如「帳號已停用」），後面接「目前顯示最後成功載入的內容」。橫幅保留 stale 標示，沒有任何按鈕。
- **專案圖示列的狀態點**：錯誤色，螢幕報讀器讀到的名稱含「存取遭拒」。
- **系統匣**：見 [系統匣面板與選單](tray.md)。

標題與提示跟隨介面語言（繁中與英文）。Server 回報的原因照原文顯示，不翻譯。Server 沒有給可讀的原因時，說明改為「目前帳號無法存取這個專案」。

### 能做與不能做

- 已載入的看板與文件內容保留可讀。查詢失敗不會清空它們。
- 全部寫入操作在畫面上停用，並說明原因。例如在任務清單勾選任務時，勾選停用，顯示「目前沒有存取權限」。
- 就算繞過畫面直接呼叫寫入命令，也會立即被拒。寫入不會排隊、暫存或延後重放，Server 收不到它。
- 切換專案、開啟詳情頁、搜尋與複製照常可用。

### 恢復

下一次輪詢成功時全自動復原：橫幅與狀態點消失、寫入操作恢復、看板重新查詢並顯示最新內容。你不用手動重整。

### 和離線、需要重新登入同時發生時

一個分頁同一時間只呈現一種狀態。優先序是：需要重新登入 ＞ 離線 ＞ 沒有存取權限。

| 連線狀態 | 分頁沒有存取權限 | 你看到的 |
| --- | --- | --- |
| online | 否 | 正常，沒有橫幅 |
| online | 是 | 沒有存取權限（紅色橫幅） |
| offline | 是 | 離線（琥珀色橫幅） |
| needs-reauth | 是 | 需要重新登入（琥珀色橫幅與重新登入鈕） |
| offline | 否 | 離線（琥珀色橫幅） |

例如分頁已經沒有存取權限，之後同一個連線因連續失敗進入 offline：分頁改為呈現離線橫幅，不會同時出現兩條。連線回到 online 而分頁仍被拒時，改回呈現沒有存取權限。

反過來，連線離線期間你被移出專案：Server 恢復後對輪詢回 403，連線回到 online、離線橫幅消失，分頁改為呈現沒有存取權限，不會停在離線。

> [!NOTE]
> 這個狀態只在分頁已經有 session 時出現。app 重啟後第一次交握就被拒時，沿用上面「還沒建立 session 時」那一節的復原頁。

## remote 上的破壞性操作

- **封存**：確認對話與本地相同，描述會指出將寫入 server 上的哪個 Project／Repo。確認後寫入 server，取消則無任何變更。offline 期間封存隨寫入遮罩一起停用。
- **刪除變更**：守門與本地的 discard 對齊。未開工即刪；帶開工痕跡的變更由 server 拒絕，並沿既有的刪除失敗路徑回報。

## 一般重啟與完全重置

- **一般重啟**：停止再啟動 server，資料與 remote 分頁都保留，server 不會重印 setup token。
- **完全重置**：以 npx 啟動的 server，刪除它的資料目錄後重新啟動，會重新印出全新的 setup token。在 checkout 內開發的人另有開發者用的重置指令。

重置後的開箱流程見 [開箱：第一位 Admin 與第一組 Project／Repo](server-setup.md)。
