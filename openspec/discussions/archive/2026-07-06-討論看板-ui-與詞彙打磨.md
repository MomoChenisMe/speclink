## Context

desktop-discussion-board（討論看板第二刀）落地後，使用者回饋：討論 UI 的資訊架構不易理解與操作，中文用詞不直觀（例：「促轉」「已促轉」）。模式：assumptions（相關元件 DiscussionColumn/DiscussionDrawer/ArchivedList/App 確認框皆為剛完成的程式碼，context 充分）。相關 change：desktop-discussion-board（14/14 待歸檔）。專案尚無 LANGUAGE.md——本討論的詞彙結論可作為其第一批條目。關鍵事實：「促轉」僅存在於 GUI 文案與 skills 說明，CLI 輸出為英文，改詞零 CLI 相容性影響。

## Rounds

<!-- `### Round N — <mode> (<date>)` entries are appended here by the CLI. -->

### Round 1 — assumptions (2026-07-06)

**Focus**: 現行 UI 哪些詞與結構造成不易理解——盤點與假設
**Position**: 全面盤點 GUI 可見詞彙後提出五項假設：(1)「促轉」為自造縮譯應改白話（候選「轉為變更」）；(2)「歸檔」vs「封存」同概念兩詞為實作不一致，應統一「封存」；(3) 已促轉細列顯示 slug 而非 topic，促轉前後「變臉」是理解斷點；(4) 確認框文案工程味過重（from_discussion、kebab-case 直接暴露給使用者）；(5)「回合」「脈絡」次要可併議。使用者未逐項回應假設，要求以 ASCII UI 呈現整體調整提案——下一輪給設計方向。
**Open**: 使用者具體卡住的操作為何；詞彙最終選字；促轉後兩級呈現（細列）是否保留

### Round 2 — assumptions (2026-07-06)

**Focus**: 整體調整方向——以 ASCII mockup 呈現三畫面（討論欄／抽屜／確認框）供裁決
**Position**: 使用者同意採行。三個設計手段：(1) 生命週期階梯進抽屜頭（討論中→已結論→轉出變更）讓狀態模型可見；(2) 詞彙全面白話化（促轉→轉為變更、已促轉→已轉出變更、再促轉→再轉出一個變更、歸檔→封存統一、N 回合→N 輪、脈絡→背景、促轉分頁→衍生變更）；(3) 已促轉細列改「衍生樹」——顯示 topic（不再變臉為 slug）、子 change 以 ├└ 樹狀列出＋階段，群組標題改「已轉出變更的討論」。抽屜預設分頁改「結論」（有結論時），分頁序：結論／討論過程 N／背景／衍生變更。確認框文案改使用者語言（說會發生什麼，不暴露 from_discussion/kebab-case 等工程詞），名稱輸入說明改「英文小寫，字間用 -」。
**Ruled out**: 促轉後討論完全離板（丟失再轉出入口與衍生視角——第二刀討論已否決過，本輪再確認不採激進版）；細列升回全卡（欄位空間爆炸）；「歸檔」反向統一（封存已是 change 側與封存頁既定詞）。
**Open**: 無——詞彙選字與結構調整均已裁決。

## Conclusion

**Decision**: 討論 UI 詞彙白話化＋資訊架構三調整：全部 GUI 文案改用「轉為變更／已轉出變更／再轉出一個變更／封存（統一）／N 輪／背景／衍生變更」；已促轉細列改衍生樹（topic＋├└ 子 change 樹＋階段標示，群組名「已轉出變更的討論」）；抽屜加生命週期階梯、預設分頁改結論（有結論時）；促轉確認框文案使用者語言化。
**Rationale**: 「促轉」等自造詞與 slug 變臉是理解斷點；動詞直說結果（轉為變更）與看板「變更」頁名呼應；衍生樹表達父子關係優於 pill 標籤堆；生命週期階梯讓狀態模型免腦補。改動僅及 GUI 文案與版面——CLI 輸出為英文，零相容性影響。
**Rejected alternatives**: 促轉後討論完全離板（丟失再轉出入口）；細列升回全卡（欄位空間）；統一為「歸檔」（「封存」已是既定詞）。
**Deferred**: 「已刪除」chip 用詞維持現狀；欄上卡片不加生命週期階梯（避免卡片變重），僅抽屜。
**Capture to**: openspec/LANGUAGE.md（詞彙第一批條目）＋新 change（GUI 文案與版面調整）
