## Context

使用者提出六項桌面需求，並附專案圖示底色設定畫面：1. 設定色票一律顯示選取時深色；2. 原提案為預設未選取底色黑色、自訂色為深色的40%；3. 設定頁點專案進入該專案頁面；4. 公司環境更新頁內容不可見、標準資料下載出現 download failed，希望有 Debug mode 記錄證據；5. 可設定 Proxy；6. 標準資料可全部或單一包匯出。使用者第二次回覆確認第1項，並將第2項修正為選取時深底白字、未選取時淺底黑字，附深紫羅蘭 #9400D3、深板岩藍 #483D8B、蘭花紫 #DA70D6 參考，其餘假設不需修正。公司端失敗原因尚未取得診斷證據，不認定已由 Proxy 造成。
需求已有可驗證目標，不另做需求盤問，以假設清單核對範圍；配色修正後仍需以具體色碼確認呈現。相關正式規格：desktop-app（裝置層專案圖示底色、設定與更新）、desktop-config（設定模式與裝置設定）、security-standard-data（受限 ZIP 匯入與安全標準下載）。目前沒有進行中變更。舊規格要求未選取色混入50%白色及同色系深字，本次改為指定深淺配對與黑字。舊討論搜尋僅命中 web-service-navigation-redesign 的 Server SPA HTTP 資料層裁定，原句為「只設一個前端 HTTP 資料層，統一處理 credentials、JSON 錯誤、登入失效、loading 與 mutation 後更新；不得讓各元件散落 fetch 或再疊一層無行為的 Rust proxy。」此處 proxy 是 API 轉送層，與公司網路 Proxy 設定不是同一問題，不構成否決。
程式證據：apps/desktop/src/views/ProjectSettingsView.tsx 的色票依選取狀態切樣式；packages/ui/src/theme.css 目前混入50%白色；apps/desktop/src/components/projectTile.ts 供主視窗與系統匣共用；apps/desktop/src/App.tsx 專案列入口呼叫 activateTab；crates/host/speclink-host/src/security_data.rs 停用環境 Proxy、使用內建憑證信任來源且將底層網路失敗收斂成 download_failed；apps/desktop/src/adapter/updater.ts 委派 Tauri updater；apps/desktop/src/views/settings/UpdatesPage.tsx 使用內附更新日誌；SecurityDataPage.tsx 目前有匯入而無匯出入口。
Prior discussions: web-service-navigation-redesign

### Round 1 — assumptions (2026-10-19)

**Focus**: 六項桌面需求的初始範圍與依據
**Position**: 將需求分為配色與導覽、診斷與連線、離線資料交換三部分，先以假設核對全部六項。
- 第1項：設定頁所有色票預覽固定深底白字，僅外框標示選項；證據為 ProjectSettingsView.tsx 現在將選取狀態傳給 projectTileClass。
- 第2項初始假設：預設未選取黑底，自訂色未選取為40%原色加60%黑色；這是待使用者核對的解讀，與 desktop-app 現有混白色規格不同。
- 第3項：任一設定頁點專案即進該專案看板，包含同一專案；專案設定有未儲存內容時沿用捨棄確認。證據為 App.tsx 專案列切換入口與 desktop-app 現有離開設定規則。
- 第4項：應用程式設定新增預設關閉的 Debug mode；開啟後記錄畫面錯誤、請求時間／目的地／耗時／HTTP狀態／底層錯誤，可匯出診斷紀錄、遮蔽密碼與金鑰並限制大小。security_data.rs 現在會遺失底層網路失敗原因；更新日誌是內附內容，因此須涵蓋畫面錯誤。
- 第5項：裝置層 Proxy 設定提供沿用系統、手動設定與直接連線，至少涵蓋更新檢查、更新下載、安全標準下載；診斷記錄實際採用方式。security_data.rs 目前停用環境 Proxy，只能視為調查線索；公司憑證或 Proxy 驗證是否必要依診斷證據判斷。
- 第6項：支援離線匯出單一標準的指定版本，以及全部本機已安裝且有效版本；保留原始資料、授權與來源資訊。全部匯出整包亦須能在另一台電腦整批匯入；現有 security-standard-data 僅規定單包匯入。
**Open**: 第1項色票預覽、第2項深淺與40%的定義、第3項點專案導向、第4項Debug紀錄範圍、第5項Proxy範圍與模式、第6項單包與全部離線匯出的範圍，均待使用者核對。

### Round 2 — assumptions (2026-10-19)

**Focus**: 使用者確認範圍並修正未選取配色
**Position**: 第1、3、4、5、6項已由使用者確認，第2項確定改為選取深底白字、未選取淺底黑字，精確配色仍待核對。
- 第1項完全依初始假設：設定色票預覽一律深底白字，未選中的色票也深色，只有外框標示目前選擇。
- 第2項修正初始解讀：紫色選取像深紫羅蘭，未選取像使用者所稱「藍花紫」；附圖標示深紫羅蘭 #9400D3、深板岩藍 #483D8B、蘭花紫 #DA70D6。建議以 #9400D3 搭白字、#DA70D6 搭黑字作為待確認的具體範例，深板岩藍是否只是參考尚未決定，不自行增加第七個色票。
- 其他五項沿用第一輪完整範圍，使用者明示「其餘不需修正」；不在此重開已確認需求。
**Ruled out**: 自訂色未選取為40%原色加60%黑色——使用者明確要淺色表示，初始理解錯誤；未選取沿用同色系深色字——使用者指定黑字；只記錄下載錯誤——更新頁也有畫面問題，需涵蓋畫面錯誤。
**Open**: 第2項：確認紫色的深淺色碼與其餘色票沿用相同深淺原則；「預設未選取黑色」是否被本次淺底黑字規則取代，仍待確認。第1、3、4、5、6項已決定，尚未轉為變更。

### Round 3 — interview (2026-10-19)

**Focus**: 預設色票的未選取狀態是否與淺底黑字原則一致
**Position**: 第2項配色方向已決定，預設色票未選取時採淺灰底黑字，六項需求可收斂為結論。
- 使用者回覆「預設色票 - 同意作法」，採用前次建議的淺灰底黑字，取代原先預設未選取黑底的要求。
- 設定頁所有色票預覽仍固定深底白字，選取外框是唯一選項標示；實際專案圖示則選取深底白字、未選取淺底黑字，主視窗與系統匣一致。
- 紫色具體範例採前次列出的深紫羅蘭 #9400D3 配白字、蘭花紫 #DA70D6 配黑字；其餘既有自訂色採相同深淺原則，精確色值留給提案設計，附圖深板岩藍不另增色票。
**Ruled out**: 預設色票未選取保留黑底——使用者接受淺灰底黑字，統一未選取的視覺語意；以40%暗化公式生成未選取色——無法表達已指定的淺底配色。
**Open**: 六項需求方向皆已決定；其餘色票精確色值、診斷紀錄容量／保留策略、Proxy在各平台的實際接線與整批包格式交由提案設計，公司環境的實際失敗原因仍須取得診斷紀錄後判斷。

## Conclusion

**Decision**: 採用六項桌面改進，統一配色與設定導覽，加入可匯出的診斷紀錄、裝置 Proxy 設定及安全標準離線包匯出。
- 設定頁「專案圖示底色」保留預設及既有六個自訂色票；所有預覽一律深底白字，不隨選項是否被選中而變淺，僅外框標示目前選擇。裝置偏好沿用既有儲存方式，Local／Remote皆可用，不寫團隊設定。
- 實際專案圖示在選取時深底白字、未選取時淺底黑字，主視窗左側專案列與系統匣使用同一套配色。預設色票未選取改淺灰底黑字，取代初始黑底需求；預設色票選取及設定預覽維持深底白字原則。
- 紫色具體範例為選取／設定預覽使用深紫羅蘭 #9400D3 配白字、未選取使用蘭花紫 #DA70D6 配黑字；其餘自訂色遵循同樣的深淺配對原則。附圖深板岩藍 #483D8B 僅作參考，不增加第七個自訂色票。此決定取代原始40%暗化解讀，也取代正式規格未選取混入50%白色並搭同色系深字的固定規則。
- 在應用程式設定或專案設定點左側專案圖示，離開設定並進入該專案看板，包含點擊目前專案；專案設定有未儲存內容時先沿用捨棄確認，取消即保留原頁與修改。
- 在應用程式設定加入預設關閉的 Debug mode；開啟後記錄畫面錯誤及網路請求的時間、目的地、耗時、HTTP狀態、底層錯誤原因與實際採用的Proxy方式，提供診斷紀錄匯出並限制紀錄大小。密碼、存取金鑰等敏感資訊須遮蔽；記錄要能協助區分連線、憑證、回應及畫面問題，不能再只有 download_failed 泛稱。更新日誌目前內附於程式，更新頁內容不可見亦須以畫面診斷涵蓋。
- 增加裝置層 Proxy 設定，提供沿用系統、手動設定及直接連線，至少一致涵蓋更新檢查、更新下載與安全標準下載。現有安全標準下載停用環境Proxy只能視為線索，公司失敗原因需以紀錄驗證；Proxy不替代官方來源、資料完整性與更新簽章的既有檢查。
- 安全標準資料頁提供各標準指定版本的單包匯出，以及全部本機已安裝且有效版本的整包匯出；匯出不連網、不補下載缺少的資料，保留原始資料、授權、署名與來源資訊。另一台電腦可離線匯入單包或一次匯入整批包，維持匯入檢查與失敗保舊語意；匯入資料不因包內自填指紋而被提升為官方可信來源。
**Rationale**: 設定色票要呈現實際深色選項，專案列則以深淺區別是否選取；淺底黑字包含預設色票，視覺語意一致。先保留能重現與定位問題的診斷證據，再以明確Proxy設定處理公司連線需求；離線包匯出讓受限環境仍可取得已驗證可用的標準資料。這些設定與資料屬裝置層，不應污染專案政策。
**Rejected alternatives**:
- 預設未選取黑底及自訂色40%原色加60%黑色 — 使用者最終指定未選取淺底黑字，並確認預設採淺灰底。
- 設定頁未選中色票顯示淺色 — 使用者要求預覽一律深底白字，僅以外框表示目前選擇。
- 未選取沿用同色系深色字 — 使用者明確指定黑字。
- 直接認定公司Proxy是根因或只保留download_failed — 目前沒有公司端診斷證據，且泛稱無法區分底層原因。
- 只記錄下載失敗而忽略畫面錯誤 — 更新頁內附內容也有不可見問題，需能診斷呈現流程。
- 只匯出引用或解析結果 — 另一台電腦離線安裝需要完整原始資料、來源與授權。
**Deferred**:
- 其餘色票與預設深灰／淺灰的精確色碼 — 交由提案設計依既有色系與文字可讀性定值，深淺原則已定。
- 診斷紀錄確切容量、保留期限及檔案配置 — 交由提案設計選最小可用方案，預設關閉、限制大小、遮蔽敏感資訊及可匯出已定。
- 各平台系統Proxy讀取、手動Proxy協定與認證、既有Server連線是否套用及例外範圍 — 交由提案核對現有網路實作後定義，更新與安全標準下載的覆蓋要求已定。
- 公司端實際失敗原因與是否需公司憑證或Proxy驗證支援 — 尚無診斷紀錄，待取證決定，不以關閉憑證驗證處理。
- 整批包容器、相容方式、CLI匯出入口及整批匯入交易邊界 — 交由提案設計延伸既有受限單包格式，單包／全部匯出與離線整批匯入能力已定。
