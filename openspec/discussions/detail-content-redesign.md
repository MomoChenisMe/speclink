## Context

使用者看著變更詳情頁的提案分頁（tray-panel-restyle）截圖，問這一層能不能有視覺上更合適的瀏覽方式；範圍不只提案，還含設計、任務、規格、審查，與討論詳情頁的結論、討論過程、背景、衍生變更。「更合適／漂亮一點」沒有驗收標準，需要 grill 階段先磨利目標。偵察結果：十個面裡七個是「大標籤＋整段 Markdown 散文」（SectionedDoc、DeltaSpecView、RoundsView、ConclusionView），任務／排程／審查三個分頁已是結構化介面；已封存詳情頁與變更／討論詳情頁共用同一批元件；規格詳情頁已有逐條需求分段但變更詳情頁的規格分頁沒有沿用；discuss show --json 只回 content 與 info，輪與結論的結構由前端自行解析 Markdown。文件格式來源分三種強度：schema 模板（提案一種形狀＋propose 技能另兩種、設計、規格 delta 與任務為硬格式）、技能慣例（D1～Dn、輪四欄位、結論六欄位，由 discuss-skill 規格釘住不變）、結構化 JSON（工單、排程）。相關正典規格：desktop-app（五條呈現需求：markdown 內容保留文件結構、討論輪以卡片呈現、討論結論以欄位標籤呈現、規格分頁 delta 區段以色標呈現、提案與設計章節以中文標籤呈現，皆來自兩天前封存的 desktop-detail-page 與 desktop-readonly-detail-pages）、discuss-skill、workflow-schemas、review-station；在途變更 tray-panel-restyle 只改 tray-status-menu，與本題無交集。

### Round 1 — assumptions (2026-10-12)

**Focus**: 現況的痛點是哪一種——掃讀難、找段落難、看不出結構、還是看不出關聯
**Position**: 使用者裁定：Markdown 格式維持現狀，要改的是 UI 的呈現，目標是「漂亮一點」。
- 決策空間：A 目標（痛點）→ B 範圍（十個面；已封存頁與規格詳情頁是否同步）→ C 呈現策略（C1 依固有結構拆區塊、C2 頁內導覽、C3 排版密度、C4 關聯跳轉）→ D 非模板內容的退回規則 → E 落地（刀數、要不要原型）
- C1 底下新增分支：章節白名單寫死在前端（SectionedDoc.tsx）還是從 schema 模板讀——schema 可 fork 自訂，自訂章節名前端認不得就整篇退回
- 現況證據：提案／設計走 SectionedDoc（h2 白名單→中文大標籤＋散文）、規格分頁走 DeltaSpecView（色標標頭＋散文）、背景純 Markdown、結論六欄位標籤＋散文、討論過程每輪一卡四欄位標籤＋散文；任務／排程／審查／驗證已是結構化介面
- 前次討論 desktop-ui-redesign 第 1 輪把範圍定為「換皮、資訊架構不動」，內容呈現只做到標籤化；這次重開那一層，理由是使用者明確要求
**Ruled out**: 改 Markdown 格式或模板來遷就呈現——使用者裁定格式不動，只改 UI
**Open**: 「漂亮一點」的驗收標準；討論記錄要不要納入 schema 模板（使用者提問）；B 的兩個同步面；C 各面的具體畫法；D 退回規則；E 落地方式

### Round 2 — interview (2026-10-12)

**Focus**: 討論記錄要不要納入 schema 模板，以及「漂亮一點」的驗收標準怎麼定
**Position**: 討論記錄不進 schema；驗收標準提案為「每個面與任務／排程／審查三個分頁同一等級」，以原型逐面確認。
- 不進 schema 的理由：schema 的每個 artifact 都有 generates 路徑落在 changes/<name>/，討論在 openspec/discussions/ 無處可放；討論格式已由引擎 scaffold（discuss.rs）與 discuss 技能擁有、discuss-skill 規格釘住不變；開放 fork 自訂只會讓 discuss search 與桌面的輪卡片／結論欄位解析失效
- UI 現在自己解析討論 Markdown（discuss show --json 只回 content 與 info）；格式已凍結所以可行，日後要改的正解是引擎在 --json 多回拆好的 rounds，不是進 schema
- 驗收標準三條：第一屏看得出標籤、項目、細節三層；項目型內容（路徑、能力名、變更名、日期、清單）用介面元件呈現；自由散文照 Markdown 排但只佔它該佔的位置
- 原型：在 desktop-ui-redesign 的既有畫板 https://claude.ai/artifact/1QhDWmQi6muFFQnHTqqHa3 新增兩列九張 816px 內容卡畫板——變更側（提案、設計、任務、規格 delta、審查，資料取自 tray-panel-restyle 與其蓋章前的審查工單快照）、討論側（結論、討論過程、背景、衍生變更，資料取自 desktop-ui-redesign）；共同語言為 13px 小標＋細線分段取代 20px 大標籤、細線列、等寬灰底路徑籤、可點的能力／變更／討論籤、SHALL 等寬灰底、長段落收合標「還有 N 項」；提案加段落目錄列、設計的 D1～Dn 成可收合卡且任務列的 D 籤可跳、規格分頁沿用規格詳情頁的需求段並加修改色條與 REMOVED-SCENARIO 列、任務列拆標題／內文／驗證三層、審查發現拆嚴重度章＋軸向＋路徑＋原文、討論過程改時間軸、結論的分刀成卡並帶變更籤與階段籤、背景的規格與變更名成籤、衍生變更成列表附任務進度與兩站章
- 事實：已封存詳情頁與變更／討論詳情頁共用同一批元件，改了自動跟上；規格詳情頁是獨立元件，規格 delta 分頁反過來沿用它
**Ruled out**: 討論記錄納入 schema 模板——沒有位置、已有主人、可自訂反而破壞引擎與 UI 的解析
**Open**: 驗收標準與原型方向是否成立；原型要檢查的四件事（段落小標的輕重、列與卡的密度、哪些籤要能點、任務列三層是否過頭）；C1 章節白名單寫死前端還是讀 schema 模板；D 非模板內容的退回規則；E 刀數與是否先畫原型再 propose

**Focus**: 使用者要「再豐富一點、像手冊頁那樣」——手冊頁的哪些零件可以搬到變更與討論詳情頁，且不動原始 Markdown
**Position**: 把手冊頁的三欄版面整套搬到詳情頁：左欄文件樹取代分頁列，中欄手冊式閱讀卡，右欄本頁目錄，底部關聯籤與上一份／下一份；九張畫板已改成 1440×1500 的全殼頁面重新發佈。

### Round 4 — interview (2026-10-12)

**Focus**: 手冊式詳情頁底部的「上一份／下一份」是否成立——使用者覺得「份」讀起來像不同份文件
**Position**: 建議整條底部固定列拿掉，關聯籤搬進左欄身分區。
- 字面：「份」暗示同一種東西有多份；提案、設計、任務、規格是同一個變更的不同部分，不是不同份
- 結構：手冊頁的翻頁成立是因為手冊有閱讀順序；變更文件只有產出順序、沒有閱讀順序，使用者多半直接跳任務或規格；討論側預設開結論，更沒有翻頁情境
- 冗餘：左欄文件樹已列出每份文件，底部前後鈕是第二套導覽；底部列剩下的關聯籤在左欄身分區補一列「規格」即可
- 代價：少一條固定列，閱讀卡多約 50px；手冊頁保留自己的底部列（出處與翻頁在那裡有意義），兩種頁面各有理由
**Ruled out**: 改名「上一步／下一步」——產出順序仍不是閱讀順序，任務→規格說不通；閱讀卡結尾放「接著看設計 ›」文字連結——左欄樹兩步內到得了任何一份，多此一舉
**Open**: 使用者是否同意移除底部列；分頁列換成文件樹是否成立；四格數字磚要不要；提示框用在哪些地方才不過頭；C1 章節白名單來源；D 退回規則；E 刀數

**Rationale**: 手冊頁已經證明三欄閱讀頁在這個 app 裡成立，詳情頁照同一套分工（左欄管頁與頁之間、右欄管頁內）讓使用者學一次就通；把文件樹、閱讀卡、目錄做成骨架、把每份文件的畫法做成渲染器，骨架一刀、渲染器兩刀平行，各刀的 spec delta 互不重疊；數字磚與提示框全由現有結構推出，所以 Markdown 格式與 schema 都不必動，agent 的產出流程零影響。
**Rejected alternatives**:
- 改 Markdown 格式或模板來遷就呈現 — 使用者裁定格式不動，只改 UI
- 討論記錄納入 schema 模板 — schema 的 artifact 都落在 changes/<name>/，討論沒有位置；格式已由引擎與技能擁有；開放自訂會讓 discuss search 與桌面解析失效

- 只加右側目錄不加左側樹 — 跨文件跳轉需要跨文件的樹
- 左樹列文件加段落、拿掉右欄 — 與手冊頁分工相反，20 輪塞進左樹會把文件節點推出可視範圍
- 底部「上一份／下一份」 — 「份」讀成不同份文件；變更文件沒有閱讀順序；與左樹重複
- 「開啟 ▾」收進「⋯」 — 變更層與文件層混在一個選單
- 標題列按鈕全部 ghost — 失去依階段主要鈕的提示
- 讀 schema 模板取章節名 — 只覆蓋一種提案形狀，Bug Fix 與 Refactor 形狀在技能檔裡
- 保留整篇退回 — 手寫提案看起來和現在一樣
- 一刀落地 — 約 15 條需求、十幾個元件，兩站審起來太痛
