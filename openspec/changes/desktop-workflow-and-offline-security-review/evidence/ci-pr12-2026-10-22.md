# PR #12 CI 修正（2026-10-22）

## 失敗來源與修正

- 原 CI：[39697922964](https://github.com/mosutw/speclink/actions/runs/39697922964)，提交 `ca5d754d`。三個作業系統皆在 Rust workspace 的 CLI 整合測試失敗。
- `remote_write_path` 的三個封存測試只模擬封存端點，未提供新增的 `GET /config`。正式程式在封存前先讀權威安全政策，因測試伺服器回覆 404 而停止。補齊設定回應，並新增「設定讀取失敗不得送出封存請求」測試；沒有讓正式程式忽略設定錯誤或略過安全驗收。
- `no_raw_wire_json` 檢查發現安全報告流程有三處 `serde_json::Value`。改用共用、拒絕未知欄位的輸入型別區分深度報告與舊報告匯入；送出前沿用 `DeepReport` 驗證，以型別欄位取回遮蔽後的 findings/checks，再轉成協定型別。沒有擴大檢查白名單。
- 同類搜尋：檢視 CLI 的所有封存模擬與安全報告輸入。`remote_verb_parity` 已提供設定端點，維持不變；本次只補齊漏掉的三個測試。既有完整 CLI 測試涵蓋本機深度報告、舊報告匯入及不合法報告拒絕。
- 擴大 workspace 驗證另重現 Host 路徑偏好測試失敗：Windows 的 `canonicalize()` 會增加 `\\?\` 前綴，一般路徑不能直接與它作字串相等比較。三處斷言改為兩邊都由檔案系統解析後比較目錄位置；正式路徑驗證與 UNC 支援未改動。
