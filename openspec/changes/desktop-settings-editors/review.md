- [SUGGESTION] apps/desktop/src/__tests__/helpers/codemirror.ts — Standards: 可能是 Divergent Change（同類東西放在不同地方）／隱性相依。`Range.prototype.getClientRects`／`getBoundingClientRect` 的補丁寫在 helper 模組頂層，靠 import 的副作用生效。但 `apps/desktop/vitest.setup.ts` 已明文把 jsdom 缺的功能集中補在那裡（pointer capture、scrollIntoView、ResizeObserver）。現在哪個測試檔會渲染到編輯器、卻沒 import 這個 helper，就會在掛載時直接拋錯。建議把補丁移到 vitest.setup.ts。
- [SUGGESTION] apps/desktop/src/__tests__/helpers/codemirror.ts — Standards: 可能是 Duplicated Code（重複程式碼）。`typeInEditor` 和 `replaceEditorText` 的 dispatch 結構一樣，只差 `from: view.state.doc.length` 和 `from: 0, to: …`，可以合成一個帶範圍參數的函式。
- [CRITICAL] apps/desktop/src/views/project-settings/parts.tsx — Correctness: `useEditorSave` 掛在視窗上的 ⌘S 只看 `editing`，不看 `wfDisabled`。CodeEditor 的 `Mod-s` keymap 在 readOnly 時也一樣會呼叫 `onSave`。按鈕有 `disabled={ps.wfDisabled || saving}` 擋著，快捷鍵卻能繞過去。觸發路徑：remote 存檔遇到 409 → `handleWriteError` 呼叫 `settings.readSettings()`，remote adapter 因此悄悄改用最新 revision（adapter/workspace.ts 的 `readSettings` 會覆寫 `revision`）→ 衝突面板出現（`conflict !== null` 讓 wfDisabled 變 true）→ 使用者照習慣再按一次 ⌘S → `saveContext`／`saveRules` 帶著新 revision 寫入成功。結果是使用者還沒在面板上做選擇，別人的修改就被蓋掉了。而且 `conflict` 沒被清掉，面板還在；這時若按「重新載入伺服器版本」，畫面會套用已經過期的 `conflict.latest`，顯示內容和檔案實際內容對不上。建議讓 hook 接收 disabled 旗標（或在 `run` 內檢查），並讓 CodeEditor 在 readOnly 時不呼叫 onSave。
- [WARNING] apps/desktop/src/views/project-settings/ContextPage.tsx — Correctness: 存檔進行中編輯器仍然可以輸入：`readOnly={ps.wfDisabled}` 沒有把 `saving` 算進去，RulesPage 也一樣。`saveContext` 寫入的是按下儲存當下的 `draftContext`；成功後執行 `setContextText(舊草稿)`＋`setCtxEditing(false)`，編輯器隨即卸載。按 ⌘S 之後繼續打的字（remote 有網路延遲時很常發生）會被悄悄丟掉。編輯態一關，`dirty` 也跟著歸零，不會出現捨棄提示；下次 `beginCtxEdit` 又會用 contextText 重設草稿。以前沒有快捷鍵，存檔必須用滑鼠點按鈕，這條路徑是這次引入 ⌘S 後才變得常見。建議改成 `readOnly={ps.wfDisabled || saving}`。
- [SUGGESTION] apps/desktop/src/views/project-settings/parts.tsx — Correctness: `busy` 每次掛載各有一份。ProjectSettingsView 只掛當前頁，所以存檔中切到別的設定分頁再切回來時，`ctxEditing` 仍是 true，但新掛載的 hook `busy=false`，可以再送出一次寫入。在 remote 下，第二筆帶的是舊 revision，等第一筆完成後，它會對自己剛寫入的內容報 409。可以把「寫入中」旗標移到 useProjectSettings。
- [SUGGESTION] apps/desktop/src/components/CodeEditor.tsx — Correctness: 外部 `value` 是用 `useEffect` 同步進編輯器的。如果更新優先序不是離散事件（CodeMirror 的 MutationObserver 回呼裡 `window.event` 為空），React 會在 commit 之後才另外排程跑 passive effect。這段空檔若進來新的按鍵，effect 會用舊的 `value` 整份取代文件，下一次 render 再換回來，但游標會被 `Math.min(head, value.length)` 夾回前面，快速打字時會造成字序錯亂。觸發條件較少見；改用 `useLayoutEffect`，或改成和「最後一次 onChange 送出的值」比對，就能消除這個空檔。
