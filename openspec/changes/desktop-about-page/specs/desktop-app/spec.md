## ADDED Requirements

### Requirement: 關於頁

應用程式設定的分類欄 SHALL 於「應用程式」群組之後有群組「關於」，唯一一項「關於 Speclink」；主區麵包屑為「設定 / 關於 Speclink」。macOS 原生選單的「關於 Speclink」SHALL 直接開啟此頁。頁內由上而下 SHALL 為：

- **品牌卡**：橫式鎖版（高 40px，深色主題用深色版）、其下一行灰字「app 版號 · 引擎 引擎版號 · 平台 架構 · 更新狀態籤」（更新狀態籤：已是最新、有新版本、檢查中、無法檢查、尚未檢查）、一句產品描述；SHALL NOT 另放裸標記。
- **版本卡**三列：「檢查更新」（說明含上次檢查的相對時間，從未檢查時說明為尚未檢查；鈕觸發手動檢查，與更新頁共用同一份狀態）、「更新日誌」（開啟瀏覽模式對話框）、「複製版本資訊」（把四行文字寫入剪貼簿——Speclink app 版號、Engine 引擎版號、Platform 平台與架構、Skills 技能檔版本——並短暫顯示已複製）。
- **連結卡**三列整列可點並帶外開圖示：「原始碼」（說明為等寬倉庫網址）、「說明文件」、「回報問題」（開啟新 issue 頁並帶入版本四行）；皆以系統瀏覽器開啟，失敗以失敗 toast 呈現。
- **授權卡**兩列：「授權條款」（說明「MIT License · © 2026 MomoChen」；「檢視」開對話框顯示隨 app 打包的 LICENSE 全文）、「第三方授權」（「檢視」開對話框列出桌面 app 與 CLI 用到的開源套件：npm 與 cargo 兩節，每筆名稱、版本與授權識別字，依名稱排序；清單於建置時由腳本自相依清單產生，缺檔時顯示「清單尚未產生」）。

版本資訊 SHALL 由桌面 core 一次回傳（app 版號、引擎版號為 speclink-core 的版本、平台與架構、技能檔版本為 ASSET_VERSION），前端 SHALL NOT 自行拼湊。頁內文案 SHALL 跟隨 UI 語言。

#### Scenario: 選單關於直達頁

- **WHEN** macOS 使用者點原生選單「Speclink › 關於 Speclink」
- **THEN** 主區為關於頁、麵包屑「設定 / 關於 Speclink」、分類欄「關於 Speclink」為作用中；品牌卡顯示鎖版、版本列與產品描述

#### Scenario: 複製版本資訊

- **WHEN** 使用者於關於頁點「複製版本資訊」的「複製」
- **THEN** 剪貼簿為四行：`Speclink <app 版號>`、`Engine <引擎版號>`、`Platform <平台> <架構>`、`Skills <技能檔版本>`，鈕短暫顯示已複製

#### Scenario: 版本列的更新狀態與上次檢查

- **WHEN** 使用者於關於頁點「檢查更新」且目前已是最新
- **THEN** 品牌卡版本列的狀態籤為「已是最新」、「檢查更新」列說明顯示上次檢查為「剛剛」；切到更新頁，「最新版本」列同步為已是最新

#### Scenario: 連結外開

- **WHEN** 使用者點「回報問題」列
- **THEN** 系統瀏覽器開啟倉庫的新 issue 頁，網址含版本四行；開啟失敗時以失敗 toast 呈現錯誤

#### Scenario: 授權對話框

- **WHEN** 使用者點「授權條款」的「檢視」，關閉後再點「第三方授權」的「檢視」
- **THEN** 第一次對話框顯示 LICENSE 全文；第二次對話框分 npm 與 cargo 兩節列出套件名稱、版本與授權識別字且依名稱排序；清單檔缺席時顯示「清單尚未產生」而非錯誤
