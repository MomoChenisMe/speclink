## Context

desktop-discussion-board 交付的討論 UI 使用自造詞（促轉／已促轉）與 slug 顯示，使用者回饋不易理解與操作。詞彙結論已落 openspec/LANGUAGE.md（轉為變更／已轉出變更／再轉出一個變更／封存／N 輪／背景／衍生變更）。本刀為純前端文案與版面調整：packages/ui 的 DiscussionColumn、DiscussionDrawer 與 apps/desktop 的 App 確認框；不觸碰 crates/ 與資料形狀（DiscussionItem、promoted_to、status 值照舊）。

In scope：GUI 文案替換、細列衍生樹、抽屜階梯與預設分頁、確認框文案。
Out of scope：CLI 輸出、引擎欄位、skills 文件用語、歷史 artifacts 回改、看板卡片上的階梯。

## Decisions

### D1 詞彙替換以 LANGUAGE.md 為單一對照

所有替換以 openspec/LANGUAGE.md 詞條為準：轉為變更（促轉）、已轉出變更（已促轉）、再轉出一個變更（再促轉）、封存（討論卡按鈕的歸檔）、N 輪（N 回合）、背景（脈絡分頁）、衍生變更（促轉分頁）。替換面僅 packages/ui 與 apps/desktop 的使用者可見字串與 aria-label；測試斷言同步改。正典需求標題同步汰換：delta 以 RENAMED 把「討論抽屜檢視與 GUI 促轉」改名「討論抽屜檢視與轉出變更」（引擎於 MODIFIED 套用後執行改名，兩者可同刀）。
替代方案：在元件內建詞彙對照層（i18n 式 key-value）——本刀僅中文單語言、desktop-config-multiproject 已規劃 i18n 範圍，先行抽象是重複投資，否決。

### D2 已轉出細列改衍生樹

PromotedRow 首行顯示 `topic`（粗體，與全卡一致的識別錨點；slug 不再出現於看板）；子變更逐列以樹狀前綴呈現——最後一列 `└`、其餘 `├`，每列為「變更名＋階段標示」；群組標題「已促轉 (N)」改「已轉出變更的討論 (N)」。階段標示沿用 discussionChipStage 派生（提案中／進行中／已就緒／已封存／已刪除），不動派生邏輯。
替代方案：維持 pill 橫排——看不出父子關係（衍生語意），否決；縮排代替樹狀字元——視覺上與換行文字難區分，否決。

### D3 抽屜生命週期階梯與預設分頁

抽屜頭（標題下方）以單行階梯呈現三站：討論中 → 已結論 → 轉出變更；已過站與現站以視覺區分（如 ✓ 與實心點），封存不入階梯（封存後只在已封存頁）。分頁序改為：結論／討論過程 N／背景／衍生變更；`splitDiscussionSections` 切分成功且結論區段非空時預設開「結論」，結論為空時預設開「背景」；切分失敗維持整篇單一檢視退回（分頁名「記錄」）。
替代方案：階梯放看板卡片——卡片變重且欄寬有限，否決（討論結論明定僅抽屜）；預設分頁維持第一個 tab——讀者最想看的是結論，否決。

### D4 確認框文案使用者語言化

轉為變更確認框：標題「轉為變更？」，說明三句話——會在「提案中」新增一張變更卡、提案內容以本討論的結論開頭、討論會移到「已轉出變更」區；名稱輸入 label「變更名稱」、說明「英文小寫，字間用 -」，placeholder 為預填名本身（不再出現 kebab-case 字樣）；主按鈕「轉為變更」。封存討論確認框：標題「封存討論？」、說明「會移到已封存頁的討論節，可隨時唯讀檢視」、主按鈕「封存」。不出現 from_discussion、meta、proposal、kebab-case 等工程詞。
替代方案：文案維持工程精確描述——目標使用者含 PO/PM，工程詞是理解障礙（本刀動機本體），否決。

## Implementation Contract

**行為（使用者可觀察）：**

- 看板討論欄：已結論卡按鈕為「轉為變更」「封存」；欄底群組標題「已轉出變更的討論 (N)」；細列首行為討論 topic，其下子變更以 ├／└ 樹狀逐列列出、每列帶階段標示；slug 不出現在看板任何位置。
- 討論抽屜：標題下方有「討論中 → 已結論 → 轉出變更」階梯且現站可辨；分頁序為 結論／討論過程 N／背景／衍生變更；開啟有結論的討論預設顯示結論內容；衍生變更分頁底部按鈕「再轉出一個變更」（尚未轉出時為「轉為變更」）。
- 確認框：文案如 D4——無任何工程詞；輸入框說明「英文小寫，字間用 -」。
- 卡片與細列上「N 輪」取代「N 回合」。

**介面／資料形狀：** 元件 props 與 SpeclinkDataSource 零變更；DiscussionItem 零變更；僅 JSX 文案、className 與分頁 value 排序調整。

**失敗模式：** 切分失敗的記錄維持整篇退回（分頁「記錄」＋衍生變更）；結論區段為空時預設分頁退回「背景」，不出現空白結論頁。

**驗收條件：** npm test -w packages/ui 與 -w apps/desktop 全綠（斷言新詞彙與新結構：按鈕名、群組名、樹狀前綴、預設分頁、階梯存在）；真實視窗驗證：欄／抽屜／確認框三畫面與 mockup 一致、舊詞（促轉／已促轉／回合／脈絡／歸檔按鈕）不再出現於討論 UI。

**範圍邊界：** 見 Context 的 In/Out scope；crates/ 零 diff 為驗收硬條件。

## Risks / Trade-offs

- [MODIFIED delta 基底尚未進正典] → desktop-discussion-board 須先歸檔（proposal 依賴已載明）；tasks 首項為歸檔前提確認，未歸檔即開工會使 delta 目標缺席。
- [測試斷言大面積改字] → 逐測試檔同步替換並以紅綠確認——先改斷言（紅）再改元件（綠），避免漏改殘留舊詞。
- [樹狀字元在窄欄折行] → 子變更名過長時 truncate（既有 truncate class 沿用），樹狀前綴固定寬度不參與截斷。
