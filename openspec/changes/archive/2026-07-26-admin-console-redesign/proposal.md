## Why

`web-service-navigation-redesign` 讓 Speclink Server 從無樣式 HTML 換成 React SPA，導覽問題解決了，但版面組成仍是「所有東西都是常駐表單」：建立與邀請表單永久佔據列表頁、表格列內嵌下拉與按鈕、不可變的代號與可改的名稱共用同一種輸入框樣式。對透過 AI 代理執行 Remote SDD 的開發者、PO／PM 與自架管理員而言，這讓日常維運（邀請成員、建立專案、撤銷憑證、查稽核）每一步都要在雜訊中找目標。

兩個具體斷點：管理員從側欄進入「帳號」後被丟進一個沒有側欄的殼，只能靠瀏覽器上一頁離開；「資料操作」與「系統狀態」兩頁各印一份 Store 驅動／契約／等級／能力／健康，同一件事有兩份真相。

色票與字型不是問題——`apps/server-web/src/index.css` 與 `apps/desktop/src/index.css` 早已匯入同一份 `packages/ui/src/theme.css`。與 Desktop 不一致的是版面組成與互動模式，所以本變更的重心放在殼、抽屜語彙與資訊架構，不是樣式微調。

改版走查後追加三項（2026-07-25 使用者驗收回饋）：**下拉選單仍是原生 `<select>`**，與 shadcn 其他控件的高度、focus 與展開樣式都對不齊——設計系統只差這一個原語沒補齊；**管理面沒有任何首次上手引導**，自架管理員第一次進來要自己猜六個目的地與抽屜語彙；**Server 面只有硬編中文**，Desktop 早已支援 zh-TW／en，同一個產品兩種語言待遇。

## What Changes

- **殼依角色裁切，不再有第二個 layout**：管理員與一般成員共用同一個殼；管理員開啟 `/account` 時側欄整條保留（無項目高亮），一般成員則不渲染側欄。移除只為帳號頁存在的獨立殼。
- **「帳號」移出側欄**，改由 header 右上的電子郵件連結進入，並與登出按鈕並列——同時解決「header 只有一顆登出、看不出自己是誰」。
- **對齊 Desktop 的三個版面數字**：header 高度、側欄寬度與主內容內距改採 Desktop 殼的值。
- **管理目的地七個併為六個**：合併「資料操作」與「系統狀態」為「系統」，消除 Store 健康的兩份真相。**BREAKING**：`/admin/data` 目的地移除，其內容併入 `/admin/system`。
- **互動模式改為「列表為主體、編輯進抽屜」**：建立、邀請與細節編輯一律以右滑 Sheet 呈現，破壞性動作維持 AlertDialog 確認；表格列不再內嵌任何輸入控制項，整列可點開細節抽屜。
- **不可變欄位視覺分離**：專案與儲存庫代號建立後不可變更，抽屜內以唯讀樣式呈現；更名改為「先按更名、才出現輸入框」，取代常駐輸入框。
- **總覽從裝飾改為可行動**：六張巨型指標卡改為四張可點入對應頁的緊湊卡，下半頁新增「需要處理」（無事項時整塊不出現）、「系統健康」摘要與「最近活動」。
- **列表頁補齊清單能力**：搜尋、狀態篩選、稽核紀錄的動作／來源／時間區間篩選與分頁；憑證頁以分頁（存取金鑰｜裝置）取代兩塊堆疊區段。
- **空狀態不再只印一行「尚無 X。」**，改為圖示、一句說明其用途的文字與主要行動按鈕。
- **使用者可見文案收斂**：移除工程詞（見「相容性影響」），並將新詞條寫入 `openspec/LANGUAGE.md`。
- **下拉選單改用 shadcn/ui 的 Radix Select**：`packages/ui` 新增 `Select` 原語，Desktop 與 Server 兩端一起換掉原生 `NativeSelect`，並統一表單控件高度。**BREAKING（內部）**：`NativeSelect` 自 `@speclink/ui` 移除。
- **首次進入提供分步導覽**：管理員第一次開啟 `/admin` 時以疊層逐一介紹六個目的地與抽屜語彙，可隨時略過；看過後不再自動出現，並保留「重看導覽」入口。
- **Server 管理面支援中文與英文**：沿用 Desktop 的 `I18nProvider` 與 locale 偏好機制（明示偏好優先、未設定跟隨系統），header 提供語言切換。

## Non-Goals

- 不變更任何認證、授權、session、CSRF 或 secret 邊界；admin gate、同源檢查與 audit 來源標記維持現狀。
- 不變更 CLI 子指令、旗標、stdin 契約或 exit code；不變更 bearer API 與 Client Protocol。
- 不在 SPA 內加入 changes、specs 或 discussions 的檢視與編輯（沿用既有範圍限制）。
- 不新增第二套 theme，不新增 Radix dropdown 相依——右上帳號入口以電子郵件連結加登出按鈕呈現，兩個項目不值得引入下拉選單元件。
- 不把殼抽成 `packages/ui` 的共用元件。該層只轉發版面，刪掉它兩端各留自己的殼也不會壞任何行為；版面一致性靠明確數值與既有共用 theme 維持。
- 不修 Desktop 抽屜長標題造成水平捲軸的缺陷——已切為獨立變更。
- 不加入深色模式切換，或任何本次未列出的新管理功能。（語言切換原列為 Non-Goal，2026-07-25 使用者裁定納入本變更。）
- 導覽教學不涵蓋帳號頁與未登入流程——首次上手的痛點在管理面的六個目的地。
- 多語系只做介面文案；`openspec/config.yaml` 的 `locale`（AI artifacts 產出語言）、CLI 輸出與 audit 內的動作字串都不隨介面語言變動。

## Capabilities

### New Capabilities

（無）

### Modified Capabilities

- `server-web-console`: 管理目的地由七個改為六個（資料操作與系統狀態合併為系統）；帳號頁改由同一個依角色裁切的殼承載且管理員側欄不消失；列表頁的建立與編輯改以抽屜承載，表格列不含輸入控制項；不可變代號以唯讀樣式呈現；下拉選單改用 shadcn/ui Select 原語且表單控件高度一致；新增首次進入的分步導覽與介面語言切換（zh-TW／en）。
- `server-admin`: 管理 browser API 的 view model 隨頁面合併與新增內容調整——系統頁改為單一 view model，總覽 view model 增列待辦、系統健康摘要與最近稽核，稽核 view model 增列篩選與分頁參數。

## Impact

### 目標使用者與情境

透過 AI 代理執行 Remote SDD 的開發者、PO／PM 與自架管理員；情境為 Remote workflow 的日常維運——邀請與停權成員、建立專案與儲存庫、發放與撤銷憑證、查閱稽核與確認服務健康。對應 Speclink workflow 的營運面，不影響 propose／apply／archive 等 SDD 動詞。

### 影響的前端套件

- `packages/ui`：新增 `Select` 原語（`@radix-ui/react-select`）並移除 `NativeSelect`；locale 偏好解析（`detectSystemLocale`／`readLocalePreference`／`writeLocalePreference`／`resolveUiLocale`）自 Desktop 提升為共用匯出，Server 面才不必再抄一份。
- `apps/desktop`：僅隨 `Select` 原語替換與 locale helper 匯入位置調整；行為與版面不變。
- `apps/server-web`：新增 `i18n/messages.ts` 訊息目錄、導覽教學元件與語言切換入口。

### 影響的 crate

- `speclink-server`：browser admin API 的 view model 組裝（總覽、系統合併、稽核篩選與分頁）。既有 domain action、audit 來源與權限檢查沿用，不新增動詞。
- `speclink-core`、`speclink-cli`、`speclink-fs`、store crates、`speclink-host`、`speclink-node`：不受影響。

### 相容性影響

- **CLI**：無變更。人眼輸出與 `--json` 皆不動，不影響既有回歸對照。
- **bearer API 與 Client Protocol**：無變更。
- **browser JSON API**：`/admin/data` 與 `/admin/system` 兩個頁面 view model 合併為一個系統 view model；總覽與稽核 view model 增列欄位。此 API 僅供同源 SPA 使用、隨 binary 一同交付，無外部使用者需要遷移。
