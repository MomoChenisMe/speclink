- [WARNING] apps/desktop/src/core/updater.ts — Correctness: 下載中收到 `dismissed` 會回到閒置（`state.phase === "downloading" ? { phase: "idle" }`），但 `downloadAndInstall()` 照樣跑完並安裝，取消只是把畫面藏起來。Tauri 外掛在 Windows 安裝時會結束 app，macOS 會直接換掉 app 檔案。觸發路徑：設定卡下載中按「取消」，之後 Windows 版 app 會突然關閉，macOS 版下次啟動已是新版，等於沒經同意就套用。建議把 adapter 拆成 `download()` 加 `install()` 兩段，取消後就不呼叫 install。
- [WARNING] apps/desktop/src/store.ts — Correctness: 取消後被放棄的那次 `acceptUpdate` 沒有任何守門，晚到的結果仍會落地。觸發路徑：下載中「取消」→「檢查更新」→ 再按「下載」。第一次下載若先完成，它的 `downloaded` 會把第二次提早推到「待重啟」，此時第二次其實還在下載。若第一次失敗，catch 裡的 `pendingUpdate = null` 會清掉新檢查拿到的待更新項，並把第二次下載轉成 error；或在 available 態讓「下載」鈕按了沒反應（`if (!pending) return`）。建議只在 `pendingUpdate === pending` 時才更新狀態或清空。
- [WARNING] apps/desktop/src/components/AssetNoticeDialog.tsx — Correctness: 確認框兩列擺的是兩套不同的版號。第二列 `[t("assets.dialog.appVersion"), appVersion ?? "—"]` 是 app 發版號（tauri.conf 0.8.0），第一列 `projectVersion` 是技能檔標記版號（ASSET_VERSION，目前 v1.44.0）。觸發路徑：任一過期專案開框會看到「專案 v1.40.0／你的 Speclink 0.8.0」，數字看起來專案比較新，跟標題「技能檔是舊版」打架；較新態也看不出要升到哪一版。真正拿來比對的 `prompt.version` 從頭到尾沒顯示。建議第二列改用 `prompt.version`。
- [SUGGESTION] apps/desktop/src/assetPrompt.ts — Correctness: `projectVersion` 取 `probe.tools.find((tool) => tool.workspaceVersion !== null)`，也就是第一個有版號的工具，跟引擎判狀態的順序（newer > missing > stale）無關。各工具版號不一致時（例如後來新加的工具），較新態可能顯示成過期工具的版號。建議照 status 挑對應的工具（`t.newer` 或 `t.stale`）。
