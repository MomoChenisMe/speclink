# 看板與任務

看板是桌面 app 的主畫面，點側欄的「變更」就到這裡。這一頁講看板的欄位、卡片、搜尋、拖曳、卡片上的動作、詳情面板與任務分頁。畫面骨架與回饋規則見[認識桌面 app](desktop-overview.md)。

## 看板的欄位

看板由左到右是「討論」「提案中」「進行中」「已就緒」四欄。變更卡在哪一欄，由變更的狀態推導，優先序如下：

1. 任務全部完成（總數大於 0，完成數等於總數）→「已就緒」。
2. 已蓋開工章，或已有任何任務完成 →「進行中」。
3. 其餘 →「提案中」。

| 開工章 | 任務進度 | 所在欄 |
| --- | --- | --- |
| 無 | 0 任務 | 提案中 |
| 無 | 0/28 | 提案中 |
| 無 | 3/28 | 進行中（詳情面板不顯示開工資訊） |
| 有 | 0/28 | 進行中 |
| 有 | 13/28 | 進行中 |
| 無 | 28/28 | 已就緒 |
| 有 | 28/28 | 已就緒 |

剛提案完的變更（有任務、全未勾、未開工）在「提案中」欄。詳情面板只在變更有開工章時顯示開工者與開工日；沒有開工章、只因任務進度而列在「進行中」的變更，詳情面板不顯示開工資訊。本地與 remote 工作區用同一套規則。每欄欄頭的數字是該欄目前的卡片數。

## 討論欄

討論欄分上下兩區：

- **上區**是討論中的全尺寸卡：狀態為 open 或 concluded 的討論，以及已轉出但尚無結論的討論。open 卡是唯讀的。concluded 卡帶「封存」按鈕。已轉出但尚無結論的卡帶「已轉出・尚無結論」標示，沒有任何按鈕。
- **下區**是欄底的「已轉出 N」收合列，N 是已轉出且已有結論的討論數。預設收合；點一下就地展開細列，再點收合。展開狀態不跨啟動保留。沒有這類討論時收合列不出現。

討論卡以 slug（檔名）為標題，用等寬字型；topic 是卡身描述。複製 slug 鈕緊跟在標題後面，點它把 slug 寫進剪貼簿並短暫顯示已複製，不會開詳情面板。建立者以頭像圓點呈現，指標停留顯示全名。卡底並排「N 輪」與建立時間。討論卡有狀態 chip。改進討論（由改進掃描產生的討論）的卡片帶一枚小章，提示文字是「改進討論」。

已轉出細列以 slug 為首行（帶複製鈕）、topic 為次行，下面用樹狀前綴（├、└）逐列列出轉出的變更與階段 chip：提案中、進行中、已就緒依看板欄配色；已封存為中性色；兩邊清單都找不到的變更標示「已刪除」（紅色加刪除線），討論維持已轉出。

欄頭的計數是上區的卡片數。上區沒有卡片、但有已轉出的討論時，不會顯示「尚無討論」。已封存的討論不在這一欄。

> [!NOTE]
> 桌面 app 不提供新增討論、加輪、寫結論、轉為變更。這些由 CLI 或 agent 執行，見[討論：需求還模糊時](discuss.md)。討論詳情面板的內容見[規格、討論、已封存與搜尋](desktop-browse.md)。

## 變更卡長什麼樣

每張變更卡有三列：

1. **識別列**：變更名稱（等寬字型）、緊跟其後的複製鈕（指標停留才顯現；點它複製名稱，不開詳情面板）、右端的建立者頭像與關係圖示。
2. **描述列**：提案「為什麼」段落的首句，一行截斷。提案缺席或該段為空時，這一列不出現。
3. **meta 列**：進度條與「完成數/總數」。

標題永遠單行。太長時在可用寬度處截斷，以省略號收尾，不折行、不斷字；複製鈕留在同一列。變更卡沒有狀態 chip，因為所在欄就是階段。

卡片上可能出現的標示：

| 標示 | 什麼時候出現 | 指標停留顯示 |
| --- | --- | --- |
| 來自討論 | 變更有來源討論 | 全部來源討論 |
| 「待重新反映」徽章（琥珀色） | 這個變更反映的討論被重新結論，等待再次 ingest | 待重新反映的來源 |
| 「待手動」小章 | 寫碼任務全部完成，但還有未勾的手動任務 | 「待手動·剩 N 項」 |
| worktree 標示（藍色） | 這個變更有活躍的 worktree | 見下方「worktree 卡片」 |
| 審查章、驗證章 | 品質關卡有進度或已蓋章 | 見[桌面上的品質關卡](desktop-quality.md) |
| 「invalid」標記 | 變更的 metadata 檔壞掉 | — |

「待重新反映」與「待手動」都不影響卡片所在的欄。還沒有任何寫碼任務的變更不顯示「待手動」。remote 工作區的卡片不顯示「待手動」。metadata 壞掉的卡照其階段顯示，但對它發起的變更操作會被引擎拒絕。

## 搜尋與篩選

看板欄位上方有一列搜尋工具列。

- 按 Cmd+F（macOS）或 Ctrl+F（其他平台）聚焦搜尋輸入。
- 輸入非空白內容後，看板只顯示命中的卡片，工具列出現清除鈕與即時命中數。點清除鈕清空字串，輸入保持聚焦。
- 各欄欄頭的計數等於過濾後的卡片數。沒有任何命中時各欄為空、計數為 0，不顯示錯誤。

比對有三層，任一層命中就顯示：

1. **欄位子字串**：變更卡比對名稱與摘要，討論卡比對主題與 slug。去頭尾空白、不分大小寫。命中的字會高亮。
2. **名稱模糊比對**：變更名稱與討論 slug 另以字元順序比對（查詢的字元依序出現就命中）。只模糊命中時卡片顯示但不高亮。
3. **全文比對**：查詢也會掃描進行中變更的提案、設計、任務、delta 規格，以及進行中討論的記錄全文。全文命中的卡片會顯示一行摘錄：命中的文件名、前後文與高亮。全文查詢失敗時靜默退回前兩層，不顯示錯誤。

| 輸入 | 效果 |
| --- | --- |
| desktop | 名稱含 desktop 的變更卡顯示並高亮 |
| 桌面 | 摘要含「桌面」的變更卡顯示並高亮 |
| dta | 名稱依序含 d、t、a 的變更卡顯示，不高亮 |
| （清空） | 還原全部卡片 |

篩選收在搜尋輸入右側的篩選開關鈕後面：

- 點開關鈕彈出篩選面板，有三個維度：建立者、建立時間（近 7 天／近 30 天／更早三選一）、來源討論（選定後只顯示該討論卡與來源含它的變更卡）。
- 再點開關鈕、點面板外或按 Esc 關閉面板。關閉不清除已啟用的篩選；開關鈕顯示啟用數。
- 面板內可單獨清除某個維度，也可全部清除。
- 多個維度與搜尋字串以交集過濾。

搜尋字串與篩選不跨啟動保留，也與已封存頁的搜尋各自獨立。過濾中點卡片、拖曳與封存都照常。

## 拖曳卡片

**欄內排序**：把卡片拖到同欄的新位置放開，順序就存進那張卡自己的記錄檔（變更存在變更目錄的 `.openspec.yaml`，討論存在討論記錄的 frontmatter）。

- 一次拖排只改被拖那張卡的檔案，而且只改順序那一行，其他內容逐位元不變。
- 某一欄第一次拖排時，app 先依目前顯示順序替整欄的卡片補上順序，再套用這次移動。只補這一欄。
- 新建的變更或討論（還沒有順序）顯示在欄頂。同欄順序在不同機器上一致。
- 順序不會出現在 CLI 輸出，`speclink list` 的輸出不受影響。
- 寫回失敗（例如檔案不可寫）時，畫面顯示單行錯誤，看板刷新回磁碟上的實際順序。放開前鄰居被封存或刪除，app 會用現存鄰居重算，不會壞檔。
- metadata 壞掉的卡不參與順序寫入，也不會被整欄補章。
- remote 工作區的順序存在 server 端，不寫進卡片的記錄檔。

**跨欄拖曳不改階段**：把變更卡拖到另一個階段欄放開，卡片彈回原位，不寫任何檔案。階段只由任務完成度與開工章決定。討論卡只能在討論欄內拖排。按下後位移沒超過拖曳門檻就放開，視為點擊，會開啟詳情。

**封存落點**：只有拖曳「已就緒」的變更卡時，看板右緣才浮現封存落點。落點是浮層，各欄寬度不變。拖到落點放開，進入封存確認流程（見[封存](archive.md)）。拖曳提案中、進行中的變更卡或討論卡時，落點不出現，放開在欄外只會彈回。

拖排成功時不顯示任何文字訊息，卡片就在新位置。

## 卡片上的動作

**退回提案中**：只有「進行中」的變更卡與其詳情面板有這個動作。

1. 點「退回提案中」，先出現確認對話框。
2. 確認後由引擎裁決，app 不預判。
3. 成功時開工章清空、已勾任務為 0，卡片依規則自然回到「提案中」欄。
4. 變更已有工作痕跡時，引擎拒絕並開啟守門對話框：列出已勾任務數與 touched 記錄的檔案清單，並說明出路。已勾任務可在任務分頁取消勾選後重試；touched 記錄需要請 agent 判斷。對話框內沒有任何清理或強制退回的按鈕。

本地與 remote 工作區的行為一致。

**刪除變更**：詳情面板的刪除鈕只在「提案中」可按。其他階段為停用，提示載明已有開工痕跡並指向先退回提案中。刪除走引擎的 discard 全語意：有開工痕跡（有開工章或任一任務已勾）時被引擎拒絕、檔案零改動；成功時解除來源討論的鏈結並清除 touched 記錄。討論只轉出這一個變更時，討論狀態會回復。remote 工作區由 server 拒絕已開工變更的刪除。

**封存變更**：詳情面板的封存鈕只在「已就緒」可按。其他階段為停用，提示載明任務進度與「完成後才能封存」。remote 工作區缺少對應能力時，能力缺失的原因優先於階段原因顯示。可按期間階段在外部被改掉（例如另一個 session 取消勾選一個任務），引擎會拒絕封存，app 以失敗浮層呈現，變更留在看板。桌面不提供任何略過守門的強制通道。封存時若有未結的審查或驗證工單，會先出現三選項對話框，見[桌面上的品質關卡](desktop-quality.md)。

## 詳情面板

點變更卡開啟詳情面板。標頭由上而下固定四層：

1. **標題列**：變更名與複製名稱鈕。
2. **狀態列**：進度條與完成百分比。有審查或驗證狀態時，同列顯示章籤（審查章在前、驗證章在後）。
3. **出身列**：建立者頭像與名字、產生工具、建立相對時間、開工日期（有開工章時）、「來自」與來源討論籤（有來源討論時）、「同源」與同源變更籤（有同源變更時）。缺席的資訊整段不顯示。
4. **動作列**：分析、封存、刪除，以及進行中變更的「退回提案中」。

標頭不顯示任務計數字樣，任務數由任務分頁徽章與進度條承載。建立者、開工者與蓋章者的完整識別（含 email）收進指標停留提示，標頭可視文字不直出 email 與日期。狀態列與出身列永遠單行，不撐寬詳情面板。來源討論籤以 slug 直出並在過長時截斷，指標停留顯示完整 slug 與 topic；多份來源討論只顯示第一份，其餘收進「+N」籤（見[規格、討論、已封存與搜尋](desktop-browse.md)）。

詳情面板的分頁有提案、設計、任務、規格。提案、設計與規格的呈現方式見[規格、討論、已封存與搜尋](desktop-browse.md)。

**分析**：動作列只有一個「分析」按鈕，同時執行結構驗證與分析；沒有獨立的「驗證」按鈕。結果在詳情面板內的分析面板依序呈現：

- **結構驗證列**：通過時顯示單列通過標示；失敗時顯示錯誤數並逐條列出錯誤訊息（與 `speclink validate` 的輸出一致）。
- **維度摘要卡**：覆蓋度、一致性、模糊度、缺漏四張卡，各顯示發現數。零發現顯示「無問題」（成功配色），非零顯示「N 個問題」（警示配色）。
- **發現卡**：逐條列出嚴重度徽章、來源檔、摘要與建議行。

再點「分析」或面板的關閉鈕會收合面板；收合後再點「分析」會重新執行並展開。切換到別的變更時面板清空。

有活躍 worktree 的變更，詳情面板還會顯示分支名與 worktree 路徑。

## 任務分頁

**勾選任務**：

- 勾選或取消勾選後畫面立刻反映，不等寫回完成。其餘任務全程可互動。連續快速勾選不會互鎖；勾了馬上取消也不會遺失，兩次寫回依序落盤。
- 寫回失敗時該任務回復原狀，並顯示單行錯誤，檔案不變。
- 在畫面勾任務的效果與 `speclink task done` 相同：任務行打勾、記錄 touched 檔案（有未被先前任務認領的 git 髒檔時才追加）、變更首次有任務完成且尚未開工時蓋開工章。勾第一個任務後卡片會移到「進行中」欄。
- 重複勾選已完成的任務視為成功，不寫檔、不報錯。取消勾選與拖曳排序只改 `tasks.md`，不動開工章與 touched 記錄。
- 寫回在背景執行，視窗不會凍結，也不會閃出主控台視窗。

**工具列**（任務清單頂部）：

| 按鈕 | 效果 |
| --- | --- |
| 「全部已完成」 | 全部任務標為完成，單次寫回。未開工的變更會蓋開工章。全部已完成時按鈕停用。 |
| 「重置任務」 | 全部任務取消勾選，單次寫回。不蓋開工章、不記錄 touched。 |
| 「下一個未完成」 | 第一個未完成任務捲入可視範圍並短暫高亮。按 n 鍵等效。全部完成時停用。 |

目標狀態已達成時重按不改檔。

**拖曳排序**：每個任務列的列首有拖曳把手。

- 只能從把手啟動拖曳。點核取方塊或任務文字不會啟動拖曳。
- 放開後一次到位排序並寫回 `tasks.md`。只搬 checkbox 行，群組標題與其他行不動。
- 編號前綴自動重寫：文字以「數字.數字」開頭、且位於帶「數字.」前綴標題的群組下的任務，前綴重寫為「群組編號.組內序」。不符這個樣式的任務文字逐字保留。
- 拖到群組標題上放開：來自標題上方的任務成為該群組的第一個任務；來自標題下方的任務移到標題之前，成為上一群組的末任務。兩個方向都重編號。
- 拖曳過程中被越過的任務讓位時不會穿過群組標題，群組歸屬看得清楚。
- 沒有逐格上下移動的按鈕。

| 拖放前（群組 1） | 把 1.1 甲拖到末位後 |
| --- | --- |
| - [ ] 1.1 甲 | - [x] 1.1 乙 |
| - [x] 1.2 乙 | - [ ] 1.2 丙 |
| - [ ] 1.3 丙 | - [ ] 1.3 甲 |

**手動任務**：以 `[M]` 標記的任務（需要你親手做、agent 無法代行，不限於測試）在描述正上方獨立一行顯示「手動」徽章。徽章左緣與描述左緣切齊，配色取語意色而非灰階。勾完後任務文字劃線，徽章保留不劃線。舊檔的 `[P]` 標記只會被剝掉，不產生徽章。手動任務的規則見[實作：完成任務](apply.md)。

**任務文字與識別**：清單顯示的任務文字不含行尾的穩定 ID 註解，也不含 `[M]`、`[P]` 前綴；寫回時這些原文都保留。勾選以任務的穩定 ID 定址，任務重排後仍命中同一個任務；沒有 ID 的舊檔走序號相容路徑。任務群組標題以粗體、16px 呈現，文字照來源不翻譯。

**已封存的變更**：任務檢視為唯讀。沒有拖曳把手、沒有工具列，核取方塊不可點。

## worktree 卡片

本地工作區在主 checkout 開啟 worktree 政策後（見[平行實作與合回：worktree](worktree.md)），看板會用與 `speclink list` 相同的規則探測 worktree。變更與 worktree 對應的條件是：worktree 的分支名為 `speclink/<變更名>`、主工作區有同名且未封存的變更、worktree 內該變更的目錄可讀。三個條件缺一就略過。

對應成立時：

- 卡片帶 worktree 標示（藍色，進行中語意）。變更詳情面板顯示分支名與 worktree 路徑（作業系統原生路徑形式）。中英介面都直接寫「worktree」。
- 詳情面板各分頁的文件原文、建立與開工資訊、狀態報告、分析報告、看板全文搜尋，全部讀 worktree 副本。同一變更在同一畫面的計數與內容同源，不會出現計數來自 worktree、內容來自主 checkout 的情況。
- 在 worktree 內勾任務，主看板的卡片計數自動更新。
- worktree 移除（合回收尾）後，標示與詳情面板資訊退場。
- git 不可用時看板照常，只是沒有 worktree 標示，不顯示錯誤。

worktree 掛著時的動詞分兩級：

- **被擋下**：「封存」「退回提案中」「刪除」拒絕執行，訊息提示先執行 worktree-merge 收尾。變更目錄與看板狀態不變。
- **寫進 worktree 副本**：任務勾選、全部勾選、任務拖排、卡片拖排、放棄審查工單。檔案效果與側效（touched 記錄、首次完成的開工章）全部落在 worktree 副本，主 checkout 的對應檔案不被寫入。

唯讀呈現不受防護影響。這套防護只作用於桌面動詞；CLI 的對應動詞不在此限。remote 工作區不適用 worktree 呈現。

**出處**：`desktop-app`、`board-card-order`、`worktree-overlay`、`manual-task-marker`、`task-identity`
