# 規格、討論、已封存與搜尋

看板以外，桌面 app 還有幾個閱讀面：規格頁與規格詳情頁、討論詳情頁、已封存頁，以及手冊頁。這一頁講前三者怎麼呈現、怎麼搜尋與換頁，也講變更的提案、設計、規格三份文件在詳情頁裡怎麼畫。詳情頁的共通規則（三欄骨架、麵包屑與返回、‹ › 切換、「開啟 ▾」）見[認識桌面 app](desktop-overview.md)；手冊頁見[桌面 app 的手冊頁](desktop-manual.md)。這些畫面都是唯讀的。

## 規格頁

點專案欄的「規格」進入規格頁。頁標題區是標題「規格」、一句灰字說明與右端的搜尋框，下面是一張列表卡，一列一份正式規格。每列有：

- 規格名稱（等寬），滑過該列時才出現複製名稱鈕。點它把名稱寫進剪貼簿並短暫顯示已複製，不會開啟規格。
- 一行截斷的 Purpose 摘要，取 Purpose 段第一個非空行。Purpose 還是封存流程產生的佔位文字時，改以警示樣式顯示「Purpose 待補」，不顯示佔位原文。
- 右端的需求數、溯源變更數（都是「圖示＋數字」）、最後修改的相對時間（今天／昨天／N 天前；取不到修改時間時這項不出現），列尾是 ›。

這些資訊在清單載入時一次帶出，不會逐列去讀規格全文。

搜尋框以名稱子字串即時過濾，不分大小寫。清空輸入後清單還原。

| 既有規格 | 輸入 | 顯示 |
| --- | --- | --- |
| desktop-app、desktop-config、node-sdk | desktop | desktop-app、desktop-config |
| desktop-app、desktop-config、node-sdk | SDK | node-sdk |
| desktop-app、desktop-config、node-sdk | zzz | 無結果空狀態 |

清單依最後修改時間新到舊排序；取不到修改時間的規格排最後，並依名稱字母序排列。分批瀏覽見下方「換頁」。沒有任何規格的專案與搜尋無結果，各在列表卡內顯示空狀態文案。規格頁不提供任何規格寫入操作。

點一列開啟該規格的**規格詳情頁**，全文在這時才載入。關掉後清單與搜尋字串不變。手冊頁的出處開的也是同一個規格詳情頁。規格頁開著時外部改了某份 spec.md，該列的修改時間會更新，開著的規格詳情頁也會換成新全文。

## 規格詳情頁

規格詳情頁採三欄骨架，宿主頁維持規格頁（或手冊頁），主區標題列沒有任何變更層的動作。

**左欄**：

- **身分區**：capability 名（等寬）緊跟複製名稱鈕、「正式規格」籤、一行出身「N 條需求 · M 個 scenario」與「最近更新 YYYY-MM-DD」（M 是各需求的 Scenario 數加總，最近更新取規格全文最新一次更新）。其下是「溯源」關聯列：第一顆來源變更籤與其餘數「+N」，點了切到溯源文件；沒有任何來源時這一列不出現。
- **「文件」節點**：「規格」（徽章是需求數）與「溯源」（徽章是來源變更去重後的數量），預設開「規格」。
- **「狀態」列**：需求數、溯源數、最近更新的日期與變更名（沒有更新記錄時，最近更新這一列不出現）。

### 「規格」文件

閱讀卡由上而下：

1. **標題區**：標題「規格」、需求數籤，同一列右端是「搜尋需求」輸入與「開啟 ▾」。
2. **出處行**：`<spec.md 路徑> · 正式規格 · 最近更新 YYYY-MM-DD（<變更>）`。路徑是 spec.md 相對所在 checkout 根的實際位置，預設為 `openspec/specs/<capability>/spec.md`；remote 專案沒有本機 checkout 時路徑不出現。
3. **數字磚**：「需求」「Scenario」「溯源變更」，以及以日期為值的「最近更新 · 變更名」。
4. **提示框**，只放推得出的事實：
   - Purpose 段以封存流程的佔位文字「TBD - created by archiving」起頭時，有警告提示框「Purpose 待補」，帶出這份 spec.md 的實際路徑，指引你直接編輯正式規格的 Purpose 段（不走 delta）。
   - 有需求沒有來源變更時，有提示框「N 條需求沒有來源變更」，列出這些需求的標題，並說明溯源文件與「溯源變更」磚不含它們。
   - 兩者都沒有時沒有提示框。
5. **內文**：先是 Purpose（灰底引言段），接著每條需求一段：「Requirement」小標與需求標題，右端是錨點「來自 變更名 · 日期」（該變更在封存清單裡時可點，點了開啟它的已封存詳情頁；需求沒有來源時不出現）；需求文裡的 SHALL、SHALL NOT、MUST、MUST NOT 以等寬灰底標示；每個 Scenario 是左側細線縮排的區塊。第一條需求預設展開，其餘收合成一列（小標、標題、錨點與 Scenario 數籤），點一下切換展開。

以 tray-status-menu（15 條需求、74 個 scenario、9 個來源變更、最近一次由 tray-panel-restyle 在 2026-10-12 更新）為例：

| 位置 | 呈現 |
| --- | --- |
| 出處行 | `openspec/specs/tray-status-menu/spec.md · 正式規格 · 最近更新 2026-10-12（tray-panel-restyle）` |
| 數字磚 | 15「需求」、74「Scenario」、9「溯源變更」、2026-10-12「最近更新 · tray-panel-restyle」 |
| 「狀態」列 | 需求 15、溯源 9、最近更新 2026-10-12 |
| 提示框 | 無 |

**搜尋需求**：以需求標題比對，不分大小寫、子字串命中即算。只留下命中的需求段（Purpose 一直都在），命中的第一段展開；沒有命中時顯示「沒有符合的需求」。字串不會被記住。

**本頁目錄**（視窗寬 1200px 以上）列出 Purpose 與目前呈現的全部需求標題，搜尋後只列命中的段。

需求段以外的內容不會被丟掉：`## Requirements` 下的引言接在 Purpose 之後，最後一條需求之後的其他二級區段（例如附錄）接在全部需求之後，也列入本頁目錄。程式碼區塊裡的行一律當內容，不會被誤認成需求。規格裡完全沒有需求標題時，整篇以一般 Markdown 呈現，沒有數字磚、提示框與本頁目錄，也不報錯。

### 「溯源」文件

閱讀卡是：標題「溯源」與來源變更數籤（沒有「開啟 ▾」）；出處行「自全文的 @trace 註解推導，不是檔案 · 封存清單命中者在前、依封存日期升冪」；數字磚「來源變更」、「最早 · 變更名」與「最近 · 變更名」（值是日期）、「有來源的需求」（例如「13 ／ 15」）。下面一列一個來源變更：

- **在封存清單裡的**：可點，副標是封存日期，依封存日期由早到晚排在前面。點了開啟該變更的已封存詳情頁，規格詳情頁關閉，宿主頁不變。
- **不在封存清單裡的**：不可點，副標「無封存記錄」，排在所有可點列之後，依在全文中第一次出現的順序。

| 全文出現序 | 變更名 | 封存日期 | 呈現位置 |
| --- | --- | --- | --- |
| 1 | drawer-polish | 2026-08-04 | 第 2 列 |
| 2 | spec-archive-drawer | 2026-07-11 | 第 1 列 |
| 3 | desktop-archived-parity | 2026-08-11 | 第 3 列 |

例如你從手冊頁的出處開了規格詳情頁，再點溯源裡的一列：規格詳情頁關閉、已封存詳情頁開啟，宿主仍是手冊頁；按 Esc 回到手冊頁。

規格全文沒有任何來源時：身分區沒有「最近更新」與「溯源」列，「狀態」列沒有最近更新；「規格」文件的出處行與數字磚少了最近更新、各需求沒有錨點，提示框列出全部需求；「溯源」節點徽章為 0，文件沒有數字磚，顯示「此規格沒有來源變更」。

## 變更文件的呈現

變更詳情頁與已封存變更詳情頁的提案、設計、規格三份文件用同一套畫法。任務、排程與工單的畫法見[看板與任務](desktop-board.md)與[桌面上的品質關卡](desktop-quality.md)。渲染不會改任何來源檔案。

章節標題是 16px 粗體（內文 15px），和任務群組卡頭、規格的需求標題、排程卡頭、工單輪卡頭同一款式。

### 提案與設計

文件以二級標題切段，每段帶本頁目錄錨點。已知的模板章節顯示中文標籤與專屬畫法，英文標題不直出；白名單以外的二級標題（例如「Rollout」）照原文當段標題、不翻譯，內文照常排版，整份文件不會因此退回。整份文件沒有任何二級標題時，以一般 Markdown 呈現，不報錯。

| 來源章節 | 呈現標籤 | 畫法 |
| --- | --- | --- |
| Summary | 摘要 | 灰底引言段 |
| Why | 為什麼 | 編號步驟 |
| What Changes | 變更內容 | 編號步驟 |
| Proposed Solution | 解法 | 編號步驟 |
| Non-Goals | 非目標 | 帶禁止圖示的細線列 |
| Alternatives Considered | 曾考慮的替代案 | 方案／落敗理由 |
| Capabilities | 能力 | 能力籤＋說明 |
| Impact | 影響 | 規格列＋三組路徑籤 |
| Context | 背景 | 細線列 |
| Decisions | 決策 | 可收合的決策卡 |
| Implementation Contract | 實作契約 | 鍵值列 |
| Risks / Trade-offs | 風險與取捨 | 每條一個警告提示框 |

其他白名單章節也各有畫法：Motivation、Problem、Root Cause、Success Criteria 的列點成細線列；Goals / Non-Goals 以「**Goals:**」與「**Non-Goals:**」切成左右兩欄；Migration Plan 與 Open Questions 照常排版。章節標題尾的「(optional)」比對前會先去掉。列式章節的標題右端附列點數籤。

「為什麼」「變更內容」與「解法」的頂層列點、編號項，以及連續散文區塊都排成編號步驟，混合時依文件原順序連續編號。這是所有專案共用的預設顯示方式，不依專案名稱或設定；巢狀列點、連結、續行與程式區塊會保留，渲染不會改寫來源文件。

提案的幾個專屬畫法：

- **能力**：New Capabilities 與 Modified Capabilities 之下，每個「能力名: 說明」列點成能力籤加說明；「(none)」顯示「無」。能力在本變更的 delta 規格裡時籤可點，點了切到規格文件並選定該能力（捲到該能力段，「開啟 ▾」也指向它）。這一段之下有一個提示框，每個被修改的能力一行「能力名 有 N 條需求被改寫」，delta 裡有宣告移除的 scenario 時加上「，其中 M 個 scenario 以 REMOVED-SCENARIO 宣告」。
- **影響**：「Affected specs:」成「規格」列；「Affected code:」之下的 New、Modified、Removed 成「新增 N」「修改 N」「移除 N」三組等寬路徑籤（「(none)」顯示「無」）。路徑籤滑過時出現複製鈕；本機專案另有「在 Finder 顯示」鈕，但「移除」組沒有，因為那些檔案在實作後已經不存在。這一段不符這個形狀時，整段當一般細線列。
- **曾考慮的替代案**：每條以第一個「——」切成「方案」與「落敗理由」，切不到時整條當一般列。

設計的幾個專屬畫法：

- **決策**：每個三級標題一張可收合卡，標題開頭的 D 編號成籤，卡頭右端標列點數，預設收合，點卡頭展開。從任務文件的 D 籤跳過來時，該卡展開並捲到卡頭。
- **實作契約**：「- **鍵**：值」形式的列點成鍵值列，切不到時照常排版。
- **風險與取捨**：每條列點一個警告提示框，以第一個「→」切成標題與內文。

**籤槽與數字磚**：

- 提案的籤槽標出模板形狀：有 Problem 與 Root Cause 為「Bug Fix」，有 Summary 與 Motivation 為「Refactor」，有 Why 與 What Changes 為「Feature」，都不是時沒有籤。
- 提案的數字磚依序從「解法步驟」「非目標」「成功準則」「能力」「影響的檔案」「替代方案」中，取章節存在的前四格（章節存在但為零顯示 0）。例如一份 Refactor 提案有六個解法步驟、五條非目標、一個修改的能力、六個受影響的檔案與四條替代方案，數字磚是「解法步驟 6」「非目標 5」「能力 1」「影響的檔案 6」，「替代方案」因為已滿四格不出現。
- 設計的數字磚：「決策」、「目標／非目標」（例如「5 ／ 3」）、「風險與取捨」、「開放問題」（寫「無」算 0），章節缺席時該格不出現。

### 規格（delta）

每個能力一段。能力頭是等寬能力名、delta 計數徽章與「看正式規格」鈕：點了開啟該能力的規格詳情頁；這個能力是本變更新增的（封存前還沒有正式規格）時不出現。能力頭帶本頁目錄錨點。

delta 的區段標題呈現為色標區段標頭，原始英文標題不直出，配色與計數徽章一致：

| 來源區段標題 | 標頭文字 | 色系 |
| --- | --- | --- |
| ADDED Requirements | 新增 | 綠 |
| MODIFIED Requirements | 修改 | 琥珀 |
| REMOVED Requirements | 移除 | 紅 |
| RENAMED Requirements | 更名 | 藍 |

- 「新增」「修改」區段裡的每條需求，用和規格詳情頁同一種需求段呈現，左緣加上該操作顏色的色條。Scenario 裡的 WHEN、THEN（含 AND、GIVEN）列點排成「標籤／內容」兩欄，其他內容（例如範例）接在兩欄之下。
- 需求文超過三段時只展開前三段，其餘收進「展開其餘 N 段需求文」；Scenario 超過三個時只展開前三個，其餘收進「還有 N 個 scenario」。每個區段的第一條需求預設展開，其餘收合成一列（小標、標題、Scenario 數籤；有移除時另帶「移除 N 個 scenario」籤），點一下展開。
- 「修改」區段裡宣告要移除的 scenario，會在該需求的需求文之前以注意提示框「本變更移除 N 個 scenario」列出名稱（刪除線），並說明封存時正式規格的這些 scenario 會被拿掉。宣告用的註解原文不會直出。
- 「移除」「更名」區段的內文照常排版在色標標頭之下。
- 不含 delta 區段標題的規格文件整篇照常渲染。

籤槽是各操作的計數籤（例如「修改 5」，為零的不出現）。數字磚依序是「觸及的能力」「修改的需求」「移除的 scenario」「新增／更名」（例如「1 ／ 0」）。沒有任何 delta 規格時，籤槽與數字磚都不出現。

## 討論詳情頁

點看板討論欄的討論卡或「已轉出」細列，開啟討論詳情頁，宿主頁切回看板。討論欄怎麼分區、卡片長什麼樣子，見[看板與任務](desktop-board.md)。

**左欄身分區**：討論 slug（等寬）為題，緊跟複製 slug 鈕與狀態籤；topic 在下方，最多三行。狀態籤有五種，判準和看板討論卡相同：討論中、已結論、已轉出、已轉出・尚無結論、已轉出・保留中。出身一行是建立者頭像＋名字、「N 輪」與建立日，缺的段不出現。其下的「關聯」列是先前討論數，點了切到背景文件；背景裡先前討論寫 none 時這一列不出現。改進討論另帶「改進討論」標示，一般討論沒有。

**標題列的「封存」**（外框按鈕）：

| 討論狀態 | 「封存」 |
| --- | --- |
| 已結論、未封存 | 可按，走確認流程 |
| 已轉出、保留在途 | 出現但停用，提示說明結論保留在途、最後一刀轉出後自動封存 |
| 討論中、已轉出且未保留、已封存 | 不出現 |

已結論討論的封存在討論卡上也能做，兩處走同一個確認流程。確認後討論移入封存：從討論欄消失、出現在已封存頁的討論節，詳情頁關閉回看板。已轉出、已結論但保留在途的討論，看板上的卡片沒有任何按鈕，收尾由你在 CLI 用 `speclink discuss archive` 明示解除。

**「狀態」列**：

- 「階段」是步驟列「討論中 → 已結論 → 已轉出 → 已封存」，現站可辨識，之前的站打勾。狀態籤是「已轉出・保留中」或「已轉出・尚無結論」時，現站用警示色；其他情況用主色。已轉出但還沒有結論時，「已結論」站是灰圈、沒有勾。
- 保留在途時，多一列「保留在途」說明。
- 有衍生變更時，多一列「衍生變更」：每個變更一顆可點的等寬籤，附階段籤，點了開啟該變更的詳情頁。

**文件**依序為結論、討論過程 N、背景、衍生變更 N。記錄切分成功且結論非空時預設開「結論」，結論為空時預設開「背景」。記錄的區段缺失或格式不符預期時，整份記錄以單一檢視呈現（節點變成「記錄」與「衍生變更」），不報錯。

> [!NOTE]
> 討論詳情頁不提供新增討論、加輪、寫結論、丟棄、轉為變更。這些由 CLI 或 agent 執行，見[討論：需求還模糊時](discuss.md)。

### 結論

行首的 Decision、Rationale、Rejected alternatives、Deferred、Capture to、Next 前綴切成六個區段，標題是 16px 粗體的「決定」「理由」「否決替代案」「擱置」「記錄去向」「下一步」，每個都是本頁目錄錨點。前綴原文不出現；來源沒有的欄位不出現空區段；一個欄位都沒有時，整篇以一般 Markdown 呈現。

- **決定**：第一段是定論句，字級比內文大；其後的列點是定案細節，以細線列呈現，預設只展開前 4 條，其餘收進「展開其餘 N 項定案細節」。區段標題右端顯示細節總數。
- **分刀**：決定裡以粗體開頭、粗體內以 `cut <編號>`、「刀」或「第 N 刀」起頭的列會被抽出，成為決定之後的「分刀」區段，每刀一張卡。卡頭是刀的識別籤、範圍句與該刀的變更數；這一列的其餘文字與巢狀子項接在卡內，不丟內容。粗體內的反引號片段是該刀的變更名籤：已轉出的附階段籤，點了開啟該變更（已封存的開已封存詳情頁）；還沒轉出的是不可點籤。
- **理由**：照 Markdown 呈現。
- **否決替代案、擱置**：每條列點一列（沒有列點時以「；」切），以第一個「——」或「 — 」拆成「方案」與灰字的「落敗理由」兩行，切不到時整條是方案。擱置的每列帶時鐘圖示。兩個區段標題右端顯示列數。
- **記錄去向**：以「、」或逗號切成籤；是正式規格名的籤可點，點了開該規格的規格詳情頁。
- **下一步**：照 Markdown 呈現，後面另列內文中每個 `/speclink-*` 指令的等寬籤，各附複製鈕，點了把指令原文寫進剪貼簿。

刀有沒有轉出，只看粗體內的變更名籤在不在衍生變更清單裡（變更名只寫在粗體之後的刀，反引號裡可能是識別字或檔名，視同沒有變更名）：

| 刀的變更名籤 | 已轉出的 | 判定 | 刀卡 | 列入提示框 |
| --- | --- | --- | --- | --- |
| a、b | a、b | 已轉出 | 一般外框，各附階段籤 | 否 |
| a、b | a | 部分轉出 | 一般外框，b 之後有「尚未轉出」籤 | 否 |
| a | 無 | 整刀未轉出 | 橄欖色虛線外框加淡橄欖底，識別籤之後有「尚未轉出」籤 | 是 |
| 無 | — | 無從判定 | 一般外框，沒有轉出標示 | 否 |

數字磚：「定案細節」「分刀」（標籤附變更數，例如「分刀 · 3 個變更」）「否決的替代方案」「擱置」，欄位缺席時該格不出現。出處行是 `openspec/discussions/<slug>.md · N 輪之後寫入`。

有整刀未轉出的刀時，數字磚下方有橄欖色提示框「N 刀尚未轉出」：每刀一列，有識別籤、範圍句與「前往」鈕（點了把那張刀卡捲到可見處）；末行說明這幾刀還沒有變更，並附一顆可複製的指令籤 `/speclink-propose --from-discussion <slug>`。沒有整刀未轉出的刀時沒有提示框，結論也沒有其他提示框。

### 討論過程

符合工具產生格式（每輪標題形如 `### Round N — <mode> (<date>)`）的記錄，每一輪是時間軸上的一張輪卡，**由新到舊**排列：最新一輪在最上、第 1 輪在最下。這只改呈現，記錄檔裡的順序不變。時間軸每輪一個節點，色點依 mode 區分：assumptions 用主色、interview 用看板討論欄的色相，其他 mode 用中性色。

- **卡頭**：輪次籤（本頁目錄錨點）、焦點（Focus 的第一行，當作這一輪的標題；沒有 Focus 時只有輪次籤）、mode 與日期。
- **卡身**：行首的 Position、Ruled out、Open 呈現為「立場」「否決」「待決」三個欄位，前綴原文不出現；一個欄位涵蓋從標籤行到下一個標籤行的全部內容。
  - 立場：第一段是定論句（中等字重），其後的列點成細線列。
  - 否決：每條一列（沒有列點時以「；」切），每列帶「×」圖示。
  - 待決：以「無」或 none 起頭時，呈現為一行帶勾選圖示的灰字原文；否則每條一顆琥珀色籤。
  - 來源沒有的欄位不出現空欄位。
- 第一輪與最後一輪（最下與最上兩張）預設展開，其餘收合成卡頭一列，點卡頭切換展開。
- 任一輪的標題不符格式時，整篇以一般 Markdown 呈現，沒有時間軸、數字磚與提示框，不報錯。

數字磚：「輪」（輪數）、「天」（不同日期數），其後依首次出現的順序每個 mode 一格，最多四格。出處行是日期範圍與各 mode 的輪數。結論已經寫入時，有提示框「討論已收斂」，內文是「第 N 輪之後寫入結論」，再接最後一輪的待決狀態（「最後一輪待決：無」或「最後一輪仍列 M 項待決」）。

| 一份 20 輪的討論 | 呈現 |
| --- | --- |
| 數字磚 | 20「輪」、1「天」、10「assumptions」、10「interview」 |
| 出處行 | 2026-10-08 · assumptions 10 輪 · interview 10 輪 |
| 提示框 | 「討論已收斂」：第 20 輪之後寫入結論、最後一輪待決：無 |

### 背景

背景內文收尾的 `Related specs:`、`Related changes:`、`Prior discussions:`、`Source doc:` 四行會從內文剝離，其餘分三段（各是本頁目錄錨點）：

- **起因與範圍**：第一段散文是灰底引言，其餘照 Markdown。內文裡與正式規格名、作用中變更名、已封存變更名、其他討論 slug 完全相同的字詞（前後不接英數、連字號或底線；反引號裡的不算）自動變成可點籤，分別開啟該規格的規格詳情頁、該變更的詳情頁、該封存變更的已封存詳情頁、該討論的詳情頁。
- **關聯**：「正式規格」「在途變更」「已封存變更」「先前討論」「來源文件」五列，值是收尾四行解析出的名稱與內文命中名稱合併後的籤。值為空的列不出現；來源文件寫 none 時顯示「無」。全部都空時整段不出現。
- **記錄**：「建立」（建立日與建立者名字）、「種類」（「改進討論」或「一般討論」）、「檔案」（`openspec/discussions/<slug>.md`，附複製鈕；已封存討論沒有這一列）。

數字磚：「命中的正式規格」「在途變更」「相關已封存變更」（為 0 時不出現）與「先前討論」（收尾沒有這一行時不出現，寫 none 算 0）。出處行是「記錄建立時寫入一次」與建立日。第一輪的 mode 是 assumptions 時，有提示框「沒有 grill 階段」。

### 衍生變更

列出這份討論轉出的每個變更的現況，唯讀，沒有「轉為變更」或「再轉出一個變更」按鈕。結論解析得出分刀時依刀分組：組頭是刀的識別籤、範圍句與該組變更數（列入本頁目錄），不屬於任何刀的變更接在最後；解析不出時依轉出順序平面列出。每一列：

| 子變更所在 | 階段籤 | 任務 | 審查章、驗證章 | 日期 | 開啟鈕 |
| --- | --- | --- | --- | --- | --- |
| 作用中（已就緒、已審查、已驗證） | 已就緒 | 完成數／總數 | 兩章都有 | 最近蓋章日 | 開啟變更詳情頁 |
| 作用中（進行中、審查中） | 進行中 | 完成數／總數 | 無 | 不出現 | 開啟變更詳情頁 |
| 已封存（結局為已審查、已驗證） | 已封存 | 完成數／總數 | 兩章都有 | 封存日期 | 開啟已封存詳情頁 |
| 已封存（結局為曾審查未通過） | 已封存 | 完成數／總數 | 沒有審查章 | 封存日期 | 開啟已封存詳情頁 |
| 兩者皆無 | 已刪除（刪除線） | 不出現 | 無 | 不出現 | 無 |

數字磚：「變更」（總數）、「已封存」、「作用中」、「任務」（有任務資料的列加總 n/m）。出處行是「依結論的分刀分組」或「依轉出順序」。討論已轉出、沒有保留在途、且只剩一個作用中的子變更時，有提示框「只差最後一刀」，點名該變更與它的階段，並說明它封存後討論會自動隨之封存。沒有衍生變更時顯示空狀態文案、沒有數字磚。

## 來源討論與同源變更

由討論轉出的變更，卡片帶一枚討論徽章。變更連結多份討論時，徽章仍只有一枚，代表清單第一份（出身）討論；指標停留時列出全部來源討論。

在變更詳情頁左欄身分區的「來自」列：

- 固定顯示第一份來源討論的籤，其餘收進「+N」籤（N 是沒有直接顯示的數量）。只有一份來源討論時沒有「+N」籤。
- 點「+N」開啟浮層，列出其餘來源討論的 slug 與 topic。點任一項開啟該討論的詳情頁。
- 籤以 slug 直出（等寬），topic 不直出。slug 超過寬度上限時截斷，指標停留顯示完整 slug 與 topic。多份來源討論不會各自換行，標記也不會撐寬左欄。

**同源變更**：兩個變更的來源討論有交集，就互為同源。「同源」列也是顯示第一顆、其餘收進「+N」浮層，點浮層項開啟該變更的詳情頁。

| 變更 A 的來源 | 變更 B 的來源 | 是否同源 |
| --- | --- | --- |
| d1, d2 | d2 | 是 |
| d1 | d1 | 是 |
| d1, d2 | d3 | 否 |
| （無） | d1 | 否 |

已封存變更詳情頁的來源討論標記適用同樣的寬度與「+N」規則。

## 已封存頁

點專案欄的「已封存」進入已封存頁。頁標題區是標題「已封存」、一句灰字說明與右端的搜尋框；下面一張列表卡，頂部是「變更」「討論」兩個分頁，預設「變更」，作用中的分頁有主色底線。每個分頁標籤帶一枚徽章，顯示該節目前（搜尋過濾後）的筆數。

**搜尋**同時過濾兩節：你在其中一節時，另一節的徽章反映它的命中數。例如在「變更」輸入一個只命中 3 筆封存討論的字串，「變更」徽章顯示 0、清單顯示無結果空狀態，「討論」徽章顯示 3，切過去就看到那 3 筆。

**列**：

- **封存變更列**：最左是封存日期，接著是變更名（緊跟複製鈕，複製的是含日期前綴的封存目錄名）、任務數徽章（未全完成以警示樣式呈現，與全完成一眼可分；沒有 `tasks.md` 時不顯示）、觸及規格數、建立者標記（指標停留顯示全名）、來源討論標記（沒有來源討論時不出現）。名稱下方一行截斷顯示提案「為什麼」的首句；取不到時整列退回單行。
- **封存討論列**：slug 為題（等寬，緊跟複製 slug 鈕），topic 在下方一行截斷，並顯示日期、輪數與衍生變更數。改進討論帶「改進討論」小章，與看板一致。
- 計數一律是「圖示＋數字」，任務數徽章例外。整列可點、細線分隔、滑過微灰、右端是 ›。這些資訊由清單一次帶出，不逐列讀全文。

**排序**：封存變更依封存日期新到舊（同日依封存目錄名降冪）；封存討論依建立日期新到舊（同日依 slug 升冪）。

隨最後一個子變更封存而自動封存的討論，和你用桌面或 CLI 手動封存的討論，一樣出現在討論節。資料來源沒有討論清單時（較舊的資料來源），分頁列不出現，只顯示變更清單。

已封存的變更在詳情頁的「狀態」列帶審查與驗證的結局，見[桌面上的品質關卡](desktop-quality.md)。

### 已封存變更詳情頁

點一列開啟唯讀的已封存詳情頁，宿主維持已封存頁；清單沒有行內展開。

- **身分區**：變更名（等寬）緊跟複製鈕（複製含日期前綴的封存目錄名，複製後短暫顯示已複製）與「已封存」籤；審查與驗證的結局不放在身分區。出身一行依序是建立者（首字母圓標＋名字，完整識別在提示裡）、建立日期、「封存 YYYY-MM-DD」，單行、溢出裁切，缺的欄位不出現、其餘照常。有來源討論時，下面多一列「來自」，點了開啟該討論的已封存詳情頁（記錄優先讀進行中的版本，讀不到再讀封存版本）。
- **「狀態」列**三列：任務 n/m（沒有 `tasks.md` 時「—」）、品質關卡結局（都沒有時「未經品質關卡」）、封存日期。
- **文件**至少有提案、設計、任務、規格，內容來自封存目錄裡的實體文件；「開啟 ▾」對應 `openspec/changes/archive/<封存目錄名>/` 底下的檔案。任務的勾選框不可點，沒有拖曳把手、沒有批次工具列，整列也不回應點擊。文件不存在時（例如沒有 `design.md`）閱讀卡顯示空狀態，不報錯，其他文件照常可用。
- 沒有進度條，標題列沒有任何動作，右端只有 ‹ n／m ›——封存是唯讀定格。開著時內容會隨外部檔案變更反映。

### 已封存討論詳情頁

- **身分區**：slug 為題（等寬）緊跟複製 slug 鈕與「已封存」籤（改進討論另帶改進籤），topic 在下方最多三行。出身是建立者、建立日期與「封存 YYYY-MM-DD」，缺的欄位不出現；清單資料沒帶封存日期時，「封存」這一欄不出現。
- **「狀態」列**的階段步驟列與討論詳情頁相同，現站是「已封存」。有衍生變更時多一列「衍生變更」，順序依轉出順序，每顆籤依子變更現在在哪裡分三種樣子（見下表）。沒有衍生變更時這一列不出現；已封存變更詳情頁永遠沒有這一列。
- **文件**是結論、討論過程、背景、衍生變更，畫法與討論詳情頁相同，但結論沒有「N 刀尚未轉出」提示框（刀卡的轉出標示照常）、衍生變更沒有「只差最後一刀」提示框、背景沒有「檔案」列、各文件的出處行不帶記錄路徑。
- **「開啟 ▾」**只有「複製內容」，複製的是該記錄的原文。
- 沒有轉為變更、封存或任何寫入按鈕。

| 子變更所在 | 副標 | 可點 | 點了之後 |
| --- | --- | --- | --- |
| 已封存清單 | 封存日期（例如 2026-09-02） | 是 | 開啟該封存變更的已封存詳情頁，宿主維持已封存頁 |
| 進行中的變更清單 | 看板階段詞（例如「進行中」） | 是 | 開啟該變更的詳情頁，宿主切回看板 |
| 兩者皆無（例如已刪除） | 無封存記錄 | 否 | 無 |

### 本地快取

已封存變更的清單資料有一份本地快取，用來加快呈現。這份快取是衍生資料：刪掉或版本不符時會自動從封存目錄重建，與檔案不一致時以檔案為準。進行中的變更與規格清單不用這份快取，一律即時讀檔。

## 換頁

規格頁與已封存頁的兩節清單分批瀏覽，每頁預設 20 筆。

- 頁面填滿主區高度，頁面本身不縱向捲動：頁標題區與搜尋框固定在頂部（已封存頁的分頁列在列表卡頂部），列在列表卡內捲動。
- 清單非空時，列表卡底部常駐一條換頁工具列，不會隨列捲出視窗。左邊是「第 a–b 筆，共 N 筆」與每頁筆數下拉（20／50／100，預設 20）。
- 過濾後筆數超過每頁筆數時，右邊依序是第一頁鈕、上一頁鈕、頁碼鈕（目前頁為主色淡底；總頁數超過 7 時，固定列出首尾頁與目前頁的前後各一頁，其餘以省略號收攏）、下一頁鈕、最後一頁鈕，以及「跳到 __ 頁」輸入：按 Enter 跳頁，超出範圍時停在第 1 頁或末頁，非數字不理會。在第 1 頁時第一頁鈕與上一頁鈕不可用，在末頁時下一頁鈕與最後一頁鈕不可用。筆數沒有超過時，右邊整段不出現。
- 改每頁筆數會重算總頁數，目前頁碼超出時停在末頁。
- app 會記住每頁筆數，下次啟動照用：規格頁、已封存「變更」節與「討論」節各記各的，只存在 app 本機、不寫進任何專案目錄。記住的值不見了、壞掉或不是 20／50／100 時退回 20；本機儲存不可用時只是記不住，不顯示錯誤。頁碼與搜尋字串不跨啟動保留。
- 改搜尋字串會回到第 1 頁；換頁後列表捲回頂部；清單縮短使目前頁碼越界時，停在末頁而不是顯示空頁。
- 已封存頁兩節的換頁工具列與頁碼各自獨立。
