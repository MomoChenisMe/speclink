# 提交單一變更的檔案

工作樹裡常常混著好幾個變更的改動。`/speclink-commit` 只挑某一個變更的檔案做一次 git 提交，不會把無關的檔案順手掃進去。它是隨叫隨用的工具技能，不是每個變更必經的一站。

> [!NOTE]
> 技能怎麼判斷哪些檔案屬於這個變更，規格未載。本頁只寫規格有寫的部分：確認閘門的規則。

## 所見即所簽

技能守一條原則：你看到的清單，就是最後簽下去的那一份。流程如下。

1. 技能先生成 commit 訊息。
2. 技能把 commit 計畫（分組後的檔案清單）與 commit 訊息，以可見文字一次輸出在對話裡。
3. 技能才向你提出確認問題。問題只會指涉上面已經輸出過的內容，不會提到你沒看過的東西。
4. 你確認後，技能才暫存並提交。

沒有互動確認工具的環境，技能以純文字提出同樣的問題並等你回覆；一樣是先輸出計畫與訊息，再問。

## 先封存再一起提交

確認時有一個選項是「Archive first, then commit together」。選了它，技能先跑封存子流程。封存完成後，技能重新輸出更新後的 commit 計畫，以及含「Archived: yes」的 commit 訊息，再問你一次確認。第二次確認通過，才真正暫存與提交。封存本身的規則見 [封存](archive.md)。
