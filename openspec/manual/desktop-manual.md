# 桌面 app 的手冊頁

點側欄的「手冊」進入手冊頁。它讀的是專案 `openspec/manual/` 底下的手冊頁（也就是你現在讀的這些檔案），把它們排成側欄、提供搜尋與上一頁／下一頁，並標出可能過期的頁。手冊頁是唯讀的，沒有任何寫入操作。手冊怎麼生成、頁的格式怎麼定，見[操作手冊：生成與導覽](manual.md)。

## 側欄與閱讀序

手冊頁讀取每一頁的 frontmatter，用兩層排序決定閱讀序：

1. 分區依分區內最小的 order 排列。
2. 分區內的頁依 order 升冪；同值時以檔名決定。

側欄的分區就是閱讀序中連續同一 section 的頁，同一分區的頁永遠相鄰。每一列顯示該頁的 title。上一頁／下一頁是閱讀序裡的相鄰頁：第一頁沒有上一頁，最後一頁沒有下一頁。

| 頁（檔名） | order | section | 側欄位置 | 上一頁 | 下一頁 |
| --- | --- | --- | --- | --- | --- |
| index | 10 | 開始使用 | 分區 1 第 1 列 | 無 | first-login |
| first-login | 20 | 開始使用 | 分區 1 第 2 列 | index | editor |
| editor | 30 | 文件協作 | 分區 2 第 1 列 | first-login | about |
| about | 40 | 附錄 | 分區 3 第 1 列 | editor | 無 |

frontmatter 有缺漏的頁會寬容降級，不報錯：

| 情況 | 呈現 |
| --- | --- |
| 缺 title | 以檔名（去副檔名）為標題 |
| 缺 section | 歸入「其他」分區 |
| 缺 order，或 order 不是整數 | 放在所屬分區的最後 |
| frontmatter 整個解析不了（不以 `---` 開頭、YAML 壞掉） | 仍列在側欄、以檔名為標題、可開啟顯示全文。其他頁的順序與內容不受影響 |

## 搜尋

手冊頁有搜尋列。輸入時即時比對各頁的 title 與 keywords，不分大小寫、子字串命中即算。側欄只保留命中的頁與它們所屬的分區；清空輸入後側欄還原。沒有任何命中時，側欄顯示無結果文案，內容區維持目前的頁。搜尋不比對內文。

| 既有頁 | 輸入 | 側欄 |
| --- | --- | --- |
| A（title「第一次登入」、keywords 含 github）、B（title「認識畫面」、無 keywords） | GitHub | 只剩 A 及其分區 |
| 同上 | （清空） | A、B 都恢復 |

## 內頁怎麼呈現

內文以共用的 Markdown 元件渲染（frontmatter 不顯示），沿用共用的閱讀欄與行寬上限、16px 基準字級、淺色與深色主題。內容區分三段：

- **頁首**固定顯示頁標題。內文第一個非空行是一級標題時取那一行，且內文不再重複顯示那個標題；否則取 frontmatter 的 title。
- **中段**是內文的捲動區。
- **頁尾**固定顯示出處列與上一頁／下一頁。

頁首與頁尾不隨內文捲動。換頁時回到內文頂端；外部改了內文而觸發的重載會維持捲動位置。

**右側錨點列**：內文有二級或三級標題時，內容區右側列出這些標題（三級縮排一級）。點一下捲到該標題；捲動時高亮目前所在的段。內文沒有二級與三級標題時，錨點列不出現。

**點出處跳規格**：頁尾出處行裡的 capability 名可以點。點了之後，該 capability 的唯讀規格詳情面板在手冊頁上滑入，與規格頁共用同一個詳情面板；側欄的「手冊」項維持高亮，手冊內文仍在畫面上，不會切離手冊頁。正典裡不存在的 capability 名以純文字呈現，點了沒有任何效果。

**載入中與失敗**：內文載入中以灰色佔位方塊呈現。載入失敗時內容區顯示失敗文案，側欄與其他頁照常可開。

## 可能過期與未入冊

側欄會標出兩種需要注意的狀況。兩種標示都只呈現，不會觸發生成。

**「可能過期」標記**：一頁的 sources 裡任一 capability，其規格內任何一個更新時戳在該頁的 generated「之後」時，側欄那一列帶「可能過期」標記。「之後」依兩邊的格式分段判定：

- 兩邊都是帶時區偏移量的時戳：換算成同一瞬間後，規格時戳嚴格晚於頁時戳才算。同一秒不算。
- 任一邊只有純日期：規格的日曆日不早於（晚於或同一天）頁的日曆日就算。帶時間的一方取它自己時區下的日曆日。生成當天封存的規格也算。

sources 為空、generated 缺席或既不是帶時區時戳也不是純日期、規格不存在時，不標記。規格內解析不了的更新時戳視為缺席。

| 頁的 generated | sources 規格的最新更新時戳 | 標記 |
| --- | --- | --- |
| 2026-09-01 | 2026-09-05 | 可能過期 |
| 2026-09-01 | 2026-08-20 | 無 |
| 2026-09-01 | 2026-09-01 | 可能過期（同日） |
| 2026-09-01 | （sources 為空） | 無 |
| （缺席） | 2026-09-05 | 無 |
| 2026-09-05T23:31:00+08:00 | 2026-09-05T23:17:28+08:00 | 無（同日但更早） |
| 2026-09-05T23:31:00+08:00 | 2026-09-05T23:40:00+08:00 | 可能過期 |
| 2026-09-05T23:31:00+08:00 | 2026-09-05T23:31:00+08:00 | 無（同秒） |
| 2026-09-05T23:31:00+08:00 | 2026-09-05T15:40:00Z | 可能過期（換算後是 23:40+08:00） |
| 2026-09-05T23:31:00+08:00 | 2026-09-05 | 可能過期（退回同日） |
| 2026-09-05 | 2026-09-05T23:17:28+08:00 | 可能過期（退回同日） |
| 2026-09-06T00:10:00+08:00 | 2026-09-05 | 無 |
| 2026-09-05T23:31:00+08:00 | not-a-date | 無（時戳視為缺席） |

**未入冊規格計數**：正典裡有「手冊生成後新增、且沒有任何頁引用」的規格時，側欄底部顯示計數提示。判定方式：該規格的每一個更新時戳都在每一頁的 generated 之後（用同一套分段判定），且它不在任何頁的 sources 裡。這種規格不存在時，提示不出現。把它加進某一頁的 sources 後，提示就消失。

看到這兩種標示時，跑 `/speclink-manual` 重生受影響的頁，見[操作手冊：生成與導覽](manual.md)。

## 空狀態

| 情況 | 你看到什麼 |
| --- | --- |
| 專案沒有 `openspec/manual/`，或裡面沒有任何 `.md` | 空狀態文案：說明尚無手冊、可用手冊技能從規格生成。側欄「手冊」項高亮，沒有錯誤彈窗 |
| 目錄讀不了 | 同上。錯誤只寫進日誌 |
| 目前分頁是 remote 工作區 | 「remote 模式尚不支援手冊」的空狀態。不會嘗試讀遠端，也不發任何網路請求 |
| 還沒開任何專案分頁 | 與點「變更」相同的空狀態引導頁，「手冊」項高亮 |

## 外部改了手冊，畫面自動更新

手冊頁開著時，app 以外的寫者（手冊技能、你的編輯器）新增、修改或刪除 `openspec/manual/` 底下的頁，側欄索引與已開啟頁的內文會在數秒內自動重載到磁碟現況。你不用重啟，也不用重新進入頁面。重載回應交錯時，以最新一次為準。

- 你正在讀的頁被外部重生：數秒內內容區換成新內文，側欄那一頁的過期標記依新的 generated 重算。
- 外部新增一頁（order 落在既有兩頁之間）：數秒內側欄在對應位置出現那一頁，其餘頁順序不變。

監看建立不了時，手冊頁照常可讀，只是失去自動刷新。

## 提示框

共用的 Markdown 元件會把首段以 `[!NOTE]`、`[!TIP]`、`[!WARNING]`、`[!CAUTION]` 之一開頭的引言區塊（大小寫不拘）呈現為對應類型的提示框：標記文字不出現，顯示類型標籤，配色取自介面的狀態語意色（資訊、成功、警告、危險），不佔主色。其餘內容照常渲染。不符這個形式的引言維持原本的樣子。這套呈現在淺色與深色主題一致，也適用於所有用共用 Markdown 元件的畫面。
