# 桌面 app 的手冊頁

點側欄的「手冊」進入手冊頁。它讀的是專案 `openspec/manual/` 底下的手冊頁（也就是你現在讀的這些檔案），把它們排成側欄、提供搜尋與上一頁／下一頁，並標出可能過期的頁。手冊頁是唯讀的，沒有任何寫入操作。手冊怎麼生成、頁的格式怎麼定，見[操作手冊：生成與導覽](manual.md)。

## 側欄與閱讀序

手冊頁讀取每一頁的 frontmatter，用兩層排序決定閱讀序：

1. 分區依分區內最小的 order 排列。
2. 分區內的頁依 order 升冪；同值時以檔名決定。

側欄的分區就是閱讀序中連續同一 section 的頁，同一分區的頁永遠相鄰。每一列顯示該頁的 title。上一頁／下一頁是閱讀序裡的相鄰頁：第一頁沒有上一頁，最後一頁沒有下一頁。

| 頁（檔名） | order | section | 側欄位置 | 上一頁 | 下一頁 |
| --- | --- | --- | --- | --- | --- |
| index | 10 | 開始使用 | 分區 1 第 1 列 | 無 | first-login |
| first-login | 20 | 開始使用 | 分區 1 第 2 列 | index | editor |
| editor | 30 | 文件協作 | 分區 2 第 1 列 | first-login | about |
| about | 40 | 附錄 | 分區 3 第 1 列 | editor | 無 |

frontmatter 有缺漏的頁會寬容降級，不報錯：

| 情況 | 呈現 |
| --- | --- |
| 缺 title | 以檔名（去副檔名）為標題 |
| 缺 section | 歸入「其他」分區 |
| 缺 order，或 order 不是整數 | 放在所屬分區的最後 |
| frontmatter 整個解析不了（不以 `---` 開頭、YAML 壞掉） | 仍列在側欄、以檔名為標題、可開啟顯示全文。其他頁的順序與內容不受影響 |

## 搜尋

手冊頁有搜尋列。輸入時即時比對各頁的 title 與 keywords，不分大小寫、子字串命中即算。側欄只保留命中的頁與它們所屬的分區；清空輸入後側欄還原。沒有任何命中時，側欄顯示無結果文案，內容區維持目前的頁。搜尋不比對內文。

| 既有頁 | 輸入 | 側欄 |
| --- | --- | --- |
| A（title「第一次登入」、keywords 含 github）、B（title「認識畫面」、無 keywords） | GitHub | 只剩 A 及其分區 |
| 同上 | （清空） | A、B 都恢復 |

## 內頁怎麼呈現

手冊頁的主區分三欄：左邊 240px 的目錄樹（也就是上面說的側欄，淡灰底）、中間的閱讀欄、右邊 200px 的本頁目錄。目錄樹每一列顯示該頁的 title，外觀與詳情頁的文件樹節點相同：每列高 30px、圓角，滑過時出現淡底，目前開著的頁是主色淡底配主色字。

閱讀欄的內容寬 768px、置中。內文以共用的 Markdown 元件渲染（frontmatter 不顯示），排版與詳情頁的閱讀卡一致：內文 15px、行高 1.75 倍，二級標題 16px 粗體，三級標題 14px 粗體，淺色與深色主題都適用。閱讀欄分兩段：

- **捲動區裡的白底閱讀卡**，由上而下是：
  1. **標題區**：24px 一般字重的頁標題。內文第一個非空行是一級標題時取那一行，且內文不再重複顯示那個標題；否則取 frontmatter 的 title。標題旁的籤槽放分區籤（缺 section 時是「其他」）與「可能過期」籤（見下一節）；同一列右端是「開啟 ▾」。
  2. **出處行**（灰字）：頁檔相對所在 checkout 根的路徑（預設為 `openspec/manual/<檔名>.md`，查不到時這段不出現）、「產生於」加上 generated（generated 缺席時這段不出現）、「出處」與出處籤。
  3. **數字磚**：「章節」（二級標題數）、「小節」（三級標題數）、「關鍵字」（keywords 數）、「出處規格」（出處去重後的數量）。內文還沒載入或載入失敗時，整列不出現。
  4. 提示框與內文。
- **固定在底部的底列**（白底、上緣細線，內容與 768px 閱讀欄對齊）：左邊是出處列，右邊是上一頁／下一頁的框線鈕，各帶小字標籤與目標頁的標題；沒有上一頁或下一頁時那顆鈕不出現。

底列不隨內文捲動；標題區跟著閱讀卡一起捲走，捲動區外沒有固定的頁首。換頁時回到內文頂端；外部改了內文而觸發的重載會維持捲動位置。

以〈系統匣選單〉這一頁為例（`openspec/manual/tray.md`，section 為「桌面 app」、generated 為 `2026-09-17T16:05:41+08:00`、7 個 keywords、sources 只有 tray-status-menu、內文 3 個二級標題與 11 個三級標題）：

| 位置 | 呈現 |
| --- | --- |
| 標題區 | 「系統匣選單」、分區籤「桌面 app」，同一列右端「開啟 ▾」 |
| 出處行 | `openspec/manual/tray.md · 產生於 2026-09-17T16:05:41+08:00 · 出處 tray-status-menu`（tray-status-menu 可點） |
| 數字磚 | 3「章節」、11「小節」、7「關鍵字」、1「出處規格」 |

**本頁目錄**：內文有二級或三級標題時，右欄依序列出這些標題（三級縮排一級；閱讀卡標題區的頁標題不列入）。點一下捲到該標題；捲動時高亮目前所在的段。內文沒有二級與三級標題時，本頁目錄不出現。

**「開啟 ▾」**：對應這一頁的檔案 `openspec/manual/<檔名>.md`，規則與詳情頁的「開啟 ▾」相同（見[認識桌面 app](desktop-overview.md)）。例如在本機專案選「在 Finder 顯示」，Finder 會顯示這一頁的檔案，選單首列是同一個相對路徑。

**點出處跳規格**：出處行與頁尾出處列都從索引的 sources 推導：每一項取第一個 `#` 前的 capability 名，重複的只列一次；`#` 後的錨定文字不會出現。兩處的 capability 名都可以點。點了之後，該 capability 的規格詳情頁覆蓋主區（和規格頁開的是同一頁），麵包屑是「專案名 / 手冊 / capability 名」，「手冊」導覽項維持高亮，不會切離手冊頁。按 Esc 或點麵包屑回到手冊頁，內文的捲動位置不變。正式規格裡不存在的 capability 名以純文字呈現，點了沒有任何效果。

| sources | 出處行與頁尾出處列 | 數字磚「出處規格」 |
| --- | --- | --- |
| `["desktop-app#看板與任務", "desktop-app#系統匣選單", "policy-config"]`，正式規格有 desktop-app、沒有 policy-config | 一顆可點的 desktop-app 與一個不可點的 policy-config，沒有 `#` | 2 |

**載入中與失敗**：內文載入中以灰色佔位方塊呈現。載入失敗時內容區顯示失敗文案，沒有數字磚、沒有提示框，側欄與其他頁照常可開。

## 可能過期與未入冊

手冊頁會標出兩種需要注意的狀況。兩種標示都只呈現，不會觸發生成。

**「可能過期」標記**：一頁的 sources 裡任一項判為過期時：

- 目錄樹那一列的列尾帶警示色的「過期」籤。
- 開啟那一頁時，閱讀卡標題區的籤槽帶「可能過期」籤，數字磚下方有一個「可能過期」的警告提示框。提示框裡每個出處規格一行「出處 capability 名 於 日期 由變更 變更名 更新」，日期與變更名取該規格全文裡最新的一次更新；讀不到該規格或規格裡沒有更新記錄時，那一行改為「出處 capability 名 在本頁產生後更新過」。接著一行「本頁產生於」加上 generated，以及指引「用 /speclink-manual 重生這一頁」。
- 沒有過期的頁沒有這個籤，也沒有提示框。

過期只在索引端判定，畫面不會自己重算。每一項各自判定，看它有沒有錨定：

- 不帶井號的項（例如 `desktop-app`）：看該規格內全部的更新時戳。
- 帶井號的項（例如 `"desktop-app#桌面上的品質關卡"`）：只看規格裡標題與井號後文字相同（去頭尾空白、區分大小寫）的那一段需求內的更新時戳。找不到相同標題的段、或規格不存在時，這一項直接算過期。

任一取得的時戳在該頁的 generated「之後」，這一項就過期。「之後」依兩邊的格式分段判定：

- 兩邊都是帶時區偏移量的時戳：換算成同一瞬間後，規格時戳嚴格晚於頁時戳才算。同一秒不算。
- 任一邊只有純日期：規格的日曆日不早於（晚於或同一天）頁的日曆日就算。帶時間的一方取它自己時區下的日曆日。生成當天封存的規格也算。

sources 為空、generated 缺席或既不是帶時區時戳也不是純日期時，不標記。不帶錨定的項，規格不存在時不標記；帶錨定的項則算過期（見上）。規格內解析不了的更新時戳視為缺席。索引回傳的 sources 是 frontmatter 的原字串，錨定原樣保留；井號前的名稱不合路徑守門的項整項略去。

| 2026-09-05 | desktop-app | 2026-09-10T17:15:24+08:00（整份） | 「過期」籤 |

**未入冊規格計數**：正式規格裡有「手冊生成後新增、且沒有任何頁引用」的規格時，側欄底部顯示計數提示。判定方式：該規格的每一個更新時戳都在每一頁的 generated 之後（用同一套分段判定），且它的名稱不在任何頁 sources 任一項的井號前。這種規格不存在時，提示不出現。未入冊是規格層面的事，不會出現在任何一頁的籤槽。把它加進某一頁的 sources 後（寫 `z` 或 `"z#某段"` 都算），提示就消失。

看到這兩種標示時，跑 `/speclink-manual` 重生受影響的頁，見[操作手冊：生成與導覽](manual.md)。一頁只取材某規格的幾段需求時，用錨定寫法就不會因為別段的封存被標為可能過期。

## 空狀態

| 情況 | 你看到什麼 |
| --- | --- |
| 專案沒有 `openspec/manual/`，或裡面沒有任何 `.md` | 空狀態文案：說明尚無手冊、可用手冊技能從規格生成。側欄「手冊」項高亮，沒有錯誤彈窗 |
| 目錄讀不了 | 同上。錯誤只寫進日誌 |
| 目前的專案是 remote 專案 | 「remote 模式尚不支援手冊」的空狀態。不會嘗試讀遠端，也不發任何網路請求 |
| 還沒開任何專案 | 專案欄不出現，沒有「手冊」項可點；主區是「開啟一個專案開始」的空狀態 |

## 外部改了手冊，畫面自動更新

手冊頁開著時，app 以外的寫者（手冊技能、你的編輯器）新增、修改或刪除 `openspec/manual/` 底下的頁，側欄索引與已開啟頁的內文會在數秒內自動重載到磁碟現況。你不用重啟，也不用重新進入頁面。重載回應交錯時，以最新一次為準。

- 你正在讀的頁被外部重生：數秒內內容區換成新內文，側欄那一頁的過期標記依新的 generated 重算。
- 外部新增一頁（order 落在既有兩頁之間）：數秒內側欄在對應位置出現那一頁，其餘頁順序不變。

監看建立不了時，手冊頁照常可讀，只是失去自動刷新。

## 提示框

共用的 Markdown 元件會把首段以 `[!NOTE]`、`[!TIP]`、`[!WARNING]`、`[!CAUTION]` 之一開頭的引言區塊（大小寫不拘）呈現為對應類型的提示框：標記文字不出現，顯示類型標籤，配色取自介面的狀態語意色（資訊、成功、警告、危險），不佔主色。其餘內容照常渲染。不符這個形式的引言維持原本的樣子。這套呈現在淺色與深色主題一致，也適用於所有用共用 Markdown 元件的畫面。
