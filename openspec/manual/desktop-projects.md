# 專案分頁、新增工作區與設定頁

這一頁說明桌面 app 怎麼開專案、怎麼在多個專案之間切換，以及設定頁能改什麼。

## 開啟專案

桌面 app 的每個開啟入口（視窗頂列、空狀態頁、分頁列的加號、伺服器頁籤）都會進到同一個「新增 Workspace」選擇器。第一步先選來源：

- 「本機資料夾」：選一個電腦上的資料夾。
- 「Server」：從已登入的 server 挑一個 Project／Repo。server 的連線與登入見 [桌面連線 server 與 remote 工作區](desktop-remote.md)。

兩張來源卡的下方還有一個「最近開啟」區段，列出你之前開過、但現在不在分頁列上的工作區。點一下就能直接開，不必重新選資料夾或重新挑 Project／Repo。規則見下方的「最近開啟」。

選「本機資料夾」後，app 開系統的資料夾選擇器。你選定資料夾後，app 從那個資料夾往上找 speclink 專案根。找到就直接切換過去：看板、已封存頁與設定頁全部換成新專案的內容，不用重啟。你選到子目錄也可以，app 會切到往上找到的專案根。

開啟失敗（路徑不存在或不可讀）時，app 顯示一行錯誤訊息，目前的專案不變。

### 三種資料夾，三種結果

| 資料夾狀態 | app 的反應 |
| --- | --- |
| 專案根有 `.speclink.yaml` | 直接開啟，不問任何問題 |
| 有 openspec/ 但沒有 `.speclink.yaml` | 顯示啟用確認對話框 |
| 往上找不到任何 speclink 專案 | 顯示初始化確認對話框 |

兩種確認對話框都有 AI 工具多選（claude／codex），預設勾選 claude。你按確認之前，app 不會在資料夾寫入任何東西。你取消，資料夾內容維持原樣。

**初始化**（全新資料夾）：確認後 app 做的事等同於 `speclink init`。它建立 openspec/ 骨架（specs/、changes/archive/、config.yaml）、在專案根寫 `.speclink.yaml` 記錄你選的工具、為每個工具生成技能檔。它不會產生 CLAUDE.md 或 AGENTS.md。接著切到該專案，看板是空的。

**啟用**（已有 openspec/ 的資料夾，例如從別處搬來的專案）：確認後 app 只補缺的東西：openspec/ 缺的骨架、專案根的 `.speclink.yaml`、你選的工具的技能檔。既有的 openspec/ 內容一個位元都不動，包含你自訂過的 config.yaml。判定與寫入都以往上找到的專案根為準，不是你點的子目錄。

初始化或啟用失敗時，app 顯示一行錯誤訊息，不切換專案。

> [!NOTE]
> 啟用流程的規格較舊的一版寫「會產生 CLAUDE.md 的受管區塊」。較新的工作區補齊規格寫不產生 CLAUDE.md。本頁採較新版本。詳見 [本手冊的來源](about.md)。

### 最近開啟

「新增 Workspace」第一步的兩張來源卡下方，是「最近開啟」區段。它記住你成功開過的工作區，讓你下次一點就開。

**怎麼記**：

- 每次成功開啟一個工作區，app 就把它記到清單最前面。經選擇器開、點分頁切換、直接開帶 remote 標記的資料夾、本機轉 remote，四種方式都算。
- 同一個工作區只留一筆，再開一次就移到最前。清單最多 20 筆，滿了就丟最舊的一筆。
- 本機轉 remote 成功時，那個資料夾的本機條目被移除，改記成 remote 條目。
- 記錄存在 app 本機，不寫進任何專案目錄。關閉分頁、分頁列滿 10 個被淘汰，都不會動到這份記錄。

**怎麼顯示**：

- 已經在分頁列上的工作區不會列出來。濾完沒有東西時，整個「最近開啟」區段連標題都不顯示，第一步只剩兩張來源卡。
- 本機條目顯示資料夾名稱與完整路徑。remote 條目顯示連線名稱與工作區名稱（Project／Repo），連線名稱從伺服器頁籤的清單即時查得。
- 每筆條目都有「自最近開啟移除」。移除後從畫面與記錄一起消失，重啟 app 也不會回來，其餘條目順序不變。
- 介面語言是英文時，這幾個字面分別是「Recently opened」、「Remove from recently opened」、「Connection removed」、「Connection signed out」。

**點本機條目**：app 先探測那個路徑。探測成功就關掉選擇器，走與「本機資料夾」選同一路徑完全相同的流程：既有專案直接開、沒有 openspec 骨架的走初始化確認（確認前不寫入）、帶 remote 標記的走下方「直接開啟帶 remote 標記的資料夾」的分流。探測失敗（例如資料夾已被刪除）時，該條目變成錯誤態並顯示一行原因。選擇器留在原地，分頁列與目前專案都不變。條目會留在清單裡，直到你自己移除。

**點 remote 條目**：app 先確認原本綁定的 checkout 仍然對得上那個 Project／Repo（沒綁 checkout 的條目跳過這一步），再用同一個連線、同一個 Project／Repo、同一個 checkout 資料夾開啟。驗證或連線失敗（例如 checkout 資料夾已被刪除）時，該條目變成錯誤態並顯示原因，不建分頁、不切換專案，仍可移除。

**remote 條目的連線狀態**：

- 連線已從伺服器頁籤移除：條目顯示「連線已移除」，開啟停用，移除仍可用。
- 連線還在但已登出：條目顯示「連線已登出」，開啟停用，移除仍可用。
- 伺服器清單讀取失敗或還沒讀完：app 不在畫面上判定這兩種錯誤態，開啟維持可用。此時你點條目，app 在開啟流程裡用現有清單補判。連線解不出來且條目綁有 checkout 時，轉成「連線已移除」、不建分頁。沒綁 checkout 的條目照常以原連線與 Project／Repo 開啟。
- 錯誤態在你下一次開啟「新增 Workspace」時清掉。

**升級與壞資料**：升級 app 後第一次啟動、還沒有最近開啟記錄時，app 用既有的分頁列補種這份清單，最後開的分頁排最前。記錄已存在（就算是空的）就不補種，重啟也不會重複補種。記錄壞到無法解析時，app 照常啟動、不報錯，清單視為空。個別條目壞掉時只丟那一筆。下一次成功開啟工作區後，記錄重新寫入，只含那一筆。

## 專案分頁列

視窗頂欄用分頁列列出目前開著的專案。作用中的分頁就是目前看到的專案，顯示專案根的目錄名。

- 分頁最多 10 個。順序與最後作用中的分頁跨重啟保留。這些記錄存在 app 本機，不寫進任何專案目錄。
- 點分頁就切換專案，效果與「開啟專案」相同。同一個專案再開一次不會多一個分頁，而是跳到既有分頁。
- 關閉分頁就從分頁列移除。它不影響「最近開啟」的記錄：關掉的專案會出現在「新增 Workspace」的最近開啟區段，一點就能開回來。分頁列不是最近開啟的唯一記憶。
- 分頁上只有專案名稱與必要的狀態圖示，沒有計數徽章。待收尾的數量看看板欄位計數與系統匣面板。
- 快速鍵：Ctrl+Tab 循環切換分頁，Ctrl+1 到 Ctrl+9 直達第 N 個分頁。

分頁指到的資料夾已經不存在時，分頁變成錯誤態（警示標記）。點它會顯示一行錯誤、不切換專案，並提供「自分頁移除」。app 啟動時會對每個背景本地分頁探測一次路徑，失效的也轉成錯誤態。

沒有任何分頁時（例如第一次使用），主畫面顯示帶「開啟專案」的空狀態引導頁，不是空看板。

remote 分頁（連到 server 的工作區）在滑鼠停留時顯示已連接的 checkout 路徑。

## 從 server 挑 Project／Repo

選「Server」後：

1. 從已登入的連線中挑一個 server。還沒有連線可以就地新增並登入，登入後回到這一步。從伺服器頁籤進來時 server 已預選，直接到下一步。
2. app 從 server 取回你有 membership 的清單，以 Project 分組列出 Repo，你單選一個。你不需要手打任何識別字串。清單是空的時，畫面顯示繁中說明，不是錯誤。這通常代表管理員還沒給你這個 Project 的 membership，見 [帳號、邀請、存取金鑰與 membership](accounts.md)。
3. 決定要不要連接本機 checkout。略過就以「只看規格」的方式開一個 remote 分頁。

### 連接本機 checkout

你選了 checkout 資料夾後，app 先做一次零寫入的檢查：

- 資料夾已有 remote 標記（`.speclink.yaml` 的 remote 區段）時，標記指向的 server 與 repo 必須和你剛選的一致。不一致就以繁中訊息拒絕，訊息會指出標記指向哪個 server 與 repo。磁碟不動。
- 沒有標記時，資料夾必須是 Git repository。不是就拒絕。
- `.speclink.yaml` 壞掉無法解析時，app 顯示解析錯誤，不改資料夾、不開分頁。

檢查通過後，畫面顯示資料夾路徑與 Claude／Codex 勾選框。既有 `.speclink.yaml` 有記錄工具時以它為預選。沒記錄時只依資料夾裡實際存在的工具痕跡預選，不會自動幫你勾 Claude。至少勾一個工具、路徑也齊備之前，「開啟 Workspace」按鈕維持停用。

按下「開啟 Workspace」後 app 才寫入：把工具選集寫進 `.speclink.yaml`、為選到的工具生成或更新技能檔、清掉沒選的工具的 Speclink 產物。沒有標記的資料夾會補上與 CLI remote 連接同構的 remote 區段。你自己在 `.speclink.yaml` 寫的其他設定與自訂工具都保留。同步全部成功後才開始連線。同步失敗時選擇器停在原地，保留路徑與選集讓你重試，不會開分頁。

> [!NOTE]
> 較舊的工作區選擇規格寫這一步「生成 AGENTS.md／CLAUDE.md 的 Speclink 區塊」。較新的工作區工具規格改為只生成技能檔，並把舊版留在指令檔裡的區塊剝掉、保留你自己的文字。本頁採較新版本。詳見 [本手冊的來源](about.md)。

### 直接開啟帶 remote 標記的資料夾

你用「本機資料夾」開到一個帶 remote 標記的資料夾時，app 依狀況分流：

- 對應的 server 已登入，且 `.speclink.yaml` 有至少一個有效的內建工具：先同步技能檔，成功後直接連線開 remote 分頁，不經過選擇器。同步失敗就顯示帶路徑與失敗階段的錯誤，不開分頁。
- 對應的 server 已登入，但沒有有效的工具選集：導向選擇器的 checkout 步驟。server、Project／Repo 與路徑已預填，你要親自勾 Claude／Codex。
- 沒有對應的連線或未登入：導向選擇器的 server 步驟，server 位址已預填。

資料夾同時有本機 openspec/ 與 remote 標記時，app 停下來要你選。三個出口都不會靜默覆蓋：

- 「繼續本地」：這次用本地內容開啟，標記不動。
- 「以 server 為準」：本地 openspec/ 改名成帶日期的備份，資料夾轉為 checkout 後開 remote 分頁。不上傳本地內容、不改 server。對話框會明說這是備份後棄用本地，不是合併。
- 「遷移本地內容」：進入遷移流程，把本地內容搬上一個空的 Project／Repo。見 [本地工作區遷移到 remote](migrate.md)。

## 設定頁

設定分成兩頁。**專案設定頁**跟著作用中的專案分頁走。**應用程式設定頁**與任何專案無關。

### 專案設定頁（本地專案）

頁簽依序為 config.yaml、.speclink.yaml，預設落在 config.yaml。config.yaml 與 .speclink.yaml 簽首用等寬字標出對應的檔案路徑。

> [!NOTE]
> 規格對頁簽數目有兩種說法。較新的需求（2026-08-23）寫專案設定頁只有 config.yaml 與 .speclink.yaml 兩簽。較早的一組需求（2026-08-22）寫有獨立的「Schema」頁簽，順序為 config.yaml → Schema → .speclink.yaml，且 config.yaml 簽內不放產出流程。本頁的頁簽列依較新者；產出流程的內容仍照那組需求列在下方。實際畫面以產品為準。詳見 [本手冊的來源](about.md)。

**config.yaml 簽**有三張卡：

- 「專案說明」卡：唯讀時以 markdown 呈現，太長會收合並提供顯示更多。沒設定時顯示空狀態提示。按右上的編輯鈕，這張卡就地變成多行文字區，按鈕列變成取消與儲存。儲存只寫專案說明。清空後儲存會把這個欄位整個移除。
- 「產出規則」卡：唯讀時只列出有內容的產物分節，分節名為小節標題、規則為清單。編輯時依目前的產出流程固定分節（spec-driven 是 proposal、design、specs、tasks 四節），每節一個文字區。一行就是一條規則，行的順序就是寫入與注入的順序。不能自己新增分節。儲存時每行去頭尾空白、空行不寫入。某節清空就移除該節，全部清空就移除整個產出規則。以特殊字元開頭的規則（例如 @ 或反引號）會自動加引號，存回去仍逐字還原。
- 「產出政策」卡：locale 與 spec_locale 是下拉，tdd 與 audit 是開關。另有 worktree 開關，文案直接寫「worktree」。這些欄位的意義見 [工作流政策與設定](policy-config.md)。

兩張編輯卡各自獨立：一張進入編輯不影響另一張。取消會還原那張卡，不寫檔。

儲存的規則：只代換你動到的鍵，其他鍵原樣保留。把政策欄位設回預設值時會移除那個鍵，而不是寫明值。改工具清單後 app 會同步技能檔：新選的生成、取消的清理。改 worktree 開關存檔後也會同步技能檔。

worktree 開關由開改關時，如果還有活躍的 linked worktree，app 拒絕寫入並浮出擋下訊息。訊息列出每個 worktree 的變更名、分支與路徑，提示先執行 worktree-merge 收尾。設定不變、開關回到開啟。見 [平行實作與合回：worktree](worktree.md)。

**產出流程（規格稱為 Schema 簽，2026-08-22）**列出每個可解析的產出流程：名稱、來源層級、產物順序圖（例如 proposal → design → specs → tasks）。點進去是唯讀詳情，內建的內容不能在桌面編輯。這個簽提供的動作：

- 切換：用下拉選專案要用的產出流程，寫進 config.yaml 的 schema 鍵，其他內容逐位元組不變。產出規則卡的分節隨新流程更新。如果產出規則正在編輯中，分節等你儲存或取消後才跟上，草稿不會丟。
- fork：把選中的流程複製到專案的 openspec/schemas/ 下，複本名固定為「原名-custom」。同名跨層時，只有引擎實際會命中的那一層提供 fork。
- 建立：輸入 kebab-case 名稱（例如 my-flow），在專案 openspec/schemas/ 下產出預設骨架。名稱不合法（例如 My Flow）或已存在時，引擎的錯誤訊息浮出，磁碟不變。
- 開啟所在資料夾：對專案層與使用者層的流程，在系統檔案管理器顯示它的目錄。內建流程沒有這個動作。內容編輯交給外部編輯器。
- 刪除：只對專案層的流程。按下先出確認對話框，取消零變動。確認後整個目錄移除。config.yaml 正在使用的流程拒刪，錯誤浮出、磁碟不變。

**.speclink.yaml 簽**有「AI 工具」卡：內建工具 claude／codex 多選，自訂工具原樣列出、不可編輯。

### 專案設定頁（remote 工作區）

作用中分頁是 remote 工作區時，較新的需求（2026-08-23）寫專案設定頁只有單一 Workflow 簽；較早的產出流程需求（2026-08-22）寫頁簽依序為 Workflow、Schema。Workflow 簽有與 config.yaml 簽同形的專案說明、產出規則、產出政策三卡。內容來自 server 上的政策文件，簽首用等寬字顯示政策版次。沒有 worktree 開關。

儲存時 app 帶著你讀到的版次送出。別人先一步改過時，你會收到版次衝突：你的輸入原樣保留，畫面浮出逐欄位對照（server 現值｜我的輸入）。只有兩個出口：「以 server 版重載」與「檢視後以最新 revision 重新提交」。沒有強制覆寫。

你在這個 Project 的角色是 reader 時，三張卡唯讀、儲存停用，並附繁中角色說明。

Schema 簽在 remote 只列內建流程，切換下拉也只有內建可選。config 指到非內建名稱時以停用項顯示現值、不可選取，並顯示「遠端自訂尚不支援」的狀態，產出規則分節留空。fork、建立、開啟所在資料夾、刪除都不出現。

### 應用程式設定頁

頁簽依序為本機設定、伺服器，預設落在本機設定。

- 本機設定簽有「介面語言」卡，並註記內容只存在這台裝置、不寫入版本庫。三選：跟隨系統／zh-TW／en。切換即時對全介面生效並跨重啟保留。跟隨系統時，系統語言以 zh 開頭判為 zh-TW，其餘為 en（例如 zh-CN 得到 zh-TW、ja-JP 得到 en）。介面語言與 config.yaml 的 locale（AI 產物的語言）互不影響。
- 伺服器簽管理 server 連線，見 [桌面連線 server 與 remote 工作區](desktop-remote.md)。

## 設定寫入的保護

- 讀取時區分「檔案不存在或欄位未設定」與「檔案存在但解析失敗」。前者顯示為預設值狀態。後者：那個頁簽的標籤帶警示點、簽內浮出解析失敗說明、表單停用，app 不會對那個檔案寫入。config.yaml 壞掉時，專案說明與產出規則的編輯鈕也停用。應用程式設定頁不受專案設定檔壞掉影響。
- 每次寫入前 app 先確認新內容解析得回來、目標欄位值正確。寫檔後再回讀驗證一次。任一步失敗就顯示一行指明檔案與階段的錯誤訊息，磁碟上的檔案維持原內容。

## 下拉遇到看不懂的值

locale 或 spec_locale 的儲存值不在合法選項內時（例如有人手改成「繁體中文」），下拉直接顯示那個原始值，帶無效標註與警示樣式。欄位下方出現提示文字，引導你改選合法代碼。app 不會自動清空或改寫它。你改選合法代碼並儲存後，值被覆蓋、提示消失。合法代碼：locale 為 tw、ja、en；spec_locale 為 tw、ja、en、auto。

**出處**：`desktop-config`、`workspace-chooser`
