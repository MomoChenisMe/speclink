# 網路與診斷：Proxy、錯誤紀錄與匯出

更新頁無法顯示，或安全標準資料下載失敗時，可以先開啟錯誤紀錄，再重做一次原本失敗的操作，用紀錄判斷原因。公司網路需要 Proxy（代理伺服器）時，也在這裡設定。

## 開啟設定

點左側圖示列底部的齒輪，在應用程式設定選「網路與診斷」。也可以在分類搜尋框輸入 Proxy、Debug mode、匯出診斷或測試更新連線。

這些設定只存在這台裝置，重開 app 後保留，不改團隊政策或專案文件。沒有開啟專案、遠端專案離線或登入失效時，仍能使用這一頁。

## 選擇 Proxy 模式

更新檢查、更新下載、安全標準清單刷新及資料下載共用同一個選擇。

| 模式 | 何時使用與效果 |
| --- | --- |
| 系統 | 預設模式。先採用程序繼承的 Proxy 與排除規則，再讀取支援的系統固定 Proxy |
| 手動 | 自行填入固定 HTTP Proxy，例如 `http://proxy.example:8080` |
| 直接連線 | 明確略過環境及系統 Proxy，直接連到目的地 |

手動位址必須包含主機與連接埠；連接埠介於 1 到 65535。不要加入帳號、密碼、額外路徑或查詢參數。不合法的設定不會儲存，原值會保留。

儲存後，下一個網路工作才會使用新設定；已開始的下載，以及已找到的候選更新，其下載仍沿用原設定。選定的 Proxy 連線失敗時，app 不會自行改成直接連線。

### 系統模式的支援範圍

- Windows 支援單一固定 HTTP Proxy。
- macOS 支援固定 HTTP 或 HTTPS Proxy 設定。
- Linux 只讀取程序繼承的環境設定。
- 不支援 PAC／WPAD（自動代理腳本或自動探索）、Windows 分協定的 Proxy 字串、Linux 桌面私有設定、手動認證、SOCKS 或自訂憑證授權單位。

系統沒有提供可用固定路由時，頁面與紀錄會明示本次直接連線，不代表自動代理腳本已生效。系統提供不支援的協定或認證方式時，會顯示不支援。

內網或本機 Proxy 可以作為代理端點；安全標準資料的目的地仍限核准官方來源。Proxy 設定不會放寬憑證、下載大小、來源或更新簽章檢查，也不接管遠端專案的登入及資料連線。

## 記錄一次失敗

1. 開啟 Debug mode 並儲存。這個開關預設關閉。
2. 回到原本出問題的更新頁或[安全標準資料頁](security-data.md)，重做一次操作。
3. 回到「網路與診斷」，匯出診斷紀錄。
4. 不需要繼續記錄時，關閉 Debug mode 並儲存。

開啟後會記錄畫面錯誤、未處理的非同步錯誤，以及更新與標準下載的開始和結果。同一工作的事件可以互相對照。紀錄會區分名稱解析、連線、逾時、憑證、代理認證等錯誤；沒有取得的狀態不會被猜成某個 HTTP 碼。

更新頁本身呈現失敗時，錯誤畫面會提供重試及前往網路與診斷的入口。

### 容量與記錄失敗

紀錄最多保留四檔、共 8 MiB，達上限時輪替較舊內容；來不及接收的事件會累計遺失數量。關閉 Debug mode 後停止接收新事件，既有紀錄仍保留。

紀錄寫入失敗會顯示診斷記錄失敗；它不會把原下載結果改成另一種結果。設定儲存失敗時舊值不變；設定檔損壞時，新更新與標準下載會停止，直到修正設定或明確重設成功。重設後回到預設關閉 Debug mode、使用系統 Proxy 的設定。

## 匯出診斷

使用「匯出診斷」並在系統儲存視窗選擇新檔案位置。Debug mode 開或關都能匯出已有紀錄；沒有紀錄時會顯示空狀態。

匯出會產生最多 9 MiB 的 ZIP，包含 app 版本、作業系統、匯出時間及經過濾的紀錄，不含專案內容或偏好檔。密碼、金鑰、標頭、回應內容、完整本機路徑與網址的敏感部分不會納入；損壞的紀錄會跳過並計數。紀錄不會自動上傳。

取消儲存不會建立檔案，也不顯示成功。寫入失敗不留下完成包；既有目的檔不會被覆寫。

## 測試更新連線

開啟 Debug mode 後，才可按「測試更新連線」。這是一次獨立測試，只在你按下時請求內建更新端點，沿用同一份 Proxy 設定。

測試最多 20 秒、讀取 2 MiB、跟隨三次 HTTPS 轉址，不接受自填網址，不下載安裝檔、不安裝更新，也不改變原更新狀態。

結果顯示可取得的狀態或錯誤及耗時。Proxy 要求認證時，可能看到 407 或代理認證錯誤；底層沒有公開的 HTTP 碼會維持空值。這份結果只能說明本次測試，不能當成先前下載的回應，也不能單憑下載失敗就斷定是公司 Proxy 造成。
