# 認識桌面 app

桌面 app 是 Speclink 的圖形操作面。它讀的是你專案裡 `openspec/` 底下的檔案，和 CLI 看的是同一份資料。這一頁帶你認識視窗外殼、四種詳情頁的共通規則、即時更新、載入與回饋，以及顏色與排版。看板與任務的操作見[看板與任務](desktop-board.md)；規格、討論、已封存的內容怎麼呈現，見[規格、討論、已封存與搜尋](desktop-browse.md)。

## 它是什麼

- **引擎直接內嵌**。app 不會另外啟動 CLI 子程序，所有畫面資料都由內嵌引擎讀檔取得。
- **本地檔案是唯一真相**。app 不會把變更或規格的內容搬到別的地方存放。你用 CLI、agent 或編輯器改檔案，畫面就跟著變。
- **和 CLI 同一套語意**。清單與狀態的欄位和值，與 `speclink list`、`speclink status` 的輸出對應。
- **動詞經內嵌引擎執行**。對變更可執行狀態查詢、結構驗證、分析與封存；對專案可列出清單與顯示內容。結果與 CLI 一致，失敗時畫面呈現引擎回報的錯誤，不會吞掉。變更詳情頁的「分析」按鈕一次跑結構驗證加分析，結果在頁內展開，見[看板與任務](desktop-board.md)。

在一個不含 Speclink 專案標記的資料夾啟動 app，畫面會顯示「非 speclink 專案」的空狀態。app 不會崩潰，也不會堆出錯誤彈窗。

## 視窗外殼

視窗以 1440×900 的邏輯尺寸啟動，並在主螢幕置中。app 不記憶上次的視窗大小與位置，每次啟動都一樣。

原生標題列的空白條被拿掉，換成兩條自繪、高 48px 的頂列：左邊的**左側標題列**（在圖示列與專案欄上方）和右邊的**主區頂列**。拖曳任一條都能移動視窗。三個平台的差別：

| 平台 | 標題列 | 視窗按鈕 |
| --- | --- | --- |
| macOS | 不顯示原生標題文字，紅綠燈放在左側標題列左端，與標題列內容垂直置中 | 紅綠燈；主區頂列右端沒有視窗鈕 |
| Windows | 沒有原生標題列（保留陰影與圓角） | 主區頂列右端自繪三顆鈕：縮到最小、最大化／還原（圖示隨視窗狀態切換）、關閉。滑過時灰底，關閉鈕滑過時紅底白字 |
| Linux | 保留原生標題列，下方仍是同樣兩條 48px 頂列 | 沒有自繪視窗鈕 |

**左側標題列**顯示作用中專案的名稱（純文字，左緣與下方專案欄的導覽文字對齊；指標停留時顯示完整路徑），右端是「⋯」專案動作鈕。沒開任何專案時這裡留白。

**主區頂列**顯示麵包屑。有專案時是「專案名 / 頁名」，頁名為變更、已封存、規格、手冊或專案設定，點專案名回到看板；在設定模式是「設定 / 分類名」；沒開專案時是空的。麵包屑不放任何操作結果訊息。更新通知之類的通知列出現在主區頂列下方，主區頂列永遠留在視窗最上緣。

| 你做了什麼 | 麵包屑 |
| --- | --- |
| 在專案 A 的看板 | A / 變更 |
| 切到規格頁 | A / 規格 |
| 切到專案 B | B / 規格 |
| 在專案 A 開啟變更 add-auth 的詳情頁 | A / 變更 / add-auth |

## 圖示列與專案欄

左側分兩層：

- **圖示列**（約 56px，所有專案共用）：由上而下是品牌標記、每個開著的專案一個方塊、「新增專案」的「＋」，最底下是「設定」齒輪。
- **專案欄**（固定 200px，不能收合，屬於目前的專案）：由上而下是「變更」「已封存」「規格」「手冊」，最底下固定是「專案設定」，中間是彈性空白。

導覽規則：

- 點導覽項只是切頁：切到對應頁，目前所在的項以主色淡底配主色字標示。再點一次同一項不會跳回看板。
- 「已封存」帶一枚徽章，顯示封存變更的數量。看板上有變更被封存時，數字在數秒內加一。
- 「手冊」進入手冊頁，見[桌面 app 的手冊頁](desktop-manual.md)。
- 「設定」不在專案欄，入口是圖示列底部的齒輪。
- 專案欄沒有備忘項，也不顯示 app 版號。版號在應用程式設定的更新頁版本卡與關於頁品牌卡。
- 有專案、且不在設定模式時，專案欄的五個導覽項永遠都在。
- **沒開任何專案時**：專案欄不出現，圖示列只剩品牌標記、「＋」與齒輪，主區是「開啟一個專案開始」的空狀態。這時點齒輪照常進入應用程式設定，裡面的功能都能用。

**切換專案**：點圖示列上非作用中的本地專案方塊，那個方塊立刻換成轉圈圖示，原專案的畫面照常可用。app 先探測目標專案：成功才切過去，左側標題列與麵包屑的專案名同步更新；失敗則方塊以錯誤樣式（角落紅點）呈現，作用中專案不變。

**看板頁**的主區以頁標題區開頭：24px 的標題「變更」與一句灰字說明，同一列右端是搜尋與篩選工具列，下方才是各欄。

開啟與關閉專案、「⋯」專案動作選單與各設定頁的內容，見[專案、新增專案與設定頁](desktop-projects.md)。

## 設定模式與專案設定模式

點齒輪進入**設定模式**：齒輪變成作用中，專案欄換成 200px 的設定分類欄。分類欄頂部是搜尋框，下面是「應用程式」群組（一般、更新、CLI、伺服器）與「關於」群組（關於 Speclink）。左側標題列左端變成「← 設定」返回鈕，沒有「⋯」；麵包屑是「設定 / 分類名」，點「設定」回到一般頁。沒開專案時也一樣，左側恆為圖示列加分類欄的寬度。

分類欄的搜尋框以分類名與各頁的列標籤比對，不分大小寫。例如輸入「外觀」，分類欄只剩「一般」（外觀列在一般頁），「關於」群組標題一起隱藏；沒有命中時顯示「沒有符合的設定」；清空後五項還原。

點專案欄的「專案設定」進入**專案設定模式**：專案欄換成專案設定分類欄。群組「openspec/config.yaml」有專案說明、產出規則、審查規則、產出流程；群組「專案」有 .speclink.yaml（remote 專案沒有這組）。解析失敗的設定檔，其分類項帶警示點。左側標題列左端是「← 專案設定」、右端是等寬小字的專案名；麵包屑是「專案名 / 專案設定 / 分類名」，前兩段可點：專案名回看板，專案設定回專案說明頁。

兩種分類欄都會記得你上次所在的分類。

**離開設定**：點返回鈕回到進入設定前所在的頁面（在兩種設定模式之間切換不會改變這個去處；沒開專案時回到空狀態）。下列操作與返回鈕等效：Esc、⌘[、⌘←（非 macOS 為 Alt+←）、滑鼠側鍵「上一頁」，以及 macOS 上觸控板兩指向右滑過門檻後放開（判定規則與詳情頁相同，見下方「麵包屑、返回與切換」）。

- 焦點在文字輸入（例如分類欄的搜尋框）時，按 Esc 不會離開。
- 專案設定有未儲存的修改時，返回會先問「要捨棄未儲存的修改嗎？」：取消就留在原頁、修改還在；選捨棄才離開。只打開編輯而沒改內容時直接返回。
- 有對話框開著時，所有返回操作都不作用，對話框也不會被一起收掉。

## macOS 選單列

macOS 上 app 用自己的選單列，共六組。Windows 與 Linux 沒有選單列，既有的鍵盤快捷鍵照舊：Ctrl+Tab 與 Ctrl+1..9 切換專案、Ctrl+F 聚焦看板搜尋。

| 組 | 項目 |
| --- | --- |
| Speclink | 關於 Speclink、檢查更新…、設定… ⌘,、服務、隱藏 Speclink ⌘H、隱藏其他 ⌥⌘H、顯示全部、結束 Speclink ⌘Q |
| 檔案 | 開啟專案… ⌘O、關閉專案 ⌘W、安裝 CLI… |
| 編輯 | 復原、重做、剪下、複製、貼上、全選 |
| 檢視 | 變更 ⌘1、已封存 ⌘2、規格 ⌘3、手冊 ⌘4、專案設定、搜尋看板 ⌘F、重新整理 ⌘R、下一個專案 ⌃Tab |
| 視窗 | 縮到最小 ⌘M、縮放、全部移到最前 |
| 說明 | 手冊、更新日誌、GitHub、回報問題 |

各項做什麼：

- **開啟專案…**：開「新增專案」對話框。
- **關閉專案**：主視窗是焦點時關閉作用中專案。系統匣面板在前景時按 ⌘W，主視窗的專案維持開啟。
- **變更、已封存、規格、手冊、專案設定**：切到對應頁。例如按 ⌘3 切到規格頁，按 ⌘1 回到看板。
- **搜尋看板**：聚焦看板的搜尋輸入；不在看板時先切回看板。
- **重新整理**：重讀作用中專案。
- **下一個專案**：循環切換作用中專案。
- **檢查更新…**：執行一次手動檢查，並進入應用程式設定的軟體更新卡，見[自動更新、CLI、技能檔過期與關於頁](desktop-update.md)。
- **設定…、安裝 CLI…**：進入應用程式設定。
- **關於 Speclink**：開啟應用程式設定的關於頁。
- **更新日誌**：開啟更新日誌對話框。
- **GitHub、回報問題**：用系統瀏覽器開啟專案的 GitHub 頁與新 issue 頁（`https://github.com/MomoChenisMe/speclink/issues/new`），app 畫面不變。
- **編輯組與視窗組**：系統預設行為。

選單文字跟著介面語言呈現 zh-TW 或 en，切換語言後立即重建。例如切成 en，組名變成 File、Edit、View、Window、Help，項目變成 Open Project…、Close Project、Changes、Archived、Specs、Manual 等。沒有作用中專案時，「關閉專案」、整個檢視組與說明組的「手冊」停用；「開啟專案…」照常可用。

## 詳情頁：共通規則

點看板卡片、規格列或已封存列時，主區整個換成那個項目的**詳情頁**。詳情頁有四種：變更、討論、規格、已封存。各自的內容見[看板與任務](desktop-board.md)與[規格、討論、已封存與搜尋](desktop-browse.md)；這一節講四種共通的規則。

### 開在哪一頁之上

詳情頁開著時，它底下的頁面（稱為宿主頁）不可見，也不能用鍵盤或指標操作，但沒有被卸掉。關掉詳情頁後，宿主頁維持開頁前的捲動位置、搜尋字串與篩選，不會重載或重置。

- **變更詳情頁與討論詳情頁**：宿主頁一律切回看板。不論你從哪裡開（看板卡片、系統匣、頁內跳轉、封存確認框的「去蓋章」），或開的當下在哪一頁（規格頁、已封存頁、專案設定、應用程式設定），關掉後看到的都是看板。
- **規格詳情頁與已封存詳情頁**：宿主頁維持你開啟時所在的規格頁、已封存頁或手冊頁。

### 同時只開一個

任一詳情頁開著時，從任何入口（看板卡片、規格清單、已封存頁、系統匣、頁內跳轉、‹ › 切換）開另一個，先開的會關閉、由後開的取代。不會疊加，也不會拒開。

開啟變更或討論詳情頁時，下列可取消的浮層會一起收掉，效果等於按了它的「取消」或「關閉」，不會送出任何未確認的動作：新增專案對話框、初始化確認、啟用確認、封存確認（含品質關卡工單的三選項框）、封存討論確認、刪除確認、退回提案中確認、退回被擋的說明、更新日誌對話框、技能檔提示確認。更新日誌在自動彈出模式下被這樣收掉時不算看過，下次啟動仍會彈出。

| 開著的浮層 | 你開啟 | 結果 |
| --- | --- | --- |
| 新增專案 | 變更詳情 | 對話框關閉、詳情頁開啟、沒有任何專案被開啟 |
| 封存確認 | 討論 | 確認框關閉、詳情頁開啟、沒有封存發生 |
| 工單三選項框 | 變更詳情 | 三選項框關閉、詳情頁開啟、工單維持未結 |
| 刪除確認（變更 A） | 討論 | 確認框關閉、詳情頁開啟、變更 A 沒被刪除 |
| 技能檔提示確認 | 變更詳情 | 確認框關閉、詳情頁開啟、技能檔沒被改寫 |

例外：遷移對話框與遠端衝突對話框不能取消。它們開著時，開啟變更或討論詳情頁不會有任何作用：浮層維持、詳情頁不開、宿主頁不切換；從系統匣觸發時，主視窗仍會被帶到前景。

### 麵包屑、返回與切換

詳情頁開著時，麵包屑是「專案名 / 頁名 / 項目名」三段。專案名與頁名可點，點了關閉詳情頁回到宿主頁；項目名以等寬字型呈現、不可點。

- 麵包屑左側有返回鈕「←」，名稱是「返回」加頁名（例如「返回規格」），指標停留時提示會標出 Esc 與返回快捷鍵。點了關閉詳情頁。
- 麵包屑右端是 ‹ n／m ›，用來切到同一份清單的上一個或下一個項目。m 是宿主清單目前呈現的項目數（含搜尋與篩選），n 是目前項目的序位。順序就是清單的呈現順序：看板的變更依欄序（提案中、進行中、已就緒）再依欄內順序；看板的討論先上區全卡、再接欄底「已轉出」細列；規格頁與已封存頁的兩節是過濾後的全部頁。宿主不是該項目所屬的清單頁時（從手冊頁開的規格詳情頁、從規格詳情頁溯源開的已封存詳情頁），序列是那份清單未過濾的全部項目。到頭時對應的鈕停用，不會循環；目前項目不在序列裡時整組不出現。切換後頁面從頂端呈現。

例如看板搜尋後提案中欄剩 a、b，進行中欄剩 c，你開啟 b：麵包屑右端顯示「2 / 3」；按 › 切到 c、顯示「3 / 3」且 › 停用；按 ‹ 兩次回到 a 且 ‹ 停用。

| 動作 | macOS | Windows／Linux |
| --- | --- | --- |
| 上一個／下一個項目 | ⌥↑／⌥↓ | Alt+↑／Alt+↓ |
| 返回 | Esc、⌘[、⌘←、滑鼠側鍵「上一頁」、觸控板兩指向右滑 | Esc、Alt+←、滑鼠側鍵「上一頁」 |

快捷鍵以實體按鍵判定，不受輸入法影響。以下情況不作用：

- 焦點在文字輸入（輸入框、多行輸入、可編輯區）時。
- 按鍵已經被浮層（選單、對話框、提示）處理掉時。例如開著「⋯」選單按 Esc，只會關掉選單；再按一次 Esc 才關詳情頁。
- 封存、刪除、退回或討論封存的確認框開著（或確認還在途）時，切換與所有返回操作都不作用，確認框不會被一起收掉。

其他會關掉詳情頁的情況：

- 用專案欄、應用程式選單、系統匣或連線失效橫幅的「重新登入」切到別的頁面時，詳情頁先關閉，再呈現那一頁。例如停在變更詳情頁時點專案欄的「規格」，麵包屑變成「專案名 / 規格」。
- 你正在看的項目被外部刪除（例如用 CLI 刪掉該變更），看板刷新後詳情頁關閉，不會跳錯誤視窗。

**觸控板滑動返回（只有 macOS）**：兩指往返回方向（手指向右）滑動時，主區左緣出現隨滑動距離推出的「←」指示，達到門檻時轉為實心。結算在手指離開觸控板的當下：

| 放開前的手勢（門檻 120px） | 放開時的結果 |
| --- | --- |
| 向右滑 200px 後放開 | 立即關閉詳情頁 |
| 向右滑 80px 後放開 | 指示收回、詳情頁維持 |
| 向右滑 150px，未放開又滑回 80px 後放開 | 指示收回、詳情頁維持 |
| 向右滑 200px 後放開，慣性又捲了 300px | 放開當下就關頁，慣性不影響 |

- 只有觸控板與 Magic Mouse 這類有「手指按下、移動、放開」階段的輸入算數；一般滑鼠滾輪的水平捲動（含按住 Shift）不會觸發。
- macOS 系統設定「在頁面之間滑動」不含兩指滑動（關閉或只用三指）時不會觸發。
- 手指離開後的慣性捲動不會推進指示，也不會開始新的一次滑動。
- 一次手勢裡垂直移動累計超過 10px、且多於水平移動時，整次取消（指示收回、放開也不關頁），等手指離開後的下一次手勢再判定。
- 手勢開始在還能往滑動方向捲動的水平捲動區（例如寬表格、程式碼區塊）時，交給該區塊捲動，不觸發返回。只裁切不捲動的區塊（例如截斷的長名稱）不算。
- 滑動期間整個畫面不會跟著手指水平平移。
- Windows 與 Linux 不提供觸控板滑動返回：水平滑動不顯示指示、不關頁。

### 進場動畫

詳情頁開啟時以 150ms 淡入，並從下方 4px 位移到位；關閉時直接消失，沒有退場動畫。浮層（popover、提示、對話框、選單）沿用元件庫的進出動畫。系統偏好設為減少動態時，這些動畫全部停用，詳情頁與浮層立即出現與消失。動畫不改變焦點、關閉與內容行為。

## 詳情頁的三欄：文件樹、閱讀卡、本頁目錄

變更、討論、已封存三種詳情頁共用同一個三欄骨架，規格詳情頁也採同一套骨架（內容見[規格、討論、已封存與搜尋](desktop-browse.md)）。頁面底部沒有固定列。

**左欄：文件樹**（固定 240px，自己捲動），由上而下是：

- **身分區**：名稱或討論 slug（等寬 14px，過長時折行，不會撐寬欄）、階段籤、一行出身（建立者首字母圓標＋名字、產生工具、建立日、「開工 YYYY-MM-DD」；缺的段整段不出現），以及各自成行的關聯列。變更的關聯列是「來自」（來源討論籤）與「規格」（本變更 delta 涵蓋的能力籤，點了切到規格文件）；討論是 topic（最多三行，溢出截斷）與「關聯」列（先前討論數，點了切到背景文件）。建立者與開工者含 email 的完整識別收在提示裡。身分區不放審查與驗證章，品質關卡由「狀態」列呈現。
- **「文件」節點**：每份文件一個，帶圖示、名稱與徽章。點一下切換閱讀卡，作用中的節點以主色淡底標示。節點不列出文件裡的段落，頁內的段落由本頁目錄負責。
- **「狀態」列**：左標籤、右內容，細線分隔。同一頁的各列共用一個標籤欄，寬度是這一頁最長標籤的寬度，最窄 56px、最寬 112px，超過時標籤在字間折行。不論介面語言，標籤都不會壓到同列的數值，各列數值的左緣對齊。繁中介面的標籤都不超過 56px，標籤欄維持 56px；英文介面例如規格詳情頁的「Requirements」「Provenance」兩列，標籤與數值之間留有間距。變更、討論、規格與已封存詳情頁都照這條規則。

| 詳情頁 | 文件節點（依序） |
| --- | --- |
| 變更 | 提案、設計、任務（徽章 n/m）、規格（delta 計數）、排程（有波次時徽章「第 N 波」）、審查、驗證（後兩者有工單才出現，徽章是末輪序號） |
| 討論 | 結論、討論過程（徽章為輪數）、背景、衍生變更（徽章為數量） |
| 已封存變更 | 提案、設計、任務、規格，以及有工單時的審查、驗證 |
| 已封存討論 | 結論、討論過程、背景、衍生變更 |

已封存詳情頁是同一骨架的唯讀版：身分區帶「已封存」籤與「封存 YYYY-MM-DD」，標題列沒有動作。

**中欄：閱讀卡**。內容欄置中、寬 768px，放一張閱讀卡，由上而下是：

1. **標題區**：24px 一般字重的文件名、籤槽，同一列右端是「開啟 ▾」。
2. **出處行**（灰字），說明這份內容從哪來：變更與已封存變更的文件是相對變更目錄的檔案路徑（例如 `proposal.md`、`specs/<capability>/spec.md`）；排程是「由 speclink plan 推算」；討論的文件是從記錄推導的出處（見[規格、討論、已封存與搜尋](desktop-browse.md)）。
3. **數字磚**：由文件結構推出的計數格，0 到 4 格；推不出時整列不出現。
4. **提示框**。
5. **內文**。

切換文件時閱讀區從頂端開始。

**右欄：本頁目錄**（200px）。從閱讀卡渲染後的標題推出錨點，點一下捲到該段，捲動時高亮目前段；沒有錨點時不出現。視窗寬 1200px 以上才顯示；窄於 1200px 時隱藏，左欄照常、閱讀卡維持置中，頁面不出水平捲軸。

| 文件 | 本頁目錄列出 |
| --- | --- |
| 提案、設計 | 章節標籤 |
| 任務 | 群組標題 |
| 規格（delta） | 色標區段標頭與需求標題 |
| 排程 | 四張卡的標題 |
| 審查、驗證 | 輪次標題 |
| 結論 | 欄位區段標題（含「分刀」） |
| 討論過程 | 輪次籤，依畫面順序由新到舊 |
| 背景 | 三個區段標題 |
| 衍生變更 | 分刀組頭 |

例如提案含 Why、What Changes、Impact 三章，本頁目錄列出「為什麼」「變更內容」「影響」；捲到「影響」時它高亮，點「為什麼」閱讀區捲回該章。

詳情頁裡的定位捲動（手動任務提示框的「前往」、「下一個未完成」、本頁目錄、D 籤跳轉）只捲閱讀區。頁面外框（主區標題列、左欄文件樹、閱讀區的上下緣）不會位移，主區底部不會露出空白。

### 文件載入

每份文件分三種狀態：載入中畫文件的灰色佔位方塊（標題條加幾行內文條）；載入完成但檔案不存在，才顯示該文件的空狀態文案；有內容就直接呈現。載入中不會出現「無文件」之類的文案。點文件節點時，節點立刻變成作用中、閱讀卡標題立刻換成該文件名，內文還沒到就先畫佔位方塊。

### 不出水平捲軸

詳情頁不會出現水平捲軸：不論身分區的標記、標題列的動作或內文裡有多長的單一元素，左欄、標題列與閱讀卡都留在可視寬度內。變更與已封存變更的來源討論標記以 slug 直出（等寬），topic 不直出；slug 超過寬度上限時截斷，指標停留時的提示顯示完整 slug 與 topic，點標記開啟該討論。多份來源討論不會各自換行，只直接顯示第一份，其餘收進「+N」籤（見[規格、討論、已封存與搜尋](desktop-browse.md)）。

## 「開啟 ▾」選單

變更、討論、規格詳情頁與手冊頁的閱讀卡標題列右端有「開啟 ▾」（外框樣式，與標題同列），對目前文件對應的檔案提供三個動作：以預設 App 開啟、在 Finder 顯示（Windows 為「檔案總管」、Linux 為「檔案管理員」）、複製路徑。選單第一列以等寬灰字顯示檔案相對 checkout 根的路徑。

| 文件 | 對應的檔案 |
| --- | --- |
| 提案、設計、任務 | `openspec/changes/<名稱>/` 底下的 `proposal.md`、`design.md`、`tasks.md` |
| 變更裡的規格 | `specs/<capability>/spec.md`（目前選定的能力） |
| 審查、驗證 | `review.md`、`verify.md` |
| 討論的各文件 | 該討論的記錄檔 |
| 規格詳情頁 | `openspec/specs/<capability>/spec.md` |
| 手冊頁 | `openspec/manual/<檔名>.md` |

- 檔案位置與詳情頁讀內容的位置相同：綁定 worktree 的變更指向 worktree 裡的那一份；規格目錄名依專案設定；已封存的討論指向 `openspec/discussions/archive/<封存日>-<slug>.md`。已封存頁開啟的封存討論詳情頁例外，只有「複製內容」，見[規格、討論、已封存與搜尋](desktop-browse.md)。
- 沒有對應檔案的文件（排程、規格詳情頁的溯源）不顯示選單。
- remote 專案沒有本機 checkout 時，選單只有「複製內容」（複製該文件已載入的原文，還沒載完時停用），也沒有路徑首列；審查與驗證工單在這種情況下不載原文，所以不顯示選單。
- 「以預設 App 開啟」只開 markdown 檔：檔名與符號連結的實際指向都必須是 markdown。
- 動作失敗（例如檔案已被外部刪除）時，以失敗浮層提示呈現錯誤，詳情頁維持開啟，不跳錯誤視窗。
- 「開啟 ▾」不會出現在主區標題列，也不會收進「⋯」選單。

例：本機專案 `/work/app` 的變更 add-auth，在提案文件展開「開啟 ▾」，首列是 `openspec/changes/add-auth/proposal.md`；選「複製路徑」，剪貼簿是 `/work/app/openspec/changes/add-auth/proposal.md`。若 add-auth 綁定 worktree `/work/app-wt/add-auth`，在任務文件選「在 Finder 顯示」，Finder 顯示的是 `/work/app-wt/add-auth/openspec/changes/add-auth/tasks.md`。

## 外部變更即時反映

app 會監看目前專案的規格目錄樹。CLI、agent 或編輯器改了底下任何檔案，看板、各詳情頁與已封存頁會在幾秒內自動更新。已經開著的內容也會重載到磁碟現況：任務清單的勾選狀態、提案／設計／規格原文、開工歸屬、討論記錄的各文件。你不需要重啟、重開詳情頁或做任何操作。

| 你在外部做了什麼 | 數秒內畫面的變化 |
| --- | --- |
| `speclink task done` 勾掉一項任務 | 卡片的任務數與進度條更新；詳情頁開著時，計數與該項的勾選框同步 |
| `speclink in-progress add` 某變更 | 詳情頁出現開工者與開工日 |
| `speclink discuss add-round` 某討論 | 討論詳情頁出現新的一輪，輪數一致 |
| 建立新變更，再封存另一個 | 看板出現新卡；被封存的從看板消失、出現在已封存頁 |

- 你正在勾任務或拖曳時，外部觸發的重載會讓路，互動結束後補做一次重載。進行中的操作不會被打斷或蓋掉。重載回應交錯時以最新一次為準。
- app 內的操作（勾任務、拖曳、動詞）完成後，也會重載受影響的內容。
- app 從專案的子目錄啟動時（例如從檔案總管雙擊執行檔），監看照常生效：app 用和查詢指令相同的方式向上找到專案根，並監看實際的規格目錄，即使目錄名不是預設值。
- 監看建立不了時（例如檔案系統權限，或根本不在任何專案裡），其餘功能照常，只是失去自動刷新。錯誤只寫進日誌，畫面不會彈錯誤視窗。

## 載入中與載入失敗

- **第一次進入某個專案**：看板欄名照常顯示，卡片區以灰色佔位方塊呈現。載入完成後換成真資料；專案真的沒內容時，顯示空狀態文案。系統偏好減少動態時，佔位方塊的動畫停用。
- **之前來過的專案**：直接顯示上次的資料，重載完成後靜默更新，不會閃佔位方塊。
- **第一次載入就失敗**（例如離線或目錄不可讀）：卡片區顯示載入失敗提示，與空專案的空狀態可區分。下一次載入成功後提示消失。切走再切回時，重試期間先顯示佔位方塊，再度失敗則回到失敗提示。
- **已有舊資料的專案重載失敗**：照常顯示最後一次成功的資料，不顯示失敗提示。

詳情頁文件的載入見上方「文件載入」，切換專案的轉圈圖示見「圖示列與專案欄」。

凡是會讀檔或呼叫 git 的工作都在背景執行。引擎讀取耗時（例如 agent 同時在同一個 repo 操作）時，主視窗與系統匣仍可互動，資料以載入中狀態呈現，不會整窗凍結。

## 操作回饋：成功靜默，失敗浮層

看板的全域操作成功時不顯示任何文字訊息，結果由畫面本身表達。失敗時 app 以浮層提示（toast）呈現失敗訊息。

| 操作 | 成功時你看到 | 失敗時浮層內容 |
| --- | --- | --- |
| 刪除變更 | 卡片消失、詳情頁關閉 | `<變更名稱> · 刪除失敗 ✗ <core 錯誤>` |
| 封存變更 | 卡片消失、「已封存」計數加一、詳情頁關閉 | `<變更名稱> · 封存失敗 ✗ <core 錯誤>` |
| 封存討論 | 卡片消失、詳情頁關閉 | `<討論 slug> · 討論封存失敗 ✗ <core 錯誤>` |
| 拖排卡片 | 卡片位於新位置 | `<卡片識別> · 排序寫回失敗 ✗ <core 錯誤>` |
| 開啟專案 | 切換至該專案 | `<選定路徑> · 開啟專案失敗 ✗ <core 錯誤>` |
| 初始化專案 | 進入該專案 | `<選定目錄> · 初始化失敗 ✗ <core 錯誤>` |

浮層提示的規則：

- 訊息包含操作對象與引擎回報的原始錯誤，不改寫、不吞掉。
- 浮層疊在詳情頁與確認對話框之上。詳情頁開著時發生失敗，浮層仍完整可見，詳情頁維持開啟。
- 浮層在固定時距後自動消失，也可按關閉鈕提前關閉。同時只有一則；新訊息取代前一則並重新計時。
- 浮層的外觀沿用介面本身的配色：卡片底色與可讀的文字色，錯誤圖示與邊框用危險色；跟著系統的淺色／深色模式切換。
- 失敗後看板刷新回磁碟現況，不保留未落檔的假象。
- 封存變更成功時，詳情頁會關閉回看板。詳情頁開著時看不到看板，關掉它，「成功靜默」才看得到結果。

> [!NOTE]
> 開啟專案失敗時，目前專案維持不變。浮層會顯示你選的路徑與失敗原因。

## 顏色、字型與排版

**狀態語意色**依意義上色，主題主色不用來表達狀態：

| 顏色 | 意義 | 例子 |
| --- | --- | --- |
| 藍 | 進行中 | 專案還原中、遷移進行中、更新下載中、看板卡片的 worktree 標示 |
| 綠 | 成功 | 遷移完成 |
| 琥珀 | 警示 | 登入過期、需要重新認證、政策衝突、待重新反映 |
| 紅 | 錯誤與危險動作 | 專案錯誤、更新檢查失敗、設定檔解析錯誤、remote 專案拒絕存取、找不到或未知錯誤 |
| 暖黃 | 待手動 | 看板的「待手動」章、任務列的手動徽章與淡底、手動任務提示框 |
| 紫 | 品質關卡蓋章專屬 | 「已審查」章（見[桌面上的品質關卡](desktop-quality.md)） |

暖黃與琥珀是兩個不同的色相，待手動不會用琥珀或藍；錯誤不會用琥珀；靜態小標與裝飾面是中性色。審查的其他三種狀態維持藍（審查中）、琥珀（已審查·其後有變動）、紅（曾審查未通過）；紫色只出現在品質關卡的蓋章。

**生命週期與討論的色相**，看板與系統匣面板共用：

| 欄位／分區 | 色相 |
| --- | --- |
| 討論 | 桃紫 |

看板的欄頂條、欄標頭圖示、欄計數徽章、卡片波次章，以及系統匣面板的對應分區，都取所在階段的色相。琥珀、紅與紫不用在任何生命週期或討論的欄位。主色另外保留給複製成功的勾號，以及可點的連結籤與導航元素。

**字型**：介面與內容文字使用隨 app 打包的 Noto Sans TC。沒安裝這個字型的機器與離線環境看到的字型相同，app 不從網路下載字型。行內程式碼與程式碼區塊維持等寬字型；變更名稱、討論 slug、分支名與路徑也以等寬字型呈現。所有截斷的省略號都是同一字形（拉丁半形、貼基線），等寬名稱與中文文字截斷時看起來一致；找不到可用字型時退回原本的字型，不會缺字。

**文件排版**（變更、討論、已封存、規格詳情頁與手冊頁的閱讀卡）：

- 無序清單有列表符號，有序清單有編號，段落之間有可辨識的間距，來源中的單一換行呈現為換行。
- 內文 15px、行高 1.75 倍，任務列文字也是 15px。手冊頁內文的二級標題 16px 粗體、三級標題 14px 粗體。
- 淺色與深色主題跟隨系統偏好，排版與色彩在兩種主題下一致。
- 行寬上限是閱讀卡（768px）扣掉內距後的內容欄寬。章節標題、數字磚、提示框、群組卡、輪卡、需求段與內文都在同一欄對齊。視窗拉寬時行寬不變，閱讀卡置中、兩側留白均分。
- 數字磚依格數平分整列：3 格各佔三分之一，4 格各佔四分之一，只有 1 格就佔滿整列，不會固定成四欄留下空格。
- 超過行寬的表格在容器內橫向捲動，頁面不會橫向溢出。
- 來源裡的 raw HTML（含 HTML 註解）不會以原文出現；程式碼區塊裡的 HTML 原文照常顯示。渲染不改任何來源檔案。

**控制項**：任務的勾選框與初始化對話框的工具多選（claude、codex）是主題化外觀：未勾為主題邊框空框，已勾為主色底加勾號，不是作業系統原生樣式。專案設定裡專案說明與產出規則的編輯區，邊框、底色、游標行、語法上色與 focus 樣式都取自介面主題，深色主題下是深色值。按鈕外觀一致，用 Tab 聚焦時有一致的 focus 環，停用時的樣子也一致。勾選框保留原本的無障礙語意，可用空白鍵切換，效果與滑鼠點擊相同；已封存檢視的勾選框不可操作。

**游標與滑過回饋**：主視窗與系統匣面板裡的可點元素（按鈕與圖示鈕、清單列、看板卡片、收合卡頭、名稱籤與關聯籤、文件樹節點、專案欄與設定分類欄的導覽列、選單項與下拉選項）滑過時維持箭頭游標，不會變成手指。可點性改用滑過時的底色表示：整列、卡頭與沒有外框的元素出現淡淡的底色；自帶底色的籤與按鈕換成另一個看得出來的底色，例如規格詳情頁「溯源」列的「+N」籤由灰底換成主色淡底。

- 例外：Markdown 正文裡的超連結維持手指游標；拖曳把手、文字輸入與調整尺寸各維持自己的游標。
- 停用或唯讀的元素（停用的按鈕、停用的選擇卡與最近開啟列、已封存變更與批次寫回中的任務列、不可開啟的列與籤）是箭頭游標、沒有滑過底色，也不會顯示禁止游標。

**提示**：指標停在有提示的元素上 300ms 後才顯示；在同一群組內連續移動時，後續提示立即顯示。看板卡片的章與詳情頁的章籤都是同一個延遲。系統匣面板的原生提示不受此規則約束。
