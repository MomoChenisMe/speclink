# 認識桌面 app

桌面 app 是 Speclink 的圖形操作面。它讀的是你專案裡 `openspec/` 底下的檔案，和 CLI 看的是同一份資料。這一頁先帶你認識畫面骨架、詳情面板、即時更新與回饋規則。看板與任務的操作請看[看板與任務](desktop-board.md)。

## 它是什麼

- **引擎直接內嵌**。app 不會另外啟動 CLI 子程序，所有畫面資料都由內嵌引擎讀檔取得。
- **本地檔案是唯一真相**。app 不會把變更或規格的內容搬到別的地方存放。你用 CLI、agent 或編輯器改檔案，畫面就跟著變。
- **和 CLI 同一套語意**。清單與狀態的欄位和值，與 `speclink list`、`speclink status` 的輸出對應。畫面上勾任務，效果與 `speclink task done` 相同。
- **動詞經內嵌引擎執行**。對變更可執行狀態查詢、分析（結構驗證加分析）與封存；對專案可列出清單與顯示內容。成功與失敗的結果都與 CLI 一致，失敗訊息不會被吞掉。

在一個不含 Speclink 專案標記的資料夾啟動 app，畫面會顯示「非 speclink 專案」的空狀態。app 不會崩潰，也不會堆出錯誤彈窗。

## 畫面骨架

視窗以 1440×900 的邏輯尺寸啟動，並在主螢幕置中。app 不記憶上次的視窗大小與位置，每次啟動都一樣。

側欄有六個導覽項，分成兩群。頂部群組由上而下是「變更」「已封存」「規格」「手冊」；底部群組固定在側欄底部，由上而下是「專案設定」「設定」，兩群之間留彈性空白。側欄沒有備忘項，也不顯示版號；版號在應用程式設定頁的軟體更新卡（見[自動更新、安裝 CLI 與指令檔過期](desktop-update.md)）。

- 「已封存」導覽項帶一枚徽章，顯示封存變更的數量。數字隨封存動作即時更新。
- 「手冊」導覽項進入手冊頁，見[桌面 app 的手冊頁](desktop-manual.md)。
- 點導覽項只是切頁。再點一次同一項不會跳回看板。底部群組沉底不改變它們的高亮與切頁行為。
- 頂欄不放「已封存」入口，也不放任何操作結果訊息。
- 還沒開任何專案分頁時，點「設定」照常進入應用程式設定頁；點「變更」「已封存」「規格」「手冊」「專案設定」則看到空狀態引導頁。六個導覽項永遠都在。

專案分頁、新增工作區與兩個設定頁的操作，請看[專案分頁、新增工作區與設定頁](desktop-projects.md)。

## 詳情面板的規則

桌面 app 有四種詳情面板：變更詳情、規格、封存、討論。

- **同時只開一個**。任一詳情面板開著時，從任何入口（看板卡片、規格清單、已封存頁、系統匣、詳情面板內跳轉）開另一種詳情面板，先開的會關閉，由後開的取代。不會疊加，也不會拒開。
- **變更詳情與討論詳情面板開啟時，底層頁面切回看板**。不論你是從規格頁、已封存頁、專案設定頁或系統匣開的，關掉詳情面板後看到的都是看板。
- **規格詳情面板與封存詳情面板不切頁**。它們的宿主頁面就是規格頁與已封存頁。
- 四種詳情面板的寬度與全螢幕切換一致。詳情面板不會出現水平捲軸：標頭、動作列與內文都留在可視寬度內。
- **開關有動畫**。詳情面板開啟時從右側滑入、遮罩淡入；關閉時反向滑出、遮罩淡出，動畫結束後才移除。浮層（popover 與提示）用同一套進出動畫。系統偏好設為減少動態時，這些動畫全部停用，面板與浮層立即出現與消失。動畫不改變面板的焦點、關閉與內容行為。

## 外部變更即時反映

app 會監看目前專案的 `openspec/` 目錄樹。CLI、agent 或編輯器改了底下任何檔案，看板、詳情面板、討論詳情面板與已封存頁會在幾秒內自動更新。已經開著的內容也會重載到磁碟現況：任務清單的勾選狀態、提案／設計／規格原文、開工歸屬、討論記錄各分頁。你不需要重啟、重開詳情面板或做任何操作。

- 你正在勾任務或拖曳時，外部觸發的重載會讓路。互動結束後 app 補做一次重載。進行中的操作不會被打斷或蓋掉。
- app 內的操作（勾任務、拖曳、動詞）完成後，也會重載受影響的內容。
- app 從專案的子目錄啟動時（例如從檔案總管雙擊執行檔），監看照常生效。app 會向上找到專案根，並監看實際的規格目錄，即使目錄名不是預設值。
- 監看建立不了時（例如檔案系統權限），其餘功能照常，只是失去自動刷新。錯誤只寫進日誌，畫面不會彈錯誤視窗。

## 載入中與載入失敗

- **第一次進入某個工作區**：欄名照常顯示，卡片區以灰色佔位方塊呈現。載入完成後換成真資料；工作區真的沒內容時，顯示空狀態文案。
- **之前來過的工作區**：直接顯示上次的資料，重載完成後靜默更新，不會閃佔位方塊。
- **第一次載入就失敗**（例如離線或目錄不可讀）：卡片區顯示載入失敗提示，與空工作區的空狀態可區分。下一次載入成功後提示消失。切走再切回時，重試期間先顯示佔位方塊，再度失敗則回到失敗提示。
- **已有舊資料的工作區重載失敗**：照常顯示最後一次成功的資料，不顯示失敗提示。
- **詳情面板的文件分頁**：載入中顯示文件佔位方塊；載入完成且檔案不存在時，才顯示該分頁的空狀態文案；有內容就直接呈現。載入中不會出現「無文件」之類的文案。
- **切換專案分頁**：點非活躍的本地分頁後，目標分頁立刻出現切換中的轉圈圖示，原畫面照常可用。探測成功才翻頁；失敗則分頁以錯誤樣式呈現，活躍分頁不變。

凡是會讀檔或呼叫 git 的工作都在背景執行。引擎讀取耗時（例如 agent 同時在同一個 repo 操作）時，視窗與系統匣仍可互動，資料以載入中狀態呈現，不會整窗凍結。

## 操作回饋：成功靜默，失敗浮層

看板的全域操作成功時不顯示任何文字訊息，結果由畫面本身表達。失敗時 app 以浮層提示（toast）呈現失敗訊息。

| 操作 | 成功時你看到 | 失敗時浮層內容 |
| --- | --- | --- |
| 刪除變更 | 卡片消失、詳情面板關閉 | `<變更名稱> · 刪除失敗 ✗ <core 錯誤>` |
| 封存變更 | 卡片消失、「已封存」計數加一、詳情面板關閉 | `<變更名稱> · 封存失敗 ✗ <core 錯誤>` |
| 封存討論 | 卡片消失、詳情面板關閉 | `<討論 slug> · 討論封存失敗 ✗ <core 錯誤>` |
| 拖排卡片 | 卡片位於新位置 | `<卡片識別> · 排序寫回失敗 ✗ <core 錯誤>` |
| 開啟專案 | 切換至該專案 | `<選定路徑> · 開啟專案失敗 ✗ <core 錯誤>` |
| 初始化專案 | 進入該專案 | `<選定目錄> · 初始化失敗 ✗ <core 錯誤>` |

浮層提示的規則：

- 訊息包含操作對象與引擎回報的原始錯誤，不改寫、不吞掉。
- 浮層疊在詳情面板與確認對話框之上。詳情面板開著時發生失敗，浮層仍完整可見，詳情面板維持開啟。
- 浮層在固定時距後自動消失，也可按關閉鈕提前關閉。同時只有一則；新訊息取代前一則並重新計時。
- 失敗後看板刷新回磁碟現況，不保留未落檔的假象。
- 封存變更成功時，詳情面板會關閉。

> [!NOTE]
> 開啟專案失敗時，目前專案維持不變。浮層會顯示你選的路徑與失敗原因。

## 顏色、字型與文件排版

**狀態語意色**依意義上色，主題主色不用來表達狀態：

| 顏色 | 意義 | 例子 |
| --- | --- | --- |
| 藍 | 進行中 | 分頁還原、遷移進行、更新下載、卡片的 worktree 標示 |
| 綠 | 成功 | 遷移完成 |
| 琥珀 | 警示 | 登入過期、需要重新認證、政策衝突、待重新反映 |
| 紅 | 錯誤與危險動作 | 分頁錯誤、更新檢查失敗、設定檔解析錯誤、遠端工作區拒絕存取或找不到 |
| 紫 | 品質關卡蓋章專屬 | 「已審查」「已驗證」章（見[桌面上的品質關卡](desktop-quality.md)） |

主色只保留給三種東西：生命週期階梯（提案中／進行中／已就緒的深淺，看板欄與系統匣共用）、複製成功的勾號、可點的連結籤與導航元素。靜態小標、計數徽章與裝飾面為中性色。錯誤不會用琥珀色呈現。

**字型**：介面與內容文字使用隨 app 打包的 Noto Sans TC。沒安裝這個字型的機器與離線環境看到的字型相同，app 不從網路下載字型。等寬字型用於變更名稱、討論 slug、分支名、路徑、行內程式碼與程式碼區塊。所有截斷的省略號都是同一字形（拉丁半形、貼基線）。

**Markdown 內容**（提案／設計／規格分頁、討論詳情面板各分頁、已封存檢視）保留文件結構：

- 無序清單有列表符號，有序清單有編號，段落之間有可辨識的間距，來源中的單一換行呈現為換行。
- 內文基準字級 16px，任務分頁的任務文字也是 16px。
- 淺色與深色主題跟隨系統偏好，排版與色彩在兩種主題下一致。
- 來源裡的 raw HTML（含 HTML 註解）不會以原文出現；程式碼區塊內的 HTML 原文照常顯示。渲染不改任何來源檔案。
- 內文行寬有固定上限。詳情面板切到全螢幕時行寬不變，內容欄置中、留白均分。超過行寬的表格在容器內橫向捲動。

**控制項**：勾選框、多行輸入與按鈕都用主題化外觀，不是作業系統原生樣式。勾選框未勾為主題邊框空框、已勾為主色底加勾號。用 Tab 聚焦按鈕時有一致的 focus 可視環；勾選框可用空白鍵切換，效果與滑鼠點擊相同。

**提示**：把指標停在有提示的元素上 300ms 後才顯示提示；同一群組內連續移動時後續提示立即顯示。系統匣面板的原生提示不受此規則約束。
