# 操作手冊：生成與導覽

你正在讀的這份手冊，就是 `/speclink-manual` 技能從正典規格生成的。這一站有兩種用法：**生成**手冊頁到 `openspec/manual/`，或在對話裡**導覽**你怎麼操作系統。這一頁講技能怎麼分流、手冊只取材自什麼、頁面長什麼樣、什麼時候該重生。

## 兩種模式，由引數決定

| 你怎麼呼叫 | 模式 |
| --- | --- |
| `/speclink-manual` | 生成：讀規格，寫 `openspec/manual/` 底下的頁 |
| `/speclink-manual 導覽`（或 `tour`） | 導覽：不寫任何檔案，在對話裡帶你走一遍 |
| `/speclink-manual <其他文字>` | 生成，但把文字當範圍提示（例如只重生某個分區或某一頁）。摘要開頭會覆述技能理解的範圍 |

## 手冊只取材自正典規格

生成模式的內容來源只有 `openspec/specs/` 底下的正典規格。技能先取得全部 capability 的清單，再讀每個 capability 的 Purpose，把它們分成兩類：

- **使用者面向**：你會操作或看到的東西（畫面、指令、技能、輸出、檔案）。進手冊。
- **引擎內部**：儲存、wire 契約、host 執行期、測試骨架、建置與發布管線。不進手冊。

Purpose 是空的、或還是佔位文字時，技能改用該 capability 的需求標題來判斷。

README、`docs/` 目錄與程式碼都不是內容來源。規格沒寫的，手冊就不寫。每一頁末行列出它取材的 capability。

**旅程的骨幹**依序取自：驗收劇本型規格、技能交棒表型規格、使用者文件型規格。三種都沒有時，技能按功能領域從使用者面向的規格重建旅程，並在 about 頁載明屬「重建」；有劇本時 about 頁載明「轉寫自」哪些規格。about 頁也列出規格內部新舊描述不一致的地方，技能不會自己裁決矛盾。

## 第二次以後：只重生受影響的頁

手冊已存在時，技能預設只做三件事：重生「可能過期」的頁、替「未入冊」的能力新增頁、重寫 index 與 about 兩頁。其餘頁逐位元不變。你明示要求（例如「全部重生」）時才會全量重生。

| 名詞 | 意思 |
| --- | --- |
| 可能過期的頁 | 頁的 sources 裡任一 capability，其規格內最新的更新日期不早於（晚於或同一天）該頁的生成日 |
| 未入冊的能力 | 被判為使用者面向、卻沒有出現在任何頁的 sources 裡 |
| 來源已消失的頁 | sources 非空，但所列規格全部已經不在正典裡。技能只回報，不刪頁 |

> [!NOTE]
> 過期判定只比到「日」。生成當天封存的規格，一律算在生成之後。所以同一天生成又封存，那一頁會被判為可能過期，即使內容其實已經是最新。技能重生時發現內容沒有變化，就不會重寫那一頁。

沒有過期頁、也沒有未入冊能力時，技能一個檔案都不寫，並如實回報手冊已是最新。

結束時技能在對話裡輸出摘要：新增、重生、未動的頁數；可能過期的頁；未入冊的能力；about 頁記錄的矛盾數。摘要末尾建議你用一般 git 提交收尾手冊異動。這只是建議，技能不代跑。

## 導覽模式

導覽模式不寫任何檔案。

- **有手冊**：技能讀每一頁的 frontmatter 當索引，先問你一個問題確認角色，再依分區與順序帶你走。每個回答都附出處：capability 名或手冊頁名。
- **沒有手冊**：技能明說「尚無手冊，改以規格直接導覽」，改用規格清單與規格內容作答。

導覽結束時技能可能建議你跑生成模式產出手冊。這只是建議，技能不會自動呼叫其他技能。

## remote 模式的限制

專案綁定 remote store（`.speclink.yaml` 有 remote 區段）時，生成模式會明示 remote 模式尚不支援手冊生成，然後停止，零檔案寫入。導覽模式不受這條限制。remote 模式的說明見[remote 模式總覽](remote-overview.md)。

## 手冊頁長什麼樣

每一頁都是 `openspec/manual/` 底下的一個 Markdown 檔。檔名是 kebab-case 的 ASCII 英文（例如 `first-login.md`），不含空白、大寫或非 ASCII 字元。技能只寫這個目錄。

每頁開頭是 YAML frontmatter，恰好這六欄：

| 欄位 | 必填 | 意思 |
| --- | --- | --- |
| title | 是 | 頁的標題 |
| section | 是 | 側欄分區名 |
| order | 是 | 全手冊唯一的排序號，慣例間隔 10 |
| keywords | 否 | 搜尋用的關鍵字 |
| sources | 是 | 本頁取材的 capability。只有首頁與來源頁可以是空的 |
| generated | 是 | 本頁最近一次生成的日期 |

頁的順序只看 order；分區的順序看分區內最小的 order。

內文用 GitHub Flavored Markdown。提示框用 GitHub Alert 語法（NOTE、TIP、WARNING、CAUTION 四種）。跨頁連結用相對檔名。每頁最後一個非空段落是「**出處**：」開頭的出處行，列出與 sources 相同的 capability。內文不含 HTML 標籤，也不出現內部欄位名與旗標，除非那是你實際會輸入的指令或技能名。

每份手冊一定有兩頁：

- `index.md`：手冊名、系統的一句話定位、三個以內的核心概念、依角色分流的入口連結。order 是全手冊最小。
- `about.md`：標題「本手冊的來源」，載明取材範圍、旅程骨幹、規格內部的矛盾清單（沒有時寫「未發現」）、已知侷限與編成日期。order 是全手冊最大。

兩頁是衍生頁：任何其他頁新增或重生時它們跟著重寫，不會被判為過期或未入冊。沒有任何使用者面向的能力時，手冊只有這兩頁，about 頁寫「尚無可入冊的使用者面向能力」。

## 重生時順序不會亂

- 檔名已存在的頁，section 與 order 逐字保留，除非你明示要求重排。
- 新頁的 order 取相鄰頁之間的整數（20 與 30 之間填 25），既有頁不重編。
- 相鄰序號之間沒有整數可填（包括新頁得排在 about 頁之後）時，技能不會自作主張重排。那一頁留到下一輪，並在報告裡列出，等你明示要求重排。
- 沒被重生的頁逐位元不變。

## 在哪裡讀

手冊頁是一般的 Markdown 檔，用任何編輯器都能讀。桌面 app 也能讀，見[桌面 app 的手冊頁](desktop-manual.md)。
