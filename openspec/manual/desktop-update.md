# 自動更新、安裝 CLI 與指令檔過期

桌面 app 會自己保持三樣東西是新的：app 本體、隨 app 附的 CLI，以及每個專案裡的技能檔。這一頁說明三者各自怎麼運作、你會看到什麼提示。

## 自動更新 app

app 啟動後在背景查一次 GitHub Releases 有沒有新版。你也可以手動按「檢查更新」。

- 有新版：app 顯示目標版本，徵得你同意才下載套用，不會靜默安裝。套用後提示重新啟動，重啟後跑的就是新版。
- 已是最新：手動檢查時介面顯示已是最新，不出現下載動作。
- 檢查失敗（離線、更新端點連不上）：啟動時完全靜默，不擋啟動、不彈錯誤。只有手動檢查才會顯示「無法檢查更新」。
- 更新包簽章驗證不過：app 拒絕安裝並顯示更新失敗錯誤，原本的安裝不受影響。

## 安裝 CLI 指令到 PATH

app 內建一份 CLI。安裝 CLI 的介面會顯示目前狀態：未安裝、已安裝（含版本）、版本不符。已安裝且版本一致時不會重複佈署。安裝後在終端執行 `speclink --version`，版本會與 app 一致。

佈署方式依平台不同：

| 平台 | CLI 落在哪 | 何時自動處理 |
| --- | --- | --- |
| macOS | `~/.local/bin` 下指向 app 內 CLI 的 symlink | 每次啟動偵測到未安裝或版本不符就自動建立或重建 |
| Windows | 安裝器把安裝目錄加進使用者 PATH | app 內只顯示狀態 |
| Linux deb | `/usr/bin/speclink` | 由套件管理器處理 |
| Linux AppImage | 複製到 `~/.local/bin` | 啟動偵測到版本不符就自動重新複製 |

PATH 的處理：

- macOS：`~/.local/bin` 不在 PATH 時，app 自動在 `~/.zprofile` 追加一行 PATH 匯出，帶識別註解。只在缺席時寫一次，重複啟動不會重複追加。
- Linux：佈署目錄不在 PATH 時，介面提示你要把哪個目錄加進 PATH，以及加入方式。

佈署失敗不會擋 app 啟動。

> [!WARNING]
> macOS 上 app 每次啟動都會檢查 `~/.local/bin` 的 speclink。版本不符就重建成指向內建 CLI 的 symlink。你自己裝在同一位置的 CLI 會被取代。保留自有 CLI 的做法見 [安裝 CLI 與桌面 app](install.md)。

## 指令檔過期提示

每個專案的技能檔（各 AI 工具 skills 目錄下 speclink- 開頭的技能）帶一個產物層版號，與引擎同源。app 升版後，專案裡的技能檔可能就舊了。

### 什麼時候探測

app 在本地專案分頁成為作用中時探測一次。更新動作完成後，以及專案檔案有外部變動時，再探測一次。remote 工作區分頁不探測、不提示。探測只讀不寫。

探測比對 `.speclink.yaml` 列出的每個工具，結果是五種之一：

| 結果 | 意思 |
| --- | --- |
| 缺失 | 某個工具的 skills 目錄下一個 speclink- 技能都沒有。可能從沒裝過，或整組被移除，例如 clone 後技能檔沒進版控 |
| 過期 | 某個工具的技能版號舊於引擎現版 |
| 較新 | 某個工具的技能版號新於引擎現版，也就是專案檔案領先 app |
| 現版 | 全部一致 |
| 無法判定 | `.speclink.yaml` 解析失敗，或技能檔存在但讀不了 |

有多個工具時以「較新 > 缺失 > 過期 > 現版」取最嚴重的一個回報。現版與無法判定都不提示。無法判定不會被當成現版，也不會記入略過。

### 提示長什麼樣

提示出現在分頁內容頂部，不擋操作、不是彈窗。頁面往下捲時提示釘在可視區頂部、底色不透明。依探測結果有三種：

- 過期：主動作是「更新」，內容寫出將被改寫的檔案數。
- 缺失：主動作是「安裝」，內容寫出將被新建或改寫的檔案數。從沒裝過的專案不會被稱為「更新」。
- 較新：提示以「app 本體是舊版、專案檔案較新」的語意呈現，引導你更新 app。這時沒有「更新」也沒有「安裝」，只有「保留現狀」。app 不會用舊版內容改寫領先的專案檔案。

每種提示都有「保留現狀」。按下後，app 把這個專案與目前的產物層版號記在 app 本機，不寫進專案。同一版號不再問。app 升版、版號變了才會重新提示。

按「更新」或「安裝」時，app 用引擎的再生入口把受管檔整套再生。成功後提示消失。失敗時錯誤顯示在提示原位，可以重試，專案其他功能照常。

你在終端執行 `speclink update` 把技能檔更新到現版時，app 偵測到檔案變動後重新探測，提示自己消失，不用重開分頁。

> [!NOTE]
> 桌面 app 的過期提示規格（較舊）以 CLAUDE.md 是否存在、SPECLINK 標記是否被移除為例。較新的工作區工具規格把判定基準改為 skills 目錄下的技能檔。本頁採較新版本。詳見 [本手冊的來源](about.md)。

### 只更新、不降級

引擎的再生入口在寫入前先判方向。專案技能檔版號領先引擎現版時，再生一律拒絕：一行英文說明（含專案的版號與引擎的版號）、不寫任何檔案。這條守門對 `speclink update`、`speclink init --force`、設定頁改工具或改政策後的技能同步、桌面的更新動作一體適用。`--force` 不代表同意降級。唯一的明示越過入口是：

```
speclink update --allow-downgrade
```

## 版號怎麼看

```
speclink --version
```

輸出一行：套件版號、架構、引擎的產物層版號，例如 `0.1.0 (arm64, engine v1.14.0)`。技能檔開頭的版本欄位就是這個引擎版號。同一次生成的所有技能檔版號相同。這個版號只在內嵌資產內容變動時遞增，不隨 app 或 CLI 發版自動變。

CLI 端 `speclink update` 的其他行為（孤兒技能目錄清理、worktree 技能的條件式生成）見 [建立工作區與指令檔](init-workspace.md)。
