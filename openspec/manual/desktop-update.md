# 自動更新、CLI、技能檔過期與關於頁

桌面 app 會自己保持三樣東西是新的：app 本體、隨 app 附的 CLI，以及每個專案裡的技能檔。這一頁說明三者各自怎麼運作、你在哪裡看到提示，以及應用程式設定裡「更新」「CLI」「關於 Speclink」三頁各有什麼。應用程式設定怎麼進、其他分類頁見[專案、新增專案與設定頁](desktop-projects.md)。

## 自動更新 app

app 啟動後在背景查一次 GitHub Releases 有沒有新版。你也可以到應用程式設定的「更新」頁按「檢查更新」手動查。

- 有新版：app 顯示目標版本，徵得你同意才下載套用，不會靜默安裝。
- 已是最新（手動檢查時）：「最新版本」列顯示目前版本加「已是最新」，不出現「下載與安裝」卡，圖示列沒有更新鈕，也不跳 toast。
- 檢查失敗（離線、更新端點連不上）：啟動時完全靜默，不擋啟動、不彈錯誤、圖示列沒有更新鈕。只有手動檢查才在「最新版本」列顯示「無法檢查」。
- 更新包簽章驗證不過：app 拒絕安裝，圖示列的更新鈕轉為紅色警示，更新頁「下載與安裝」卡顯示更新失敗錯誤與「重試」。原本的安裝不受影響。

### 有新版時你會看到什麼

視窗頂端不會出現更新橫幅。提示改由圖示列底部、設定齒輪上方的更新鈕負責，只有下面四種狀態會出現：

| 狀態 | 更新鈕 | 滑鼠停留的提示 |
| --- | --- | --- |
| 有新版、等你同意 | 下載箭頭加琥珀點 | 目標版本與「到設定 › 更新」 |
| 下載中 | 轉圈 | 目標版本 |
| 下載完成、等待重啟 | 重啟箭頭加琥珀點 | 目標版本 |
| 安裝失敗 | 紅色警示 | 指向更新頁查看 |

閒置、檢查中、已是最新、檢查失敗時都沒有這顆鈕。點它會進到應用程式設定的「更新」頁，並捲到「下載與安裝」卡。

背景檢查（啟動時或回到前景時）發現新版，會另外跳一次 toast「有新版本 X.Y.Z」，附「查看」動作進更新頁。同一個目標版本在 app 這次執行期間只跳一次：你關掉 toast、下載後又取消，之後重檢再看到同一版，只會重新出現更新鈕，不會再跳 toast。手動檢查不跳 toast，結果看「最新版本」列與關於頁的狀態籤。

### 更新頁

更新頁由上而下是：

- 頁標題右側的「檢查更新」鈕。
- 「版本」卡：「目前版本」與「最新版本」兩列。「最新版本」列以等寬字寫版號，旁邊帶狀態籤：
  - 有新版待同意、下載中、等待重啟：目標版本加「有新版本」。
  - 已是最新：目前版本加「已是最新」。
  - 檢查中：「檢查中」。檢查失敗：「無法檢查」。還沒檢查過：「尚未檢查」。
- 「下載與安裝」卡：只在有新版待同意、下載中、等待重啟、安裝失敗時出現，標題是「Speclink」加目標版本，例如「Speclink 0.5.1」。卡內的控制依狀態：
  - 待同意：「下載」鈕。
  - 下載中：不確定長度的進度列與「取消」。取消等於收回這次同意，回到閒置，卡與圖示列的更新鈕一起消失；之後才到的下載完成會被忽略，不會安裝，也不會出現「安裝並重新啟動」。
  - 等待重啟：「更新已就緒」與「安裝並重新啟動」。
  - 安裝失敗：錯誤訊息與「重試」。
- 「更新日誌」卡：見下方「更新後的更新日誌彈窗」一節。
- 「自動檢查」卡：一個開關「啟動時在背景檢查新版本」，預設開，存在 app 本機。關掉後，啟動檢查與回到前景的重檢都不做；手動按「檢查更新」照常。重新打開後，下次啟動恢復背景檢查。

應用程式設定裡，「檢查更新」、更新日誌與下載安裝的控制只放在更新頁，別頁不重複。

目前版本與程式內附更新日誌即使 updater 尚未就緒，或 Proxy／TLS 檢查失敗，也仍可查看。未就緒時會說明更新服務狀態並停用更新動作；檢查失敗時頁面保留最後狀態，提供重試與前往「網路與診斷」的入口。背景檢查失敗不會被顯示成「已是最新」。

一次完整的更新長這樣：

1. 啟動時發現新版，圖示列出現下載箭頭加琥珀點的更新鈕，並跳一次 toast。
2. 點更新鈕進更新頁，「最新版本」列是目標版本加「有新版本」。
3. 在「下載與安裝」卡按「下載」。下載期間卡上有進度列與「取消」，更新鈕變成轉圈。
4. 下載完成，卡上顯示「更新已就緒」，更新鈕變成重啟箭頭。
5. 按「安裝並重新啟動」。重啟後跑的就是新版。

### 回到前景時重檢

app 開著不關時，你把主視窗從背景切回前景，app 會補檢一次，條件是距上次檢查已滿 1 小時。啟動檢查、手動檢查與前景重檢都算「上次檢查」。重檢在背景進行，呈現規則與啟動時相同：有新版就出現更新鈕並跳 toast；已是最新或檢查失敗都不顯示任何提示。

下面這些情況切回前景不會重檢：

- 距上次檢查未滿 1 小時。剛好滿 1 小時才重檢。剛按過「檢查更新」也會重算時間。
- 正在檢查、正在下載，或已下載完成等待重啟。
- 已經發現新版、還在等你同意。提示留到你處置，不會被重檢清掉。
- 安裝失敗的錯誤還在。錯誤留到你重試。
- 你在更新頁關掉了「啟動時在背景檢查新版本」。

| 上次檢查 | 切回前景時刻 | 是否重檢 |
| --- | --- | --- |
| 09:00 | 09:20 | 否 |
| 09:00 | 10:00 | 是 |
| 09:00 啟動、09:40 手動檢查 | 10:20 | 否 |
| 從未檢查 | 任意 | 是 |
| 09:00，09:30 起下載中 | 10:30 | 否 |
| 09:00 檢查到新版、等你同意 | 10:30 | 否 |
| 09:00 安裝失敗、錯誤還在 | 10:30 | 否 |
| 09:00 下載完成、等待重啟 | 10:30 | 否 |

macOS 上開關系統匣面板不會改變主視窗的焦點，所以不觸發重檢。面板裡的「詳情／設定／登入」動作把主視窗叫到前景時，才依上面的規則判定。節流用的時間只記在記憶體裡，app 重開就歸零。macOS、Windows、Linux 三個平台的行為一致。

## 更新後的更新日誌彈窗

app 隨版帶一份更新日誌。更新到新版後第一次啟動，app 會彈出標題為「X.Y.Z 更新內容」的對話框，列出比你上次看過的版本新的全部條目。每筆以「版號（日期）」為小標，底下依「新功能／修正／改善」分組列點。按主鈕「知道了」關閉，app 記下這個版號為已看過；下次啟動不再彈。

| 情況 | 結果 |
| --- | --- |
| 從 0.2.0 更新到 0.3.0 | 彈出「0.3.0 更新內容」，只有 0.3.0 的條目 |
| 從 0.2.0 直接跳到 0.3.1 | 彈出「0.3.1 更新內容」，依序列 0.3.1 與 0.3.0，不含 0.2.0 |
| 上次看過的版號不在日誌裡 | 只列最新一筆 |
| 全新安裝、第一次啟動 | 不彈，直接記下目前版號；之後更新才會彈 |
| 已看過目前版號 | 不彈 |
| app 版號與日誌最新版號不同 | 不彈 |

更新頁的「更新日誌」卡：最新版本是第一列，預設展開它的分組列點；較舊的版本每版一列（版號、日期、第一條摘要），附「檢視」；最底下一列是「全部更新日誌」。兩種入口都打開同一個對話框的瀏覽模式：標題是「更新日誌」、列出全部條目、主鈕是「關閉」。按「全部更新日誌」從頂端開始看；按某一版的「檢視」，開啟後那一版的小標會在捲動區最上面。

條目跟著介面語言：介面語言是英文時，「X.Y.Z 更新內容」彈窗、瀏覽模式與更新頁的「更新日誌」卡（含每版一列的第一條摘要）都顯示英文條目，分組標題是 New features、Fixes、Improvements；介面語言是繁中時顯示繁中條目，分組標題是新功能、修正、改善。切換介面語言後，已開著的對話框與更新頁立即換成新語言。介面語言不影響彈出判定與已看過記錄：看過 0.9.0 的更新內容後把介面改成英文再重新啟動，不會再彈出 0.9.0。

應用程式設定裡，更新日誌只有更新頁這個入口，一般頁與關於頁都沒有。macOS 原生選單的「說明 › 更新日誌」也會打開瀏覽模式。瀏覽模式不改變已看過記錄，不影響下次啟動的判定。已看過記錄只存在 app 本機，不進任何專案檔案；記錄壞掉時視同沒有記錄。

## 安裝 CLI 指令到 PATH

app 內建一份 CLI。CLI 的狀態顯示在應用程式設定的「CLI」頁：目前狀態（未安裝、已安裝含版本、版本不符）、佈署位置（等寬路徑）、PATH 提示與平台說明。一般頁不重複顯示 CLI 狀態。已安裝且版本一致時不會重複佈署。安裝後在終端執行 `speclink --version`，版本會與 app 一致。

佈署方式依平台不同：

| 平台 | CLI 落在哪 | 何時自動處理 |
| --- | --- | --- |
| macOS | `~/.local/bin` 下指向 app 內 CLI 的 symlink | 每次啟動偵測到未安裝或版本不符就自動建立或重建 |
| Windows | 安裝器把安裝目錄加進使用者 PATH | app 內只顯示狀態 |
| Linux AppImage | 複製到 `~/.local/bin` | 啟動偵測到版本不符就自動重新複製 |
| Linux 非 AppImage（開發建置、手動解開的 app） | 只以 `~/.local/bin` 的 CLI 顯示狀態 | 不提供佈署動作，啟動不寫任何檔案 |

PATH 的處理：

- macOS：`~/.local/bin` 不在 PATH 時，app 自動在 `~/.zprofile` 追加一行 PATH 匯出，帶識別註解。只在缺席時寫一次，重複啟動不會重複追加。
- Linux：佈署目錄不在 PATH 時，CLI 頁提示你要把哪個目錄加進 PATH，以及加入方式。

佈署失敗不會擋 app 啟動。

> [!WARNING]
> macOS 上 app 每次啟動都會檢查 `~/.local/bin` 的 speclink。版本不符就重建成指向內建 CLI 的 symlink。你自己裝在同一位置的 CLI 會被取代。保留自有 CLI 的做法見 [安裝 CLI 與桌面 app](install.md)。

## 技能檔過期提示

每個專案的技能檔（各 AI 工具 skills 目錄下 speclink- 開頭的技能）帶一個產物層版號，與引擎同源。app 升版後，專案裡的技能檔可能就舊了。

### 什麼時候探測

本地專案成為作用中專案時，app 探測一次。更新動作完成後，以及專案檔案有外部變動時，再探測一次。不是作用中的背景專案不會主動探測。remote 專案不探測、不提示。探測只讀不寫。

探測比對 `.speclink.yaml` 列出的每個工具：內建的 Claude、Codex 與 Copilot，以及通過驗證的自訂描述子（描述子的技能檔路徑以它自己的 skills 目錄起頭）。沒通過驗證的描述子不參與探測，也不會讓結果變成無法判定；它的錯誤由更新動作報出。結果是五種之一：

| 結果 | 意思 |
| --- | --- |
| 缺失 | 某個工具的 skills 目錄下一個 speclink- 技能都沒有。可能從沒裝過，或整組被移除，例如 clone 後技能檔沒進版控 |
| 過期 | 某個工具的技能版號舊於引擎現版 |
| 較新 | 某個工具的技能版號新於引擎現版，也就是專案檔案領先 app |
| 現版 | 全部一致 |
| 無法判定 | `.speclink.yaml` 解析失敗，或技能檔存在但讀不了 |

有多個工具時以「較新 > 缺失 > 過期 > 現版」取最嚴重的一個回報。現版與無法判定都不提示。無法判定不會被當成現版，也不會記入略過。

> [!NOTE]
> 桌面 app 的過期提示規格，情境範例仍以「CLAUDE.md 不存在就提示安裝」「指令檔的 SPECLINK 標記被移除不提示」舉例；`workspace-tools` 的探測本身則以 skills 目錄下的技能檔判定，不看 CLAUDE.md。本頁的判定照探測規格寫。詳見 [本手冊的來源](about.md)。

### 提示卡

探測結果是過期、缺失或較新，而且你沒對這個版號按過「保留現狀」時，專案欄底部、「專案設定」項上方會出現一張琥珀淡底的提示卡：琥珀圖示、一句標題、一句說明、右端一個 ›。

| 探測結果 | 提示卡標題 | 說明裡寫什麼 |
| --- | --- | --- |
| 過期 | 技能檔是舊版 | 將被改寫的檔案數 |
| 缺失 | 還沒安裝技能檔 | 將被新建的檔案數 |
| 較新 | 技能檔比 Speclink 新 | 引導你更新 app |

提示卡在這個專案的每一頁（變更、已封存、規格、手冊、專案設定）都在同一個位置。它不在主區裡、不是彈窗、不擋任何操作；主區各頁的高度不會因為它而改變，主區怎麼捲，提示卡都不動、也不會被捲過的內容蓋住。

其他開著的本地專案，如果上次探測是過期、缺失或較新，圖示列上那個專案的方塊角落會亮琥珀點，滑鼠停留的提示附「技能檔需要處理」。切回那個專案時 app 重新探測，再顯示提示卡。

### 確認框

點提示卡會開確認框：琥珀圖示、標題、說明，以及一張三列的細框卡——這個專案的技能檔版本、你的 Speclink 版本、會改寫的檔案數（較新時第三列是會被換回舊內容的檔案數）。按鈕依探測結果：

| 探測結果 | 按鈕 |
| --- | --- |
| 過期 | 「稍後」「保留現狀」「更新技能檔」 |
| 缺失 | 「稍後」「保留現狀」「安裝技能檔」 |
| 較新 | 「保留現狀」「更新 Speclink」 |

從沒裝過的專案不會被稱為「更新」。各按鈕的效果：

- 「稍後」：只關掉確認框，提示卡留著。
- 「保留現狀」：app 把這個專案與目前的產物層版號記在 app 本機，不寫進專案。同一版號不再問，三種結果共用這份記憶。app 升版、版號變了才會重新提示。
- 「更新技能檔」或「安裝技能檔」：app 用引擎的再生入口把受管檔整套再生，並清掉每個工具 skills 目錄下名稱以 speclink- 開頭、但這次不該產生的資料夾（與 `speclink update` 相同）。成功後確認框與提示卡一起消失。失敗時錯誤顯示在確認框的內容卡下方，按鈕恢復可按，可以重試；專案其他功能照常。
- 「更新 Speclink」（只在較新時出現）：開啟應用程式設定的更新頁。較新代表 app 本體是舊版、專案檔案領先，所以確認框沒有任何改寫專案檔案的按鈕，app 不會用舊版內容改寫領先的專案檔案。

你在終端執行 `speclink update` 把技能檔更新到現版時，app 偵測到檔案變動後重新探測，提示卡自己消失，不用重開專案。

### 只更新、不降級

引擎的再生入口在寫入前先判方向。專案技能檔版號領先引擎現版時，再生一律拒絕：一行英文說明（含專案的版號與引擎的版號）、不寫任何檔案。這條守門對 `speclink update`、`speclink init --force`、設定頁改工具或改政策後的技能同步、桌面的更新動作一體適用。`--force` 不代表同意降級。唯一的明示越過入口是：

```
speclink update --allow-downgrade
```

```
speclink --version
```

輸出一行：套件版號、架構、引擎的產物層版號，例如 `0.1.0 (arm64, engine v1.14.0)`。技能檔開頭的版本欄位就是這個引擎版號。同一次生成的所有技能檔版號相同。這個版號只在內嵌資產內容變動時遞增，不隨 app 或 CLI 發版自動變。桌面 app 的關於頁也顯示同一個引擎版號。

CLI 端 `speclink update` 的其他行為（孤兒技能目錄清理、worktree 技能的條件式生成）見 [建立工作區與指令檔](init-workspace.md)。

## 關於頁

應用程式設定的分類欄在「應用程式」組之後有「關於」組，裡面只有一項「關於 Speclink」，主區麵包屑是「設定 / 關於 Speclink」。macOS 原生選單的「關於 Speclink」直接開這一頁。頁內由上而下：

- **品牌卡**：Speclink 的橫式標誌（深色主題用深色版）。下一行是灰字的版本列「app 版號 · 引擎 引擎版號 · 平台 架構」，旁邊是更新狀態籤與「複製版本資訊」鈕。最後一句產品描述。
  - 更新狀態籤（已是最新、有新版本、檢查中、無法檢查、尚未檢查）與更新頁的「最新版本」列是同一份狀態。點它就進更新頁。
  - 「複製版本資訊」把三行文字寫進剪貼簿，並短暫顯示已複製。版本資訊還沒取得時，版本列顯示「—」，也沒有複製鈕。
- **連結卡**：三列，整列可點、帶外開圖示，都用系統瀏覽器開啟。「原始碼」（說明是等寬字的倉庫網址）、「說明文件」、「回報問題」（開新 issue 頁，並帶入版本三行）。開啟失敗時以 toast 顯示錯誤。
- **授權卡**：兩列。「授權條款」的說明是「MIT License · © 2026 MomoChen」，按「檢視」開對話框顯示隨 app 打包的授權全文。「第三方授權」按「檢視」開對話框，分 npm 與 cargo 兩節，列出桌面 app 與 CLI 用到的開源套件：名稱、版本與授權識別字，依名稱排序。清單還沒產生時顯示「清單尚未產生」，不是錯誤。

複製出來的版本資訊是三行：

1. `Speclink <app 版號>`
2. `Engine <引擎版號>`
3. `Platform <平台> <架構>`

關於頁沒有「檢查更新」與「更新日誌」，兩者只在更新頁。版本資訊由 app 一次取得，引擎版號與 `speclink --version` 顯示的 engine 版號相同。頁內文案跟隨介面語言。

**出處**：`desktop-app`、`workspace-tools`
