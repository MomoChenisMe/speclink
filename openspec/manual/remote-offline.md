# 失聯與恢復

remote 工作區連不上 server 時，桌面 app 不會退回本地模式，也不會把你離線時的操作存起來之後補送。這一頁說明你會看到什麼、哪些事做不了、以及連線回來後會自動發生什麼。

## 三種連線狀態

每個 server 連線只會處於三種狀態之一，由桌面 app 的執行期單一判定：

| 狀態 | 進入條件 | 你看到的 |
| --- | --- | --- |
| online | 任一請求成功，或背景同步收斂成功 | 一切正常 |
| offline | 請求連續失敗達到門檻，且背景同步也失敗 | 分頁層級的離線橫幅、雲朵斷線圖示 |
| needs-reauth | server 明確拒絕已撤銷、失效或遭重放的憑證 | 分頁層級的需要重新登入橫幅 |

needs-reauth 優先於 offline 呈現。本地分頁不受任何 remote 連線狀態影響。同一台機器上第二個 server 也不受影響。

## 離線時：能看、不能寫

offline 或 needs-reauth 期間：

- 已載入的看板與文件內容保留可讀，並標示 stale。查詢失敗不會清空既有內容。
- 全部寫入操作在畫面上停用：任務勾選、動詞、產物寫回、政策儲存、封存。
- 就算繞過畫面直接呼叫寫入命令，也會立即被拒。
- 讀取仍會嘗試。讀取成功就促成回到 online。

> [!NOTE]
> 沒有離線佇列。離線期間的寫入不會排隊、不會暫存、不會延後重放。server 恢復後，server 上不存在離線期間的任何寫入。

### 還沒建立 session 時

app 重啟、或恢復連線後第一次交握還沒成功時，這個分頁還沒有 session。此時桌面 app 呈現「還原中」或錯誤的復原頁，不會顯示上一個工作區的變更與討論，也不會把空清單標成 stale。這條路徑在重試或登入恢復成功後才建立 session。

## server 恢復後：全自動收斂

server 重新可達後，你不用做任何事：

1. 背景同步自動重連。
2. 連線回到 online，桌面 app 發出全量失效通知。
3. 資料全部重查後，stale 標示消失。
4. 離線期間別人建立的變更會出現在看板上。

同一個連線開了多個 remote 分頁時，恢復過程只會消耗一次已儲存的刷新憑證。其他分頁共用這次換發的結果，各自重試原本的讀取。這樣的本機併發不會被 server 當成憑證重放，不會撤銷憑證，也不會進入 needs-reauth。

## 需要重新登入時：原地復活

server 撤銷了這台裝置的憑證後，連線進入 needs-reauth。重新登入的入口有三處：

- 已有 session 的 remote 分頁上的橫幅；
- 還沒有 session 的 remote 復原頁；
- macOS 的面板與原生系統匣選單。

你明確選擇重新登入時，主視窗顯示並取得焦點，切到應用程式設定的伺服器頁，並聚焦這個連線。登入流程重用既有的裝置登入或存取金鑰路徑。只是顯示 needs-reauth 狀態、或執行不需要登入畫面的重試，不會自動喚起主視窗。

登入成功後，這個連線的全部 remote 分頁自動重新交握、全量重查、重啟背景同步。既有分頁原地恢復，沒有 session 的分頁在原位建立 session。全程分頁不會消失，不會退回本地模式。系統匣同步回到就緒狀態。系統匣的細節見 [系統匣選單](tray.md)。

## remote 上的破壞性操作

- **封存**：確認對話與本地相同，描述會指出將寫入 server 上的哪個 Project／Repo。確認後寫入 server，取消則無任何變更。offline 期間封存隨寫入遮罩一起停用。
- **刪除變更**：守門與本地的 discard 對齊。未開工即刪；帶開工痕跡的變更由 server 拒絕，並沿既有的刪除失敗路徑回報。

## 一般重啟與完全重置

- **一般重啟**：停止再啟動 server，資料與 remote 分頁都保留，server 不會重印 setup token。
- **完全重置**：以 npx 啟動的 server，刪除它的資料目錄後重新啟動，會重新印出全新的 setup token。在 checkout 內開發的人另有開發者用的重置指令。

重置後的開箱流程見 [開箱：第一位 Admin 與第一組 Project／Repo](server-setup.md)。
